이 문서는 **`C:\Users\gram\Downloads\NewPipe` 저장소에서 수행할 작업 목록**입니다.
그 저장소는 로컬 Windows에만 있고 GitHub에 없어, 이 키트를 만든 세션에서는 코드를 볼 수
없었습니다. 따라서 아래는 **확인 항목이지 확정된 변경이 아닙니다.**
"코드를 읽고 → 필요하면 고친다"의 순서를 지켜 주세요.


읽기 전용이고 표준 라이브러리만 씁니다(설치할 것 없음). 하는 일:

| 확인 | 스크립트가 하는 일 |
|---|---|
| 확인 1 | 파일명을 다루는 함수의 **소스를 그대로 인쇄** + `product_id`/`name` 참조 수. 판정은 사람이 |

## 순서가 중요합니다

```
1. 실기기에서 첫 수집  →  실물 텍스트 확보
2. 그 텍스트를 픽스처로 커밋
3. 픽스처를 보고 파서 마커 교정
```

**2번 없이 3번을 먼저 하지 마세요.** 인수인계 문서 §10의 버그 #3(`parse_sellers`가 상품명을
판매자로 지어냄)이 정확히 "실물을 안 보고 규칙을 넣어서" 생긴 일입니다.
그리고 §11이 지적한 "역추론 픽스처" 문제를 모바일에서 반복하지 않으려면,
첫 실물 텍스트를 **받은 그대로** 커밋해야 합니다.

## 확인 1 — `from_text.py`의 파일명 규칙

**볼 것**: `coupang_crawler/from_text.py`가 파일명에서 상품을 어떻게 찾는가.

키트는 파일을 `<productId>.txt` / `<productId>_sellers.txt` / `<productId>_search.txt`로 저장합니다.
인수인계 문서 §6의 원칙("키는 상품명이 아니라 `product_id`. 쿠팡이 제목을 바꿔도 시계열이 안
끊긴다")과 맞춘 이름입니다.

| from_text의 현재 규칙 | 할 일 |
|---|---|
| 이미 `product_id`로 찾음 | **아무것도 안 함.** 그대로 동작합니다 |
| 상품명(`name`) 기준 | 둘 중 하나 — ⓐ 단축어에 이름 매핑 사전 추가 (`shortcut/BUILD.md` ⑥, **Python 무수정**) ⓑ `products.xlsx`의 `url`을 `config.py`의 URL 정규화로 파싱해 `product_id → 상품` 역인덱스를 만들고 stem이 숫자면 그쪽으로 조회 |

ⓑ를 택한다면 URL 파싱은 **`config.py`에 이미 있는 정규화 함수를 재사용**하세요.
새로 정규식을 짜면 규칙이 두 벌이 됩니다.

## 확인 2 — `_sellers` 접미사를 알아보는가

기존 수동 경로에는 `<상품키>_search.txt`가 있습니다(§11). `_sellers`도 같은 방식으로
`source`를 정하는지 확인하고, 없으면 `_search`와 같은 자리에 추가하세요.

- `option_list` ← 접미사 없음
- `other_sellers` ← `_sellers`
- `search_results` ← `_search`

§7의 중복 판정 키가 `source`마다 다르므로(특히 `other_sellers`의 식별자는 **판매자**),
`source`가 틀리면 버그 #2와 같은 데이터 유실이 납니다.

## 확인 3 — 차단 마커 목록 동기화

`mobile-collect/extract.js`의 `BLOCK_MARKERS_HARD` / `BLOCK_MARKERS_SOFT`는
`parse.py`가 가진 차단 마커의 **사본**입니다. 폰에서 미리 멈추기 위한 것이고,
**최종 판단은 언제나 `parse.py`가 합니다.**

- `parse.py`의 실제 목록과 비교해 다르면 `extract.js` 쪽을 맞추세요.
- 고친 뒤 `mobile-collect/tests/extract.test.mjs`의 고정 테스트와
  `npm run build:snippet`을 함께 갱신해야 합니다.
- 폰 쪽 목록에 없어서 통과한 차단 페이지는 PC에서 다시 걸립니다(이중 방어). 반대는 아닙니다 —
  폰 쪽 목록에 오탐이 있으면 **정상 수집이 조용히 버려집니다.** 그래서 SOFT 마커는 짧은
  페이지(2,000자 미만)에서만 차단으로 봅니다.

## 확인 4 — 모바일 텍스트에 대한 파서 적중 (**실물 확보 후에만**)

모바일(`m.coupang.com`)은 데스크톱과 문구·순서가 다를 수 있습니다. 첫 실물 픽스처를 보고:

- `parse.py`의 `SELLER_SECTION_MARKERS` — 모바일의 판매자 구간 표시 문구를 추가
- 옵션 라벨 인식 — 모바일 옵션 표기가 다르면 후보 추가
- 버그 #1(모달을 열어도 배경 텍스트가 `body`에 남음)은 **모바일에서 더 심할 수 있습니다.**
  구간 표시로 범위를 제한하는 기존 방어가 모바일 텍스트에서도 먹히는지 반드시 확인하세요.
- 구간을 못 찾으면 `[]`를 반환하는 현재 정책(버그 #3 수정)을 유지하세요.
  지어낸 데이터가 CSV를 조용히 오염시키는 것보다 빈 결과가 낫습니다.

### 픽스처 커밋

```
coupang_crawler/tests/fixtures/mobile_product.txt     # 옵션 펼친 상태
coupang_crawler/tests/fixtures/mobile_sellers.txt     # 판매자 목록 연 상태
```

받은 그대로 넣고, 이 픽스처로 pytest를 추가하세요. 개인정보(로그인 상태의 이름·주소 등)가
섞였는지만 확인하고 지웁니다.

## 확인 5 — 첫 수집 후 CSV 검수

`coupang-price/prices.csv`에서 모바일로 들어온 행을 눈으로 봅니다.

- `option`에 판매자명이 들어가 있지 않은가 (버그 #1의 재발)
- `seller`에 상품명이 들어가 있지 않은가 (버그 #3의 재발)
- `price`가 와우 회원가·쿠폰가와 뒤섞이지 않았는가 — **모바일에서 새로 생길 수 있는 위험**입니다.
  모바일 페이지는 정가·회원가·쿠폰적용가를 더 촘촘히 붙여 놓습니다.

## 범위 밖 (이번에 하지 않기로 한 것)

- **LAN 직접 전송**(폰 → `receiver.py`): https 페이지에서 `http://192.168.x.x`는 mixed content로
  차단되고, Chrome 142+는 Local Network Access 권한 프롬프트를 겁니다. `receiver.py`를
  `0.0.0.0`에 바인딩하는 것은 §8의 안전장치("`127.0.0.1`에만 바인딩")를 되돌리는 일이기도 합니다.
  파일 경로로 충분하므로 열지 않습니다.
- **`--diagnose`에 모바일 호스트 대조군 추가**: 이번 요청(폰 수집) 범위 밖입니다.
  다만 §3-5에서 이미 `m.coupang.com/vm/products/{id}` 403이 실측돼 있으니,
  나중에 정책 변화를 감시하고 싶다면 그 자리에 붙이는 게 맞습니다.
- **무인 자동 실행**: 사람이 탭해야 한다는 전제는 모바일에서도 그대로입니다.
  상품이 20개로 늘면 탭 부담이 커지는 것도 데스크톱과 같습니다(§11).
