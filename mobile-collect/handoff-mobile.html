3. 조사·결정 로그

원문과 같은 규칙을 씁니다 — 추정과 실측을 구분합니다.

3-1. 환경 제약 (실측)

$ curl -o /dev/null -w "%{http_code}" https://m.coupang.com/
000
$ curl ... https://m.coupang.com/vm/products/8868816986   → 000
$ curl ... https://www.coupang.com/vp/products/8868816986 → 000

세션 컨테이너는 쿠팡으로 나가는 아웃바운드가 정책상 막혀 있습니다(403이 아니라 연결 자체가 안 됨). 따라서 이 세션에서 차단 상태를 재확인할 방법은 없었습니다. 그 판정은 PC의 --diagnose --reset-profile 몫으로 남습니다.

3-2. 모바일 캡처 수단 조사 (문헌)

수단판단
iOS 단축어 웹페이지에서 JavaScript 실행채택. Safari 공유 시트에서만 입력을 받고, completion()으로 값을 돌려줌 — 사람이 탭했을 때만 도는 구조가 원문의 확장과 동일
Android Firefox + Tampermonkey/Violentmonkey유효하나 미채택 — 사용자 기기가 iPhone. Android로 옮길 때 이 카드가 남아 있음(AMO에 정식 등록되어 설치가 쉬움)
완성된 .shortcut 파일 배포불가 — iOS는 공유 단축어에 서명을 요구하고, 서명은 Apple iCloud 링크로만 생김. 그래서 조립 문서로 대체

3-3. 전송 경로 조사 — 결정적 (문헌)

폰에서 PC의 receiver.py로 직접 POST하는 안을 먼저 검토했고, 기각했습니다.

  • Mixed content — https://m.coupang.com 페이지에서 http://192.168.x.x:8765로 보내는 것은 브라우저가 막습니다. 예외는 localhost뿐인데, 폰에서 PC의 localhost에는 닿을 수 없습니다.
  • Local Network Access — Chrome 142(2025-10-28)부터 공개 사이트가 사설 IP·loopback·.local로 요청하면 권한 프롬프트가 뜨고, 거부하면 조용히 실패합니다.
  • receiver.py를 0.0.0.0에 바인딩하는 것은 원문 §8의 안전장치("127.0.0.1에만 바인딩")를 되돌리는 일이기도 합니다.

그래서 파일 경로를 기본으로 삼았습니다. 폰이 .txt를 iCloud Drive에 저장하면 Windows용 iCloud가 PC로 동기화하고, PC는 이미 검증된 --from-text로 읽습니다. 새 수신 코드도, 새 보안 표면도 없습니다. 원문 §2의 "새 수집 경로를 추가할 때도 텍스트만 넘겨주면 된다"를 그대로 따른 것입니다.

3-4. 실기기 확인 (실측, 2026-08-01)

iPhone Safari로 m.coupang.com/vm/products/8868816986 열기 → 정상 렌더. 브레드크럼·상품 이미지·만족도까지 실제 콘텐츠가 나왔습니다.

같이 관측된 것: 로그아웃 상태였습니다. 상단에 로그인 / 회원가입이 떠 있고 장바구니는 0. 수집에 로그인 세션이 필요 없다는 뜻이므로, 원문 §5가 경고한 계정 제재 위험을 애초에 만들지 않습니다. → 로그인한 채로 수집하지 마세요.

확인되지 않은 것: 이 화면은 페이지 상단입니다. 정작 필요한 옵션·가격·다른 판매자 구간이 아래에 어떤 문구로 있는지는 여전히 모릅니다.

4. 결론과 근거

원문 §4의 결론을 그대로 계승합니다 — Akamai 센서는 정상 실행되어 텔레메트리를 POST(201)했는데도 _abck는 끝까지 미검증이었습니다. 원인은 세션이 자동화로 판정된 것 자체이며, 시간·퍼널·워밍업 축의 카드는 전부 소진되었습니다.

따라서 이번에도 판정을 뚫지 않습니다. 사람이 자기 폰에서 직접 연 페이지를, 사람이 공유 시트에서 탭했을 때만 읽습니다. 자동화 세션이 아니므로 애초에 판정 대상이 아닙니다. 3-4의 실측이 이를 뒷받침합니다 — Playwright로는 403이던 바로 그 URL이 사람 손에서는 정상 렌더됩니다.

5. 채택하지 않기로 한 것 원문 §5 계승

원문의 배제 목록은 그대로 유효합니다. 다시 제안하거나 구현하지 마세요. 지문 위조 · 스텔스 브라우저 · Akamai 센서 페이로드 조작 · _abck 조작 · 인간 입력(탭·스크롤) 시뮬레이션 · TLS/HTTP2 지문 위조 · 프록시 로테이션 · CAPTCHA 자동 해결 · 사용자 본인 프로필 사용.

이번에 추가로 배제한 것:

  • LAN 직접 전송 (폰 → receiver.py) — 3-3의 이유. 확인할 수 없는 링크를 기본 경로로 삼지 않습니다
  • 자동 탭·자동 스크롤 — 옵션과 판매자 목록은 사람이 펼친 뒤 담습니다
  • 로그인 상태 수집 — 3-4에서 로그아웃으로도 충분함이 확인됐습니다

읽기 전용입니다. 구매·장바구니·로그인은 건드리지 않습니다.

설계 원칙 (유지할 것)

  • 판단은 extract.js에, DOM 접촉은 래퍼에. 원문 §6의 "판단은 parse.py에, 브라우저 조작은 collect.py에"를 그대로 옮긴 것입니다. 래퍼는 3줄이고 생성기가 붙입니다.
  • 스니펫은 손으로 관리하지 않습니다. 두 벌이 어긋나면 테스트가 실패합니다.
  • 차단이면 파일을 만들지 않습니다. 원문 §8의 종료코드 2 정책(차단 → 즉시 중단·재시도 금지)을 수집 시작점으로 당긴 것입니다. 차단 페이지 텍스트가 CSV로 흘러드는 것을 막습니다.
  • 차단 마커는 parse.py 목록의 사본이며, 최종 판단은 언제나 parse.py가 합니다. 의도적 중복이고, 고정 테스트로 드리프트를 드러냅니다.

단축어는 extract.js가 낸 JSON을 사전으로 받아 status로 분기하고 text를 저장합니다.

10. 지금 하던 일 (중단 지점) 여기서 이어서

iOS 단축어를 사용자와 함께 조립하던 중이었습니다. BUILD.md의 9개 액션 중 ①까지만 안내했고, 사용자의 실행 결과를 기다리는 상태입니다.

조립 순서를 BUILD.md의 선형 순서에서 한 군데 바꿔 진행 중입니다. 9개를 다 만든 뒤 확인하면 어디가 틀렸는지 알기 어렵고, ①만 만들어 결과를 눈으로 보면 "모바일 페이지가 담기긴 하는가"까지 같이 판명되기 때문입니다.

사용자에게 안내한 내용:

  1. 새 단축어 → 공유 시트에 표시 켜기 → 입력 유형 Safari 웹페이지만 남기기 → 이름 쿠팡 수집
  2. 액션 ① 웹페이지에서 JavaScript 실행 추가 → raw 링크에서 스니펫 전체 복사·붙여넣기
    (액션이 안 보이면 설정 > 단축어 > 고급 확인)
  3. 그 아래 결과 보기(Quick Look) 임시 추가
  4. Safari에서 상품 페이지 열기 → 아래로 내려 옵션 펼치기 → 공유 → 쿠팡 수집
  5. JSON 화면을 스크린샷으로 보내 달라고 요청함

그 화면에서 볼 것: status가 ok인지 · chars가 수천 자인지 · productId가 8868816986인지 · text 안에 옵션·원·판매자 문자열이 있는지.

참고: 단축어 앱 안에서 ▶︎로 돌리면 실패하는 것이 정상입니다. 이 액션은 Safari 공유 시트에서만 입력을 받습니다.

12. 알려진 불확실성

  • 파서가 모바일 텍스트에 맞는지 전혀 검증되지 않았습니다. 원문 §11이 데스크톱에 대해 남긴 불확실성이 모바일에서 그대로 반복됩니다. 첫 실물 캡처에서 어긋날 가능성이 높습니다.
  • from_text.py의 파일명 규칙을 확인하지 못했습니다. 코드를 볼 수 없었습니다. 상품명 기준이라면 Python을 안 고치고 단축어에 productId → 상품키 매핑 사전을 넣는 방법이 BUILD.md ⑥에 있습니다.
  • 옵션·판매자 구간이 모바일 페이지에 어떤 문구로 있는지 모릅니다. 3-4의 스크린샷은 페이지 상단뿐이었습니다.
  • 모달을 열어도 배경 텍스트가 body에 남는 문제(원문 버그 #1)는 모바일에서 더 심할 수 있습니다. 구간 표시로 범위를 제한하는 기존 방어가 모바일에서도 먹히는지 확인이 필요합니다.
  • 가격 혼동 위험 — 모바일에서 새로 생길 수 있습니다. 모바일 페이지는 정가·와우 회원가·쿠폰 적용가를 데스크톱보다 촘촘히 붙여 놓습니다. 첫 CSV에서 price가 뒤섞이지 않았는지 반드시 눈으로 보세요.
  • m.coupang.com이 www로 리다이렉트되는 경우의 최종 URL 형태를 실측하지 못했습니다. parseProductUrl은 /vm/·/vp/ 양쪽을 처리하지만 확인은 1번 단계에서 납니다.
  • 단축어 액션의 한국어 이름은 iOS 버전에 따라 다를 수 있습니다. BUILD.md에 영문명을 병기해 두었습니다.
