1. 지금 어디서 멈췄나 여기서 이어서

사용자가 아이폰에서 단축어를 조립하는 중입니다. 2단계(액션 ②③④)를 진행 중이고, 확인 스크린샷을 받지 못한 상태에서 세션이 끊겼습니다.

단계내용상태
1단계 단축어 껍데기 + 액션 ① + 임시 액션으로 B-1 확인 완료 — 결과는 4절
2단계 ①의 코드를 run-javascript-body.js로 되돌리고 ②③④(사전·status·분기) 추가 진행 중 · 미확인
3단계⑤⑥⑦ — 메뉴·상품키·텍스트미착수
4단계⑧⑨ — 파일 저장·알림 + 실수집 검증미착수

사용자에게 마지막으로 안내한 것 (2단계):

  1. 임시 액션(클립보드에 복사·훑어보기) 삭제
  2. ①의 코드를 run-javascript-body.js로 교체 (diagnose-body.js 아님)
  3. 사전 가져오기 → 사전 값 가져오기(키 status) → 만약(ok와 같음)
  4. "그렇지 않으면" 쪽: 사전 값 가져오기(키 reason) → 알림 표시 → 단축어 중단

요청한 회신: 액션 목록 전체 스크린샷(⑤~⑨를 어느 칸에 넣을지 판단하려면 필요), 그리고 iOS 버전(설정 > 일반 > 정보).

iOS 버전을 아직 받지 못했습니다. 4단계 파일 저장의 파일명 지정 방식이 버전마다 갈립니다(shortcut/BUILD.md ⑧의 분기표). 먼저 물어보세요.

4. 이번에 확정된 사실 (실측) B-1 완료

진단 스니펫으로 받은 이 프로젝트 최초의 실물 데이터입니다. 앞 문서에서 추정으로 남아 있던 항목들이 여기서 판명됐습니다.

status = ok · chars = 30,602 · productId = 8868816986 · host = www.coupang.com
"옵션" 2회 · "원" 361회 · "판매자" 48회
밝혀진 것내용과 의미
m → www 리다이렉트 확정. m.coupang.com/vm/products/{id}로 열어도 www.coupang.com이 됩니다. parseProductUrl이 /vp/ 형태도 처리하므로 키트 수정 불필요. 다만 모바일 전용 문구를 기대하면 안 됩니다 — 폰에서 보는 www 페이지입니다
판매자 48회는 대부분 판매자배송 실측 발췌: 모레(목) 8/6 도착 예정 (판매자배송). 판매자를 구간 표시로 쓰면 48개의 오탐에 걸립니다. 버그 #3이 재발하는 정확한 조건입니다. SELLER_SECTION_MARKERS는 다른 판매자처럼 더 긴 문구여야 하고 판매자배송은 명시적으로 제외해야 합니다
옵션 구간 표시 후보는 옵션 선택. 그 위에 모든 옵션 보기 링크가 따로 있습니다 — 사람이 누르지 않으면 옵션이 일부만 담깁니다. 수집 절차에 반영할 것
가격 밀도 위험 실재 첫 300자 안에만: 6% · 27,990원 · (10g당 62원) · 29,990원 · 2,000원 · 할인 · 1개 9,190원 … 5개 27,990원 · 2개 사면 4,390원 절약. NOTES.md 확인 5의 경고가 추정이 아니라 실제였습니다
옵션 라벨-가격 짝짓기 선형 텍스트에서 자명하지 않습니다: 180g × 3개 → 8,920원 → (10g당 165원) → · 무료배송 → 배송예정일. 픽스처로 반드시 검증할 것
상품명이 문서와 다름 문서 그릭마일드 무가당 900g vs 실제 빙그레 요플레 그릭요거트 무가당 플레인, 5개, 900g. product_id는 동일. 원문 §6의 "키는 상품명이 아니라 product_id" 원칙이 실제로 값을 했습니다
로그아웃 수집 확인 첫 줄이 고객센터회원가입로그인 — 로그인 없이 정상 수집됩니다. 로그인한 채로 수집하지 마세요

전문(30,602자)은 아직 받지 못했습니다. 위는 전부 발췌입니다. 따라서 이것만 근거로 parse.py를 고치지 마세요. 픽스처는 ⑧(파일 저장)이 동작하면 나옵니다.

5. 안내 실패에서 얻은 교훈 반복하지 말 것

이번 세션에서 iOS UI 안내를 세 번 틀렸습니다. 전부 검색으로 확인할 수 있었는데 기억에 의존해 단언한 결과입니다. 같은 실수를 반복하지 마세요 — 액션 이름과 화면 위치는 찾아본 뒤에만 말하세요.

틀린 안내실제
"우상단 ⓘ를 탭" ⓘ는 편집 화면 하단 툴바에 있습니다. 동작 검색 시트가 하단을 덮고 있어 안 보였던 것입니다 — 시트를 아래로 쓸어내려 접으면 드러납니다
"∨ 메뉴에서 세부사항" ∨ 메뉴에는 이름 변경 · 아이콘 선택 · 복제 · 이동 · 홈 화면에 추가뿐입니다. 세부사항은 없습니다. 공유 시트 설정은 하단 ⓘ 안에 있습니다
"결과 보기(Quick Look) 추가" 한글 액션 이름은 훑어보기입니다. 다만 확인용으로는 클립보드에 복사가 낫습니다 — 결과를 텍스트 그대로 받을 수 있어 스크린샷보다 정확합니다

확인된 UI 경로:

  • 이름 변경 — 상단 단축어 이름 옆 ∨ → 이름 변경
  • 공유 시트에 표시 — 하단 시트를 접고 → 하단 툴바 ⓘ → 공유 시트에 표시 → 받는 항목 유형
  • 스크립트 액션이 안 보일 때 — 설정 > 단축어 > 고급

9. 남은 불확실성

  • 파서가 실제 텍스트에 맞는지 여전히 검증되지 않았습니다. 픽스처가 전부 합성이고, 실물은 발췌만 있습니다.
  • 옵션 라벨-가격 짝짓기가 선형 텍스트에서 자명하지 않습니다(4절).
  • 판매자 구간이 어떤 문구로 시작하는지 모릅니다. 사용자가 "다른 판매자" 목록을 열지 않은 상태의 캡처였습니다. 판매자배송 오탐만 확인됐습니다.
  • from_text.py의 파일명 규칙은 여전히 모릅니다. 다만 이제 추측하지 않고 측정합니다(check_pc_side.py). "모름"에서 "측정 대기"로 바뀐 항목입니다.
  • check_pc_side.py의 확인 1은 판정하지 않습니다. 근거만 인쇄합니다. 파일명 처리가 함수 형태가 아니면(예: 정규식 한 줄) 못 찾을 수 있습니다.
  • iOS 버전 미확인 — ⑧의 저장 분기를 고르려면 필요합니다.
  • 모달 배경 텍스트 문제(버그 #1)가 여기서 더 심할 수 있습니다. chars가 30,602자로 큽니다.
  • 루트 CLAUDE.md가 실제와 어긋나 있습니다 — Python/pytest/black 기준으로 쓰여 있으나 루트는 TypeScript/Vitest/React입니다. mobile-collect/는 의존성 0의 독립 키트라 영향받지 않지만, 이 파일을 읽는 세션이 잘못된 규칙을 따를 소지가 있습니다. 이번 범위 밖이라 손대지 않았습니다.

10. /goal 조건문

전문은 tasks/goal-prompts.md에 있습니다. 설계 원칙만 옮깁니다.

평가자는 도구를 쓰지 않습니다. 명령을 돌리지도 파일을 읽지도 않고, 대화에 이미 드러난 것만 보고 판정합니다. 그래서 조건은 명령어 출력으로 증명 가능해야 합니다.

그리고 이 프로젝트의 남은 일은 대부분 사람 손이 있어야 끝납니다. 조건에 사람 대기 탈출구와 턴 상한을 넣지 않으면 조건이 영원히 충족되지 않아 토큰만 태웁니다.
