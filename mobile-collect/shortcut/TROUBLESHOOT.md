# 단축어가 안 될 때 — 증상별 대응

`BUILD.md`가 "어떻게 만드나"라면 이 문서는 "왜 안 되나"입니다.
**증상 → 원인 → 조치** 순으로 찾으세요.

---

## 조립할 때

| 증상 | 원인 | 조치 |
|---|---|---|
| `웹페이지에서 JavaScript 실행` 액션이 검색해도 안 나옴 | 스크립트 액션이 꺼져 있음 | **설정 > 단축어 > 고급**에서 스크립트 관련 항목을 켬 |
| 액션 이름이 문서와 다름 | iOS 버전·언어 차이 | 괄호 안 영문명(`Run JavaScript on Webpage` 등)으로 검색. 그래도 없으면 *기능*이 같은 액션을 찾음 |
| `메뉴에서 선택`이 없음 | 버전 차이 | `목록에서 선택 (Choose from List)` + `텍스트` 액션으로 대체 (BUILD.md ⑤) |
| 붙여넣은 코드가 짧아 보임 | 일부만 복사됨 | 첫 줄이 `// ⚠ 자동 생성 파일 — 직접 고치지 말 것.` 인지 확인. 아니면 전체 다시 복사 |
| 공유 시트에 `쿠팡 수집`이 안 뜸 | **공유 시트에 표시**가 꺼져 있거나 입력 유형이 안 맞음 | 단축어 세부사항(ⓘ) → 공유 시트에 표시 켬 → 입력 유형 **Safari 웹페이지** 남김 |

## 실행할 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 단축어 앱에서 ▶︎ 눌렀더니 ①에서 실패 | **정상입니다.** 이 액션은 공유 시트에서만 입력을 받음 | Safari에서 공유 → `쿠팡 수집`으로 실행 |
| `수집 중단 — empty / 본문 NNN자` | 렌더가 덜 끝남 (본문 500자 미만) | 잠깐 기다렸다 **다시 탭해도 됩니다.** 페이지를 끝까지 스크롤해 두면 잘 잡힘 |
| `수집 중단 — blocked / Access Denied` 등 | 차단 페이지를 담으려 함 | **재시도하지 마세요.** 파일도 안 만들어집니다. `reason`의 마커를 기록해 두고 그날 수집은 중단 |
| `수집 중단 — error / ...` | 스크립트 예외 | `reason` 문구를 그대로 알려 주세요. 스니펫이 일부만 붙여넣어졌을 가능성이 큼 |
| 권한 요청 팝업이 뜸 | 첫 실행 | "이 단축어가 웹페이지 내용에 접근하려고 합니다" → **허용** |
| `productId`가 `null` | `m.coupang.com`이 `www`로 리다이렉트됐거나 상품 URL이 아님 | 주소창의 **최종 URL**을 알려 주세요. `/vm/products/{id}`·`/vp/products/{id}` 양쪽은 처리되지만, 그 외 형태는 아직 실측되지 않았습니다 |

## 파일이 이상할 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 파일 이름이 그냥 `.txt` (앞이 비어 있음) | ⑥이 `productId`를 못 꺼냄 — `사전 값 가져오기`의 입력이 **앞 동작의 결과**로 잡혀 있음 | ⑥의 입력을 변수 **`자료`** 로 지정 (BUILD.md ②') |
| 파일은 생겼는데 **0바이트이거나 몇 글자뿐** | ⑦이 `text`를 못 꺼냈거나, ⑧이 `본문` 변수 대신 "이전 동작의 결과"를 저장 중 | ⑦의 입력을 `자료`로, ⑧의 파일을 변수 **`본문`** 으로 지정 |
| 세 갈래 중 **한 갈래에서만** 파일이 생김 | ⑧ 파일 저장이 메뉴 갈래 **안**에 있음 | `메뉴 종료` **아래**로 옮김 (BUILD.md 전체 모양 그림) |
| 접미사가 안 붙음 (`_sellers`를 골랐는데 없음) | 그 갈래에 `변수 설정 접미사`가 없음 | 세 갈래 **전부**에 한 줄씩 넣음 |
| **차단됐는데 파일이 생김** | ⑤~⑨가 `만약 종료` 아래에 있음 — 가장 위험한 배치 | 즉시 `만약`과 `그렇지 않으면` **사이**로 옮김. 차단 텍스트가 CSV로 흘러듭니다 |
| 파일명이 `쿠팡 수집.txt`·`텍스트.txt` | ⑧에서 파일명 지정이 안 먹음 | BUILD.md ⑧의 **iOS 버전 분기표** 두 번째 줄(`이름 변경` 선행)로 전환 |
| 파일이 PC에 안 나타남 | Windows용 iCloud 미설치·동기화 지연 | iCloud 상태 확인. 안 쓴다면 README "대안 전송" 표(카카오톡·구글 드라이브·클립보드)로 전환 — **⑧만 바꾸면 됩니다** |
| 같은 날 다시 담았더니 파일이 두 개 | 덮어쓰기가 꺼져 있음 | ⑧에서 **파일이 이미 있으면 덮어쓰기: 켬** |
| 파일은 생겼는데 PC에서 수집이 안 됨 | 파일명 규칙이 PC와 안 맞음 | 쿠팡 저장소에서 `python mobile-collect/pc-side/check_pc_side.py` 실행. 확인 1·2가 답을 줍니다 |

## 데이터가 이상할 때

먼저 **로그인 상태였는지** 확인하세요. 상단에 `로그인 / 회원가입`이 보이는 로그아웃 상태가
맞습니다. 로그인 상태로 담으면 개인정보가 텍스트에 섞이고, 계정 제재 위험도 생깁니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| CSV의 `option`에 판매자명이 들어감 | 모달을 열어도 배경 텍스트가 `body`에 남음 (인수인계 §10 버그 #1) | `parse.py`의 판매자 구간 표시로 범위를 제한. **모바일에서 더 심할 수 있습니다** |
| CSV의 `seller`에 상품명이 들어감 | 구간을 못 찾아 전체 문서를 훑음 (버그 #3) | 구간 미발견 시 `[]` 반환 정책 유지. 빈 결과가 지어낸 데이터보다 낫습니다 |
| `price`가 와우 회원가·쿠폰가와 뒤섞임 | **모바일에서 새로 생길 수 있는 위험** — 모바일은 정가·회원가·쿠폰적용가를 더 촘촘히 붙여 놓음 | 첫 CSV를 반드시 눈으로 검수 (`../pc-side/NOTES.md` 확인 5) |

> 위 세 가지 교정은 전부 **실물 모바일 픽스처를 커밋한 뒤**에 합니다.
> 실물을 안 보고 규칙을 넣는 것이 버그 #3이 생긴 경로입니다.

## 그 밖에

- **매번 탭해야 하나요?** 예. 사람이 자기 폰에서 연 페이지를, 사람이 탭했을 때만 읽는 것이
  이 경로의 전부입니다. 무인 자동 실행은 하지 않습니다.
- **폰에서 PC로 바로 못 보내나요?** 안 됩니다. https 페이지에서 `http://192.168.x.x`는
  mixed content로 차단되고, Chrome 142+는 로컬 네트워크 접근에 권한 프롬프트를 겁니다.
  파일 경로로 충분하므로 열지 않습니다.
- **스니펫을 고쳐도 되나요?** `run-javascript-body.js`는 **자동 생성물**입니다. 직접 고치면
  테스트가 실패합니다. `extract.js`를 고치고 `npm run build:snippet`을 돌리세요.
