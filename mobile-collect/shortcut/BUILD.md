# iOS 단축어 만들기 (최초 1회, 약 10분)

> **왜 완성된 단축어 파일을 주지 않나요?**
> iOS는 공유받은 단축어에 서명을 요구합니다. 서명은 Apple의 iCloud 링크로만 생기고
> 이 저장소에서는 만들 수 없습니다. 그래서 **액션을 직접 조립**합니다.
> 대신 판단 로직은 전부 `run-javascript-body.js` 한 덩어리에 들어 있어서,
> 조립하는 액션은 "받아서 → 분기해서 → 저장"뿐입니다.

> **액션 이름은 iOS 버전·언어에 따라 조금씩 다릅니다.** 아래 괄호 안 영문명으로 검색하거나,
> 설명된 *기능*으로 찾으세요. `웹페이지에서 JavaScript 실행`이 아예 안 보이면
> **설정 > 단축어 > 고급**에서 스크립트 관련 항목을 켜세요.

> 막히면 **[TROUBLESHOOT.md](TROUBLESHOOT.md)** 를 보세요. 증상별로 정리해 두었습니다.

---

## 0. 준비

- iCloud Drive에 `coupang-price/manual/` 폴더를 만들어 둡니다. (파일 앱 > iCloud Drive)
- PC에 **Windows용 iCloud**가 설치돼 있으면 이 폴더가 PC로 자동 동기화됩니다.
  없으면 README의 "대안 전송" 절을 보세요. 단축어 조립은 동일합니다.

## 1. 새 단축어 만들기

1. 단축어 앱 > 우상단 **+**
2. 우상단 **정보(ⓘ)** 또는 단축어 세부사항
   - **공유 시트에 표시** 켜기
   - 입력 유형에서 **Safari 웹페이지**만 남기고 나머지는 끄기
3. 이름: `쿠팡 수집`

## 2. 액션 조립

> **①을 만든 직후 한 번 확인하고 나머지를 만드세요.** 9개를 다 만든 뒤 확인하면 어디가
> 틀렸는지 알기 어렵습니다. ①만 만들어 결과를 눈으로 보면 조립이 맞는지와
> **"모바일 페이지가 담기긴 하는가"** 가 같이 판명됩니다. → [2-1 중간 확인](#2-1-중간-확인-을-만든-직후)

각 액션 끝의 **✔ 여기까지 됐으면** 은 그 액션까지 제대로 붙었을 때 화면에서 보이는 것입니다.
안 보이면 다음으로 넘어가지 말고 그 액션을 다시 보세요.

### ① 웹페이지에서 JavaScript 실행 (Run JavaScript on Webpage)

- `run-javascript-body.js` **전체**를 붙여넣습니다.
  (폰에서 GitHub raw 화면을 열어 전체 선택·복사하는 게 가장 쉽습니다.)
- 이 액션은 **Safari 공유 시트에서 실행할 때만** 입력을 받습니다.
  단축어 앱에서 ▶︎로 직접 돌리면 입력이 없어 실패하는 게 정상입니다.

✔ **여기까지 됐으면** — 액션 카드 안에 코드가 보이고, 첫 줄이
`// ⚠ 자동 생성 파일 — 직접 고치지 말 것.` 입니다. 이 줄이 없으면 일부만 복사된 것입니다.

### 2-1. 중간 확인 (①을 만든 직후)

수집용 스니펫은 수천 자짜리 JSON을 돌려주는데, 폰 화면에서 그걸 눈으로 훑어
`옵션`·`판매자`가 들어 있는지 확인하는 건 사실상 불가능합니다.
그래서 **이 확인에만 쓰는 진단 스니펫**을 따로 둡니다.

1. ①의 코드를 **[`diagnose-body.js`](diagnose-body.js) 로 잠시 바꿉니다.**
   (추출 코어는 수집용과 **같은 것**입니다. 출력 모양만 사람이 읽을 수 있게 바꾼 것이라,
   여기서 본 값이 수집에서도 그대로 나옵니다.)
2. ① 아래에 **클립보드에 복사 (Copy to Clipboard)** 를 **임시로** 추가합니다.
   결과를 그대로 붙여넣어 회신할 수 있어 스크린샷보다 정확합니다.
   화면으로도 보고 싶으면 **훑어보기 (Quick Look)** 를 함께 넣으세요.
   (Quick Look의 한글 액션 이름은 `결과 보기`가 아니라 **`훑어보기`** 입니다)
3. Safari로 `m.coupang.com/vm/products/8868816986` 열기
4. **로그인하지 마세요.** 상단에 `로그인 / 회원가입`이 보이는 상태가 맞습니다.
   (로그아웃으로도 수집에 충분함이 실측됐고, 로그인 수집은 계정 제재 위험을 만듭니다)
5. **아래로 내려 옵션을 펼칩니다.** 판매자 목록도 열어 두면 더 좋습니다.
6. 공유 → `쿠팡 수집`

이런 화면이 나옵니다 — 그대로 스크린샷 찍어 회신하시면 됩니다:

```
status    = ok
chars     = 12345
productId = 8868816986
host      = m.coupang.com

── 문구 확인 (체크리스트 4~6번) ──
"옵션" : 있음 (3회)
"원" : 있음 (57회)
"판매자" : 있음 (2회)

── "판매자" 주변 (parse.py 구간 마커 후보) ──
… 다른 판매자 보기 (3) ⏎ …

── "옵션" 주변 ──
── 본문 첫 300자 ──
```

> `status`가 `ok`가 아니면 본문 확인은 건너뛰고 `reason`만 보여 줍니다.
> **`blocked`면 재시도하지 마세요.**

확인이 끝나면 **임시로 넣은 액션(클립보드에 복사·훑어보기)을 지우고,
①의 코드를 `run-javascript-body.js`로 되돌린 뒤**
②부터 이어서 만듭니다. 진단 스니펫은 파일을 만들지 않으므로 수집에 쓸 수 없습니다.

### ② 사전 가져오기 (Get Dictionary from Input)

- 입력: ①의 결과. JSON 문자열이 사전으로 바뀝니다.

✔ **여기까지 됐으면** — 액션이 ①의 결과를 자동으로 입력으로 잡습니다.
"입력 없음"이라고 뜨면 ①과 ② 사이에 다른 액션이 끼어 있는 것입니다.

### ②' 변수 설정 (Set Variable) — 이름 `자료` ★ 반드시 넣으세요

②의 사전을 변수 `자료`에 담아 둡니다.

> **이 한 줄이 없으면 뒤가 조용히 망가집니다.** `사전 값 가져오기`는 기본적으로
> **바로 앞 동작의 결과**를 입력으로 잡습니다. ③ 뒤에서는 앞 동작의 결과가 `status`
> **문자열**이고, ⑤ 메뉴 뒤에서는 **메뉴 결과**입니다 — 둘 다 사전이 아닙니다.
> 그 상태로 `productId`·`text`·`reason`을 꺼내면 **오류가 아니라 빈 값**이 나옵니다.
> 빈 값은 `.txt`라는 이름의 빈 파일로 저장돼 조용히 흘러갑니다.
>
> 그래서 이 뒤의 `사전 값 가져오기`는 **전부 입력을 `자료`로 직접 지정합니다.**
> 입력 칸을 탭해 변수 `자료`를 고르세요. "이전 동작의 결과"가 잡혀 있으면 지우고 바꿉니다.

✔ **여기까지 됐으면** — 변수 목록에 `자료`가 생깁니다.

### ③ 사전 값 가져오기 (Get Dictionary Value) — 키 `status`, 입력 `자료`

✔ **여기까지 됐으면** — 키 칸에 `status`, 입력 칸에 변수 `자료`가 들어가 있습니다.

### ④ 만약 (If) — `status` 가 `ok` 와 같음

**"그렇지 않으면" 쪽 (차단·미완성):**

1. 사전 값 가져오기 — 키 `reason`, **입력 `자료`** (앞 동작의 결과가 아닙니다 — ②' 참고)
2. **알림 표시 (Show Alert)**: `수집 중단 — [status] / [reason]`
3. **단축어 중단 (Stop Shortcut)**

> 이게 인수인계 문서 §8의 종료코드 2 정책(차단 → 즉시 중단·재시도 금지)입니다.
> **차단일 때는 파일을 만들지 않습니다.** 차단 페이지 텍스트가 CSV로 흘러드는 것을 막습니다.
> `empty`가 뜨면 페이지가 덜 뜬 것이니 잠깐 기다렸다 다시 실행하세요.

**"만약" 쪽 (정상):** 아래 ⑥부터 계속. **⑤ 메뉴는 ⑥⑦ 다음입니다** — 순서가 바뀌었습니다.

✔ **여기까지 됐으면** — `만약` / `그렇지 않으면` / `만약 종료` 세 줄이 보이고,
⑤부터 ⑨는 **`만약`과 `그렇지 않으면` 사이**에 들어갑니다. 위치를 꼭 확인하세요 —
`만약 종료` 아래에 두면 차단일 때도 저장이 됩니다.

### 완성됐을 때의 전체 모양

**⑥⑦을 ⑤보다 먼저** 놓습니다. 메뉴 블록 안에서 사전을 꺼내면 입력이 꼬이기 때문입니다(②' 참고).
들여쓰기가 이 그림과 같은지 확인하세요 — 단축어에서 **깊이가 곧 실행 조건**입니다.

```
① 웹페이지에서 JavaScript 실행
② 사전 가져오기
②' 변수 설정  자료                      ★
③ 사전 값 가져오기  status  (입력: 자료)
④ 만약  status = ok
   ⑥ 사전 값 가져오기  productId (입력: 자료) → 변수 설정  상품키
   ⑦ 사전 값 가져오기  text      (입력: 자료) → 변수 설정  본문      ★
   ⑤ 메뉴에서 선택 "무엇을 담았나요?"
        옵션   → 변수 설정  접미사 = (빈 텍스트)
        판매자 → 변수 설정  접미사 = _sellers
        검색   → 변수 설정  접미사 = _search
      메뉴 종료                                                     ★
   ⑧ 파일 저장   본문 → /coupang-price/manual/[상품키][접미사].txt
   ⑨ 알림 표시   저장됨: [상품키][접미사].txt
   그렇지 않으면
      사전 값 가져오기  reason (입력: 자료)
      알림 표시  수집 중단 — [status] / [reason]
      단축어 중단
   만약 종료
```

> **⑧⑨는 `메뉴 종료` 아래, `그렇지 않으면` 위입니다.**
> 메뉴 갈래 **안에** 두면 세 갈래마다 파일 저장을 세 번 만들어야 하고, 한 갈래에만 두면
> 나머지 두 갈래에서는 **아무 파일도 안 생깁니다.** 갈래 안에는 `변수 설정 접미사` 한 줄씩만
> 들어갑니다.

### ⑥ 사전 값 가져오기 — 키 `productId`, 입력 `자료` → **변수 설정** `상품키`

> **PC의 `--from-text`가 상품명 기준 파일명을 기대한다면** 여기서 `사전 (Dictionary)` 액션으로
> `8868816986` → `그릭마일드` 같은 매핑 표를 만들고 `사전 값 가져오기`로 바꿔치기하세요.
> Python 코드를 안 고치고 규칙을 맞추는 방법입니다.
>
> **어느 쪽인지는 추측하지 말고 측정하세요** — 쿠팡 저장소에서
> `python mobile-collect/pc-side/check_pc_side.py` 를 돌리면 답이 나옵니다.
> (`../pc-side/NOTES.md` 확인 1)

✔ **여기까지 됐으면** — 변수 목록에 `상품키`가 생깁니다.

### ⑦ 사전 값 가져오기 — 키 `text`, 입력 `자료` → **변수 설정** `본문`

`본문` 변수로 담아 두는 것이 중요합니다. ⑧ 파일 저장은 ⑤ 메뉴 **뒤**에 오는데,
그때 "이전 동작의 결과"는 메뉴 결과라 본문이 아닙니다. 변수로 담아 두면 순서와 무관해집니다.

✔ **여기까지 됐으면** — 변수 목록에 `본문`이 생기고, 이 액션의 결과가 수천 자짜리 페이지 본문입니다.

### ⑤ 메뉴에서 선택 (Choose from Menu) — "무엇을 담았나요?"

세 갈래를 만들고, 각 갈래에서 **변수 설정 (Set Variable)** `접미사` 에 아래 값을 넣습니다.

| 메뉴 항목 | `접미사` 값 | 언제 |
|---|---|---|
| 옵션 | *(빈 텍스트)* | 옵션을 펼친 상품 페이지 |
| 판매자 | `_sellers` | 다른 판매자 목록을 연 상태 |
| 검색 | `_search` | 검색 결과 페이지 |

> 기존 수동 경로의 `<상품키>_search.txt` 규칙을 그대로 잇습니다.

> **`메뉴에서 선택`이 안 보이는 버전이면** — `목록에서 선택 (Choose from List)` 으로 대신합니다.
> `텍스트` 액션에 `옵션`/`판매자`/`검색` 세 줄을 넣고 → `목록에서 선택` → `만약`으로
> 고른 값을 비교해 `접미사`를 설정하면 같은 결과가 됩니다.

> **왜 사람에게 묻나요?** 페이지 텍스트만 보고 자동으로 판별할 수도 있지만, 지금은
> **실물 모바일 페이지 문구를 아직 못 봤습니다.** 잘못 분류하면 `source`가 틀리고,
> `source`가 틀리면 중복 판정 키가 틀려 데이터가 조용히 유실됩니다(인수인계 §10 버그 #2).
> 실물 픽스처를 확보한 뒤에 다시 검토합니다.

✔ **여기까지 됐으면** — 갈래마다 `변수 설정 접미사` **한 줄씩만** 들어 있고,
세 갈래 아래에 `메뉴 종료`가 보입니다. 실행하면 옵션 세 개짜리 메뉴가 뜹니다.

### ⑧ 파일 저장 (Save File)

- 파일: **변수 `본문`** (⑦에서 담아 둔 것 — "이전 동작의 결과"가 아닙니다)
- **저장할 위치 묻기: 끔**
- 서비스: iCloud Drive
- **파일이 이미 있으면 덮어쓰기: 켬**
  (같은 날 다시 담으면 최신값으로 갱신 — CSV 중복 판정과 같은 정책)

**파일명을 어디에 넣는지가 iOS 버전마다 다릅니다.** 화면에 보이는 것에 맞춰 고르세요:

| 화면에 보이는 것 | 어떻게 | 결과 |
|---|---|---|
| 대상 경로 칸에 파일명까지 쓸 수 있음 | 경로를 `/coupang-price/manual/[상품키][접미사].txt` 로 지정 | 액션 1개로 끝 |
| 경로는 **폴더까지만** 받음 | `파일 저장` **앞**에 **이름 변경 (Rename File)** 을 넣고 `[상품키][접미사].txt` 지정. 경로는 `/coupang-price/manual/` | 액션 2개 |
| 경로 칸이 아예 없음 (위치 묻기만 있음) | `저장할 위치 묻기`를 **켜고** 매번 폴더를 고름. 파일명은 `이름 변경`으로 미리 지정 | 탭이 한 번 늘어남 |
| iCloud Drive 서비스가 안 보임 | `파일 저장` 대신 **공유 (Share)** 로 대체 — README "대안 전송" 표 참고 | 카카오톡·드라이브 경유 |

> 어느 쪽을 쓰든 **최종 파일명은 `<상품키><접미사>.txt` 하나**입니다.
> PC의 `--from-text`가 이 이름으로 상품과 `source`를 정합니다.

✔ **여기까지 됐으면** — 파일 앱 `iCloud Drive/coupang-price/manual/` 에
`8868816986.txt` 가 생깁니다. 이름이 `쿠팡 수집.txt` 나 `텍스트.txt` 면 파일명 지정이
안 먹은 것이니 위 표의 두 번째 줄로 가세요.

### ⑨ (선택) 알림 표시 — `저장됨: [상품키][접미사].txt`

✔ **여기까지 됐으면** — 수집할 때마다 저장된 파일명이 알림으로 뜹니다.

## 3. 조립 확인

단축어 앱에서 ▶︎로 돌리면 **①에서 실패하는 것이 정상**입니다(입력이 없음).
실제 확인은 Safari에서:

1. Safari로 `m.coupang.com/vm/products/8868816986` 열기 (**로그아웃 상태로**)
2. 아래로 내려 **옵션 펼치기**
3. 공유 → `쿠팡 수집` → 메뉴에서 `옵션`
4. 알림이 뜨고 파일 앱 `iCloud Drive/coupang-price/manual/`에 `8868816986.txt`가 생기면 성공

처음 실행 시 "이 단축어가 웹페이지 내용에 접근하려고 합니다" 같은 권한 요청이 뜹니다. 허용하세요.

**파일은 생겼는데 내용이 이상하면 — 이름부터 보세요.** 입력 연결이 끊긴 자리를 이름이 알려 줍니다.

| 생긴 파일 | 끊긴 곳 |
|---|---|
| `.txt` (이름이 없음) | ⑥이 `productId`를 못 꺼냄 → ⑥의 입력이 `자료`가 아님 |
| `8868816986.txt`인데 **0바이트·몇 글자뿐** | ⑦이 `text`를 못 꺼냄 → ⑦의 입력이 `자료`가 아니거나, ⑧이 `본문` 변수가 아닌 "이전 동작의 결과"를 저장 중 |
| 이름이 `쿠팡 수집.txt`·`텍스트.txt` | 파일명 지정이 안 먹음 → ⑧ 표의 두 번째 줄(`이름 변경` 선행)로 |
| `_sellers`를 골랐는데 접미사가 없음 | `변수 설정 접미사`가 그 갈래에 없음 → 세 갈래 전부에 한 줄씩 |
| 세 갈래 중 하나에서만 파일이 생김 | ⑧이 메뉴 갈래 **안**에 있음 → `메뉴 종료` 아래로 옮기기 |

> **차단됐는데 파일이 생겼다면** ⑤~⑨가 `만약 종료` 아래에 있는 것입니다. 가장 위험한 배치입니다 —
> 차단 페이지 텍스트가 CSV로 흘러듭니다. 즉시 `만약`과 `그렇지 않으면` 사이로 옮기세요.

## 4. 증거 체크리스트

**2-1의 중간 확인에서 이 5줄을 채워 회신하세요.** 다음 작업(파서 교정)이 이 값으로 결정됩니다.
스크린샷만으로는 `text` 안쪽을 볼 수 없어서 3~5번이 필요합니다.

```
1. status      =            (ok 여야 함. blocked/empty/error면 그 값과 reason)
2. chars       =            (수천 자 기대. 500 미만이면 렌더가 덜 끝난 것)
3. productId   =            (8868816986 이어야 함. null이면 URL 형태를 알려 주세요)
4. text 안에 "옵션" 있음?     예 / 아니오
5. text 안에 "원" 있음?       예 / 아니오
6. text 안에 "판매자" 있음?   예 / 아니오
7. 저장된 파일명 =            (⑧까지 만든 뒤. 예: 8868816986.txt)
```

> **`status`가 `blocked`면 재시도하지 마세요.** `reason`에 적힌 마커만 알려 주시면 됩니다.
> `empty`는 다릅니다 — 페이지가 덜 뜬 것이니 잠깐 뒤 다시 탭해도 됩니다.

> **가장 중요한 건 4~6번입니다.** 여기서 "아니오"가 나오면 모바일 페이지의 옵션·판매자 구간이
> 데스크톱과 다른 문구라는 뜻이고, `parse.py`의 마커를 고쳐야 합니다.
> 그 교정은 **실물 텍스트를 픽스처로 커밋한 뒤에** 합니다(`../pc-side/NOTES.md` 순서 참고).
