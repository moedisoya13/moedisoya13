## 이 계획의 전제

모바일 인수인계 §10에서 작업이 멈춰 있었습니다 — 단축어 9개 액션 중 **①까지만 조립**했고
사용자의 실행 결과를 기다리는 상태. §11의 남은 일 1~5는 하나도 끝나지 않았습니다.

그런데 남은 일의 상당수는 **이 세션이 끝낼 수 없는 종류**입니다.

| 막고 있는 것 | 왜 |
|---|---|
| 사용자의 iPhone | 단축어 조립·수집은 사람이 탭해야 합니다. 그게 이 경로의 전부입니다 |
| `C:\Users\gram\Downloads\NewPipe` | 로컬 Windows 전용, GitHub에 없음. 코드를 볼 수 없습니다 |
| 실물 모바일 텍스트 | 확인 4·5는 실물 없이 시작조차 하면 안 됩니다 (버그 #3이 그렇게 생겼습니다) |

그래서 이번 목표를 **"대신 해준다"가 아니라 "추측을 측정으로 바꾼다"** 로 잡았습니다.
사용자가 손에 쥐고 실행하면 답이 나오는 **계측기**를 만들고, 사람이 있어야 하는 지점에서

Akamai 센서 조작 · `_abck` 조작 · 인간 입력 시뮬레이션 · TLS/HTTP2 지문 위조 ·
프록시 로테이션 · CAPTCHA 자동 해결 · 사용자 본인 프로필 사용 · LAN 직접 전송 ·

| 하지 않음 | 이유 |
|---|---|
| `.claude/commands/goal.md` 생성 | `/goal`은 기본 명령어다. 동명 파일은 그것을 가린다 |
| 메뉴 ⑤를 텍스트 자동분류로 대체 (액션 9→6개 축소) | 매력적이지만 **실물 모바일 문구를 아직 못 봤다.** 잘못 분류하면 `source`가 틀리고 → 중복 판정 키가 틀리고 → 버그 #2식 유실. 버그 #3과 정확히 같은 실수 패턴. **B-2 이후 재검토** |

읽기 전용입니다. 구매·장바구니·로그인은 건드리지 않습니다.

## 알려진 불확실성 (계승 + 신규)

- **파서가 모바일 텍스트에 맞는지 여전히 검증되지 않았습니다.** 픽스처가 전부 합성입니다.
- **옵션·판매자 구간이 모바일에 어떤 문구로 있는지 모릅니다.** B-1의 증거 체크리스트 4~6번이
  이걸 처음으로 알려 줍니다.
- **`m.coupang.com`이 `www`로 리다이렉트될 때의 최종 URL 형태**를 실측하지 못했습니다.
  `parseProductUrl`은 `/vm/`·`/vp/` 양쪽을 처리하지만 확인은 B-1에서 납니다.
- **`from_text.py`의 파일명 규칙**은 여전히 모릅니다. 다만 이제 **추측하지 않고 측정합니다**
  (B-4). 이 항목은 "모름"에서 "측정 대기"로 바뀌었습니다.
- **`check_pc_side.py`의 확인 1은 판정하지 않습니다.** 근거만 인쇄하고 사람이 고릅니다.
  파일명 처리 방식이 함수 형태가 아니면(예: 정규식 한 줄) 못 찾을 수 있습니다.
- **모달 배경 텍스트 문제(버그 #1)가 모바일에서 더 심할 수 있습니다.**
