# 그레이박스 맵 (조감 3/4 시점)

레퍼런스 게임 영상의 **카메라와 픽셀 격자**를 재서, 같은 시점으로 회색 상자(그레이박스¹) 테스트 맵을 pixel-splat 엔진에서 그린다.
캐릭터는 스킨 없는 마네킹(BB, `examples/soldier ... --outfit none`)을 그대로 세워 크기를 맞춘다.

```
layout.json ──level.py──▶ height(x,z) · surface(x,z)        게임 로직이 묻는 것 (땅 높이, 밟은 재질)
                      └──▶ splats() ─▶ SplatModel            그리는 것 (학습 없음)
            ──graybox.py build──▶ 레벨 전체 G-buffer 1장 + 해 그림자 맵  (out/map/level_bake.npz)
            ──graybox.py render / clip / compare──▶ PNG · MP4 · GIF
```

## 실행

```bash
cd pixel-splat            # venv 활성화 상태, PYTHONPATH=.
python examples/map/graybox.py build   -o out/map     # 1~2분 (splat 17만 개, CPU 4코어)
python examples/map/graybox.py render  -o out/map     # overview.png, view_bb.png, bb_closeup.png (5~15초)
python examples/map/graybox.py clip    -o out/map     # walk_follow.mp4 / .gif (프레임당 0.5~0.9초, 371프레임)
python examples/map/graybox.py compare -o out/map --ref-video <레퍼런스.mp4> --ref-time 15
```

BB는 `out/bb`(60k splat)를 읽어 1,000개로 솎고 그만큼 키워 쓴다. 인물이 6×16픽셀이라 splat이 전부 래스터 타일 몇 칸에 몰리는데,
래스터 비용은 타일당 splat 수에 비례한다(60k 그대로면 프레임당 10초 이상, 1,000개면 0.5초, 이 크기에서는 그림이 같다). 다른 폴더면 `--bb`.
BB 색은 기본이 단색(따뜻한 점토색)이다. 구울 때의 색을 쓰려면 `--bb-color own`.

## 맵 고치기: `layout.json`

길이는 전부 **미터**, `x` = 동쪽, `z` = 남쪽(카메라 쪽), 높이는 풀밭 기준. 각도는 도(°)이고 +x에서 +z 쪽으로 돈다.
월드 단위는 soldier와 같다(1.80 단위 = 1.75 m, 땅 y = −1). 변환은 `level.UNITS_PER_M`.

| `type` | 뜻 | 값 |
|---|---|---|
| `hill` | 완만한 언덕 | `at`, `radius`, `height` |
| `pond` | 평평하게 꺼진 연못(어두운 면) | `at`, `radius` [rx, rz], `depth`, `bank`(기슭 폭) |
| `plateau` | 절벽으로 둘러싸인 단 | `at`, `size` [가로, 세로], `height`, `rot` |
| `ramp` | 경사로 | `at`, `size` [길이, 폭], `rot`(오르는 방향), `height` [시작, 끝] |
| `path` | 길(땅에 칠한 띠) | `points` [[x,z]…], `width` |
| `spawn` | 스폰 표시(원판 + 바라보는 방향) | `at`, `facing` |
| `rock` | 바위(반 타원체) | `at`, `size` [가로, 높이, 세로], `rot` |
| `tree` | 나무 대역(원기둥 + 원뿔/구) | `at`, `height`, `radius`, `canopy` = `cone`\|`sphere` |

`demo` 항목은 렌더용이다: `stand`(BB가 서는 곳), `walk`(걷는 경로·속도), `compare`(비교 그림에서 서는 곳).
고친 뒤에는 `build`부터 다시 돌린다. 색은 재질과 높이로만 정한다(`level.TONE`, 걸을 수 있는 땅은 1 m 오를 때마다 조금 밝게).
바닥의 눈금은 1 m(굵은 선 5 m)이고 픽셀마다 월드 좌표로 그려서 항상 1픽셀 폭이다. 선의 반폭은 그 픽셀이 덮는 땅의 반이고,
픽셀의 법선으로 계산하므로 경사로·언덕에서도 1픽셀이다(평지 값 하나로 그리면 카메라 쪽 경사로에서 선이 절반쯤 2픽셀이 된다).

## 카메라 측정 (레퍼런스 영상 1848×1080, 60 fps, 44.5초)

| 항목 | 값 | 어떻게 쟀나 | 확실한 정도 |
|---|---|---|---|
| 아트 픽셀² 크기 | 영상 8.745 px | 가로·세로 경계 밝기차의 주기(푸리에) — 5개 프레임에서 같은 값 | 측정 |
| 한 화면 | 211.3 × 123.5 아트 픽셀 | 1848/8.745, 1080/8.745 | 측정 |
| 투영 | **직교**(원근 없음) | 카메라가 움직일 때 화면 위쪽 띠와 아래쪽 띠의 땅 흐름 비 = 1.0000 (사분위 0.9988~1.0011, 1,080개 구간). 세로 화각 10°의 원근만 있어도 1.09~1.18이어야 한다 | 측정 |
| 격자 | 월드에 고정 | 격자 위상이 프레임마다 바뀐다 = 저해상도 그림을 통째로 서브픽셀 이동(부드러운 스크롤) | 측정 |
| 내려다보는 각 | **45° (정한 값)** | 측정으로는 정해지지 않았다: 땅 위 단서는 25~36°, 단서 하나는 44~45°(아래 "각도"). 그중 **45°를 쓰기로 정했다**. 30°도 옵션으로 남긴다 | 선택 |
| 사람 크기 | 선 사람 ≈ **16 아트 픽셀** (몸통 폭 6~7) | 15초 프레임의 선 캐릭터(머리 끝~발) | 측정(1프레임), 캐릭터 실제 키는 모름 |
| 배율 | **11.1** 아트 픽셀 / 월드 단위 (11.42 px/m) | 1.75 m BB가 45°에서 16픽셀이 되도록 맞춤 — 렌더로 확인(아래 "배율") | 위 둘에서 유도 |
| 보이는 땅 | 가로 18.5 m × 깊이 15.4 m | 211/11.42, 124/11.42/sin45° | 유도 |
| 해 | 그림자는 화면 왼쪽 + 약간 아래로, 길이 ≈ 화면에서 기둥 키의 0.89배 | 15초 프레임의 선 캐릭터 그림자(약 12×2 픽셀) | 추정 |

30°로 그리려면 `build --elev 30 --px-per-unit 9.6`(BB 16픽셀, 9.87 px/m, 한 화면 21.4 m × 25.1 m).

**배율**³: 선 BB는 같은 키의 막대보다 화면에서 크다. 몸의 앞뒤 두께가 sin(각)만큼 더 보이기 때문인데, 45°에서는 그 몫이 30°보다 크다.
그래서 cos 비율로 옮긴 값(9.6 × cos30°/cos45° = 11.8)이나 앞서 적어 둔 11.3은 크다 — 11.3은 렌더하면 **17~18픽셀**이다.
BB가 서는 자리의 소수 픽셀 위치에 따라 1픽셀씩 달라지므로 12곳(서브픽셀 위치를 고르게)에서 쟀다(평평한 땅, `figure_height_px`):

| 각 | 배율 | BB 키(픽셀), 12곳 | 평균 |
|---|---|---|---|
| 30° | 9.6 | 16 ×9, 17 ×3 | 16.25 |
| 45° | 10.4 | 15 ×10, 16 ×2 | 15.17 |
| 45° | 10.6 | 15 ×9, 16 ×3 (데모 자리는 16) | 15.25 |
| 45° | 10.8 / 10.9 | 15 ×5, 16 ×7 | 15.58 |
| 45° | 11.0 | 15 ×1, 16 ×11 | 15.92 |
| 45° | **11.1** | **16 ×12** | **16.00** |
| 45° | 11.2 | 16 ×9, 17 ×3 | 16.25 |
| 45° | 11.3 | 17 ×11, 18 ×1 (데모 자리는 18) | 17.08 |

11.1은 12곳 모두 16픽셀이고 양옆(11.0, 11.2)도 거의 16이라 가운데 값으로 골랐다. 10.6은 데모 자리 한 곳에서만 16이고 대부분 15다.

**각도**: 직교 카메라에서는 땅 위의 원이 세로로 sin(각) 만큼 눌려 보인다. 그 눌림을 네 가지로 쟀는데 서로 꼭 맞지는 않는다.

| 단서 | sin(각) | 각 |
|---|---|---|
| 곰이 방향을 바꿀 때 실루엣의 가로 분산 대 세로 분산의 기울기(타원체 근사) | 0.41~0.55 | 25~33° |
| 곰의 땅 위 속도(화면 속도 + 땅 흐름) 분포를 가장 뾰족하게 만드는 값 | 0.59 (군집별로는 0.38~0.58) | 36° (22~35°) |
| 땅에 떨어진 핏자국 분포의 세로/가로 폭 | 0.44~0.48 (초반 작은 무리는 0.6~0.7) | 26~29° |
| 플레이어 질주 속도가 모든 방향에서 같다고 볼 때(카메라 속도의 바깥 테두리) | 0.70 | 44° |

땅 위 단서 세 가지는 25~36°에 모이고, 플레이어 속도 단서는 44°를 가리킨다. 측정만으로는 어느 쪽인지 정할 수 없어서
**45°를 기본값으로 쓰기로 정했다**(측정 결과가 아니라 선택이다). 30°는 `--elev 30 --px-per-unit 9.6`으로 그대로 쓸 수 있다.
레퍼런스가 어떤 엔진으로 만들어졌는지는 알 수 없다.

## 왜 이렇게 만들었나

- **레벨은 학습하지 않는다.** 요소가 전부 수식으로 된 단순한 모양이라 splat을 표면에 **격자로** 직접 놓는다(중심·법선·크기가 수식에서 나온다).
  섞지 않는(hard) 합성은 splat 중심에서 1.41σ 안쪽만 덮는데, 격자 간격 d에 σ = 0.62d면 빈틈이 없다(테스트로 확인).
  같은 조건을 무작위 표본(`SplatModel.from_mesh`)으로 채우려면 splat이 약 5배 필요하다.
- **레벨 G-buffer는 한 번만 그린다.** 직교 카메라는 정수 픽셀만큼 옮겨도 같은 픽셀이 그대로 밀릴 뿐이라(테스트로 확인),
  레벨 전체를 월드에 고정된 격자로 한 장 구워 두고 프레임마다 창만 잘라 쓴다. 카메라가 흘러도 **배경은 절대 자글거리지 않고**
  프레임 비용은 BB와 조명뿐이다. 남는 소수 픽셀은 확대한 뒤에 옮긴다(레퍼런스와 같은 방식).
- **엔진 코드를 그대로 쓴다**: `rasterize`(큰 그림은 256px 조각으로 나눠 호출), 2× 렌더 + 투표(`select_downsample`), `despeckle`,
  `shade` / `postprocess`, `ShadowMap` + `visibility`, BB는 `render_gbuffer_frame`(Almost Pixel Perfect snapping 포함).
  예제에서 따로 한 것은 둘이다: 외곽선(엔진의 깊이차 기준은 낮은 각도로 본 땅 전체에 선을 긋는다 → 접평면 거리 기준),
  SSAO 반경(엔진 기본값은 2단위짜리 모델용 → `gbuf.ssao`를 장면 크기로 호출).

## 맵을 짤 때 알아둘 것 (이 카메라의 성질)
- 높이 h인 물체는 **뒤(북쪽) 땅을 h × 1.0 만큼 가린다**(45° 기준, h / tan 45°; 30°였다면 h × 1.73). 5 m 나무는 뒤쪽 5 m를 덮는다.
  그래도 싸움터 남쪽에는 키 큰 것을 두지 않는 편이 좋다(30°로 그릴 때 데모 지점이 나무에 두 번 가려져 나무를 옮겼다).
- 화면 세로 1픽셀이 땅에서는 1.41픽셀 거리다(가로 11.42 px/m, 깊이 방향 8.07 px/m; 30°라면 2배). 깊이 방향 길·틈은 가로보다 1.4배 넓게 잡아야 같은 굵기로 보인다.
- 해는 레퍼런스 화면에서 읽은 **그림자 모양**(기둥 그림자가 화면에서 기둥 키의 0.89배 왼쪽, 0.08배 아래)으로 정해 두고,
  각도에 맞는 해 방향을 거기서 계산한다(30°: 고도 52°·방위 100°, 45°: 고도 57.7°·방위 97.1°). 각도를 바꿔도 그림자가 화면에서 같은 모양이다.

## 한계
- BB는 16픽셀이라 걸을 때 픽셀이 조금씩 바뀐다(snapping으로 줄였을 뿐 없앨 수는 없다). 배경은 고정이다.
- 경사로·언덕 위에서 BB는 골반 위치의 땅 높이만 따라간다(양발이 각각 땅에 붙지는 않는다).
- 카메라 방위(`--az`)는 0만 눈으로 확인했다. 정확히 남쪽에서 볼 때 나무의 좌우 대칭 splat은 깊이가 같아 앞뒤 순서가 임의다(그림에는 영향 없음).
- 눈금·그림자 맵은 `build` 때 굽는다. 해 방향이나 격자를 바꾸면 다시 구워야 한다.

---
¹ **그레이박스(gray box, blockout)**: 텍스처 없이 회색 덩어리만으로 맵의 크기·동선·높낮이를 먼저 잡아 보는 단계.
² **아트 픽셀**: 확대하기 전, 저해상도 그림의 픽셀 한 칸.
³ **배율(px_per_unit)**: 월드 길이 1단위가 화면에서 몇 아트 픽셀인지. 카메라를 더 내려다보게(각도↑) 하면 서 있는 물체가 화면에서 짧아지므로, 사람을 같은 16픽셀로 두려면 배율을 키워야 한다.
