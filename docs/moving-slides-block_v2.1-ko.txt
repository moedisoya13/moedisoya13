[움직이는 자료 블록 v2.1-ko] AI 슬라이드 작성 참고 문서

■ 이 문서의 용도
- 슬라이드(발표 자료)를 만들 때 따르는 규칙이다. 원본은 일본어 「動く資料ブロック v2.1」이며, 한국어 환경에 맞게 고쳤다.
- 함께 제공된 "자료 작성 프롬프트"(이하 기본 프롬프트)가 있으면 그 위에 얹어 쓴다. 없으면 이 문서만으로 만든다(아래 "기본 프롬프트가 없을 때"를 적용한다).
- 소재(숫자·자료 발췌·URL과 메모)는 사용자가 대화에 붙이거나 파일로 첨부한다.
- 이 문서 안의 숫자·항목명·문구는 전부 형식을 보여 주기 위한 가공 예시다. 소재로 쓰지 않는다.


## 1. 우선순위
- 내용(숫자 처리·제목·논리·유형·그리는 기준·검증)은 기본 프롬프트를 따른다.
- 출력 형태는 이 문서를 우선한다: 파일 1개로 된 움직이는 HTML, 3페이지(소재가 많을 때만 4페이지), 제목은 1줄(띄어쓰기 포함 38자 이내, 2줄로 만들지 않는다). 설계도는 따로 내지 않고, 출력의 페이지 목록과 숫자 대장으로 대신한다(기본 프롬프트가 요구하는 설계 항목은 이 두 가지에 넣는다).
- 질문은 목적이나 독자를 소재에서도 배경에서도 읽어낼 수 없을 때만, 만들기 전에 모아서 1회 한다. 그 외에는 상식적으로 정하고 주석을 달며, 1회에 끝까지 다 쓴다.
- 언어: 슬라이드와 답변 본문은 한국어로 쓴다. 고유명사·지표명처럼 원어가 더 정확한 것만 영어를 병기한다.


## 2. 한 페이지의 틀 (외형은 아래 견본에 맞춘다)
- 첫 페이지: 위에 큰 숫자 띠(3개), 아래에 전체 흐름 또는 구조(어디서 무엇이 일어나고 있는가). 흐름의 각 지점에 해당 페이지로 들어가는 카드("p.2 ›")를 둔다.
- 본문 페이지(2번째 이후): 왼쪽에 주인공 그림(가로 폭의 60%), 오른쪽에 근거 요약 패널(옅은 바탕의 틀). 패널은 큰 숫자 1개(88~96px) → 그것이 무엇인지 1줄 → 보충 2~3줄 → 비교 대상과의 차이(계산식 포함) → "내역 보기 ›".
- 큰 숫자는 한 페이지에 하나. 예외는 첫 페이지의 요약 띠(3개)뿐이다.
- 그림도 숫자도 틀을 가득 채워 배치한다. 본문 아래에 빈 띠를 남기지 않는다.
- 소재의 숫자는 전부 어딘가에 쓴다(그림·패널·말풍선·근거 패널). 차이나 비율은 계산해서 식을 적는다. 소재에 없는 숫자는 두지 않는다.
- 주인공은 주인공 색, 비교 대상은 옅은 단계 색, 그 외는 회색.
- 누를 수 있는 것은 보고 알 수 있게 한다: "›", "누르면 ~" 같은 문구, 호버 시 테두리, 페이지에 들어온 직후 한 번만 링으로 알림. 막대나 점은 호버하면 "값·이름·출처" 말풍선을 띄운다.


## 3. 한 장에 조작 하나 (구조에서 끌어낸다)
각 페이지에, 제목의 판단을 독자가 스스로 확인할 수 있는 조작을 딱 하나만 붙인다. 조작은 제목이 말하려는 내용의 구조로 고른다.
- 피라미드(결론과 근거) → 누르면 아래 계층으로 파고든다. 오른쪽에서 근거 패널이 나온다(출처 포함).
- 분류(자르는 관점) → 관점(집계 기준·지표·연도)을 전환하면 모든 막대가 재정렬된다.
- 비교(차이) → 이전이 이후로 형태를 바꾸고, 차이나 사라진 부분이 점선으로 남는다.
- 인과(원인과 결과) → 조건을 슬라이더로 움직이면 결과가 다시 계산된다. 식을 화면에 표시한다.
- 문제 해결(부족과 해결책) → 해결책을 켜고 끄면 부족분이 메워지거나 남는다.
- 순서(흐름·공정·시간) → 차례로 조립된다, 주체가 공정을 나아간다, 시간축에 "지금" 선을 긋는다.
제목과 관계없는 움직임은 넣지 않는다. 양을 나타내는 움직임은 값에서 계산한다.


## 4. 근거 패널 (누르면 오른쪽에서 나온다)
- 모든 본문 페이지(2번째 이후)에 반드시 붙인다. 첫 페이지는 선택이다.
- 폭 720px. 오른쪽에서 미끄러져 들어오며 뒤를 어둡게 한다. ×·Esc·뒤쪽을 누르면 닫힌다.
- 위에서부터: 어디에 관한 이야기인지("현황 › 항목명") → 판단 1~2줄 → 탭(2개까지. 예: 내역／출처와 전제) → 작은 그림이나 표 → 출처.
- 본문에 다 싣지 못하는 상세한 숫자는 여기에 둔다.


## 5. 자료 전체
- 첫 페이지의 전체상에서 누른 곳으로 줌해 각 페이지로 들어갈 수 있게 한다. 해결책에서는 근거 페이지로 이동할 수 있게 한다.
- 키: → 와 Space로 다음, ← 로 이전, 숫자로 이동, Esc로 닫기·돌아가기, O로 전체 페이지 목록, D로 자동 데모(화살표 커서가 대본대로 조작하고 목록에서 끝난다. 조작할 요소에는 data-demo로 이름을 붙인다).
- 페이지에 들어가면 3초 안팎으로 조립된다: 제목 → 주인공 그림(막대는 0에서 늘어나고 60ms씩 시차를 둔다) → 숫자 → 근거 요약 패널. CSS transition과 지연으로 구성하고, JS로 움직일 때는 requestAnimationFrame에 50ms 타이머를 함께 돌린다(미리보기·백그라운드 탭에서 rAF가 멈춰도 조립이 끝나도록).
- URL의 #static과 "동작 줄이기"(prefers-reduced-motion) 설정에서는 조립이 끝난 최종 상태를 보여 준다(조작으로 바뀌는 페이지는 제목의 판단이 보이는 상태. 예: 해결책은 전부 켬). 멈춰 있어도 자료로 읽혀야 한다.
- 1920×1080 캔버스를 화면에 맞춰 축소한다. 외부 로드는 Google Fonts의 Noto Sans KR만 쓴다. HTML에는 lang="ko"를 단다.


## 6. 한국어 표기 규칙
- 증감: 증가는 +, 감소는 −(마이너스)로 쓴다. ▲▼△ 기호는 쓰지 않는다(▲를 상승으로 읽는 관행과 △를 음수로 쓰는 회계 관행이 섞여 있어 해석이 갈린다).
- 비율끼리의 차이는 %p로 쓴다(예: 37.7% − 52.1% = −14.4%p). %와 %p를 섞지 않는다.
- 큰 수는 만·억·조 단위와 천 단위 쉼표를 쓴다(예: 1조 2,340억 원, 3,450만 명). 한 자료 안에서 단위를 통일한다.
- 날짜와 시점은 한 가지 형식으로 통일한다(예: 2026년 3월 또는 2026.3).
- 제목은 "~다"로 끝나는 완전한 평서문으로 쓴다. 개조식 종결(~함, ~임, ~필요, ~강화 같은 명사형 끝맺음)은 쓰지 않는다.
- 제목 어미는 페이지마다 다르게 한다(예: "~했다", "~이다", "~할 수 있다"). 전부 "~해야 한다"로 맞추지 않는다.
- 제목 길이: 띄어쓰기 포함 38자 이내. 48px 기준으로 폭 1,748px(캔버스 좌우 여백 86px 제외)를 넘지 않아야 한다.


## 7. 기본 프롬프트가 없을 때 (최저선)
1. 소재에서 숫자 대장을 만든다(항목·값·시점·출처·모집단). 소재에 없는 숫자는 만들지 않고 "xx"로 두고 주석을 단다. 순위에서는 값이 없는 항목을 맨 뒤에 둔다.
2. 한 페이지에 메시지 하나. 제목은 사실과 판단을 한 문장에 담은 완전한 문장으로 쓴다(길이·어미는 6절). "A. B" 식의 두 문장 구성, "~는 3가지" 식의 개수 열거, 명사형 종결로 쓰지 않는다.
3. 제목만 먼저 전부 쓰고, 세로로 이어 읽어서 "전체상 → 근거 → 해결책"의 흐름이 통하는지 확인한 뒤 그림을 만든다.
4. 그림은 제목이 말하려는 내용의 구조로 고른다(3절의 6가지).
5. 도표 제목은 "무엇을·언제·단위". 판단은 쓰지 않는다. 출처는 페이지 하단과 근거 패널 양쪽에 쓴다.
6. 색은 주인공 색 1색, 옅은 단계 3개, 회색. 주인공 색은 지정이 없으면 #1976D2. 강조색(앰버 #D97706)은 자료 전체에서 한 곳만 쓴다.
7. 글자는 캔버스 기준 최소 18px(각주·출처), 본문은 20px 이상. 캔버스가 화면에 맞춰 축소되므로(1280px 폭 화면에서는 약 2/3) 이보다 작게 쓰지 않는다.
8. 상관관계만 있는 데이터로 인과를 단정하지 않는다. 추산은 "추산"이라고 쓰고 식과 전제를 화면에 표시한다.


## 8. 출력
- HTML: Claude는 아티팩트, ChatGPT는 캔버스에 쓴다(둘 다 없으면 코드 블록 1개). 1회에 끝까지 다 쓴다. 그러기 위해 페이지를 줄이고, 같은 부품은 함수로 묶어 짧게 쓴다. 도중에 멈추면 사용자가 "계속"이라고 할 때 같은 문서에 이어서 덧붙인다(손으로 이어 붙이게 하지 않는다).
- 첫 줄에 만든 방식을 쓴다: "내용＝기본 프롬프트／동작＝움직이는 자료 블록" 또는 "움직이는 자료 블록 단독(내용은 최저선 규칙으로 작성)".
- 페이지 목록(제목／구조／조작／근거 패널 내용), 숫자 대장, 조작 방법은 HTML 밖(답변 본문)에 짧게 쓴다. HTML 안에는 넣지 않는다.
- HTML은 전체 40KB 안팎을 기준으로 한다. 길어질 것 같으면 문장을 줄인다(그림·근거 패널·조작은 줄이지 않는다).
- 마지막에 더 좋게 만들 방향을 2~3개 제시해 고르게 한다.


## 9. 마무리 점검 (내보내기 전에 점검하고, 고친 뒤 내보낸다)
- 모든 페이지에 "제목의 판단을 확인하는 조작"이 있다. 모든 본문 페이지에 "출처가 있는 근거 패널"이 있다.
- 소재에 없는 숫자가 없다. 소재의 숫자가 빠짐없이 쓰였다.
- 본문 아래의 빈 띠, 글자 겹침, 삐져나옴, 18px 미만 글자가 없다. 제목이 1줄에 들어간다.
- 큰 숫자가 한 페이지에 하나다(첫 페이지 요약 띠만 예외).
- ▲▼△ 기호가 없고, %와 %p가 섞이지 않았다.
- 제목 어미가 모든 페이지에서 똑같지 않다. 개조식 종결이 없다.
- 자동 데모 대본이 존재하지 않는 요소를 가리키지 않는다.
- 코드 안의 URL이 꺾쇠(< >)로 감싸여 있지 않다.

const fit = () => { const s = Math.min(innerWidth / 1920, innerHeight / 1080); stage.style.transform = `translate(${(innerWidth - 1920 * s) / 2}px,${(innerHeight - 1080 * s) / 2}px) scale(${s})`; };
addEventListener('resize', fit); fit();
const el = (n, a, p) => { const e = document.createElementNS('http://www.w3.org/2000/svg', n); for (const k in a) e.setAttribute(k, a[k]); p.appendChild(e); return e; };
DATA.forEach(([name, v], i) => {
  const y = 24 + i * 140, w = v * 14, me = name === FOCUS;   // 길이는 값에서 계산한다. 주인공만 주인공 색. 세로는 틀을 가득 채워 배치한다
  el('text', { x: 0, y: y + 42, 'font-size': 22, 'font-weight': me ? 700 : 500 }, svg).textContent = name;
  const r = el('rect', { x: 170, y, width: w, height: 64, fill: me ? 'var(--main)' : 'var(--t3)', class: 'bar', style: `transition-delay:${300 + i * 60}ms` }, svg);
  el('text', { x: 184 + w, y: y + 42, 'font-size': 24, 'font-weight': 700, class: 'rv', style: `transition-delay:${900 + i * 60}ms` }, svg).textContent = v.toFixed(1) + '%';
  const move = e => { const b = stage.getBoundingClientRect(), s = b.width / 1920; tip.style.left = (e.clientX - b.left) / s + 18 + 'px'; tip.style.top = (e.clientY - b.top) / s + 18 + 'px'; };
  r.addEventListener('pointerenter', e => { tip.innerHTML = `<b>${v.toFixed(1)}%</b><br>${name}<br><span style="color:var(--note)">${SRC}</span>`; tip.style.display = 'block'; move(e); });
  r.addEventListener('pointermove', move);
  r.addEventListener('pointerleave', () => { tip.style.display = 'none'; });
  r.addEventListener('click', () => openDrawer(name));
});
function openDrawer(name) {   // 근거 패널: 어디에 관한 이야기인지 → 판단 → 탭 → 표 → 출처
  const d = document.getElementById('drawer'), TABS = { '내역': '<table>…</table>', '출처와 전제': '<p>…</p>' };
  d.innerHTML = `<div style="font-size:18px;font-weight:700;color:var(--main)">현황 › ${name}</div>
    <h2 style="font-size:34px;line-height:1.45;margin:14px 0 24px">(이 항목에서 말할 수 있는 것. 2줄까지)</h2>
    <div class="tabs" style="border-bottom:2px solid var(--rule)">${Object.keys(TABS).map((t, i) => `<button class="${i ? '' : 'on'}">${t}</button>`).join('')}</div>
    <div id="tabBody" style="margin-top:24px;font-size:20px;line-height:1.6">${TABS['내역']}</div>
    <p style="margin-top:28px;font-size:18px;color:var(--note)">출처: ${SRC}</p>`;
  d.querySelectorAll('.tabs button').forEach(b => b.onclick = () => {
    d.querySelectorAll('.tabs button').forEach(x => x.classList.toggle('on', x === b));
    document.getElementById('tabBody').innerHTML = TABS[b.textContent];
  });
  stage.classList.add('open');
}
const close = () => stage.classList.remove('open');
document.getElementById('scrim').onclick = close;
addEventListener('keydown', e => { if (e.key === 'Escape') close(); });
document.getElementById('more').onclick = () => openDrawer(FOCUS);
setTimeout(() => stage.classList.add('built'), 60);   // 조립 시작(막대 → 숫자 → 패널 순으로 지연시켜 두었다)
