# 영화 현상금 사냥 앱 — 제품 요구사항 문서 (PRD)

> "보고 싶었던 영화를, 극장에서 내려가기 전에, 어떻게든 보게 해준다."
> — 종영 임박작을 **수배**하고, 관람 일정을 **추적·검거**하고, **현상금**을 쌓는 영화 사냥 앱.

문서 버전: v0.1 (기획 초안) · 작성일: 2026-06-03 · 상태: 컨셉 확정용 초안

---

## 1. 제품 개요 & 비전

### 1.1 한 줄 정의
사용자가 보고 싶은 영화를 `wanted`로 등록하면, 앱이 극장 상영 데이터를 종합·예측하여
**종영 전에 실제로 관람 가능한 일정(미션)** 을 짜주고, 관람을 인증하면 현상금 포인트를 적립하는 모바일 앱.

### 1.2 메타포 (제품 전체를 관통하는 일관 컨셉)
사용자는 "영화 현상금 사냥꾼"이다. 제품의 모든 용어/UX/게임 요소가 이 메타포 위에서 일관된다.

```
수배(Wanted) → 추적(Track) → 검거(Capture) → 현상금(Bounty)
  보고 싶은     극장 정보       관람 + 인증       난이도 기반
  영화 등록     종합·예측                        포인트 적립
```

### 1.3 차별점 (왜 기존 위시리스트/예매앱과 다른가)
- 넷플릭스 찜·왓챠피디아 등은 **"보고 싶다"를 기록만** 한다. 마감기한도, 실행 계획도 없다.
- CGV·메가박스 등 예매앱은 **"오늘 뭐 보지"** 에 최적화되어 있지, "이번 주 안에 내려가는 OO를 놓치지 마라"는
  관점이 없다.
- 본 제품의 핵심은 **마감기한(종영 D-day) 관리 + 다(多)영화 관람 일정 최적화**. 이것이 제품의 존재 이유다.

### 1.4 핵심 가설
- (가치) 사람들은 "보려고 했는데 어느새 내려가서 못 본" 경험에 충분한 후회/불편을 느낀다.
- (실행) 종영 시점을 예측해 **지금 행동해야 한다**고 콕 집어주면 관람 전환이 일어난다.
- (지속) 현상금/컬렉션이 "놓치지 않고 다 잡아낸다"는 수집 욕구를 자극해 리텐션을 만든다.

## 2. 문제 정의

### 2.1 종영 시점은 어디에도 공개되지 않는다 (가장 큰 문제)
극장 체인(CGV·롯데시네마·메가박스)은 종영일을 발표하지 않는다. 상영 회차가 서서히 줄다가 어느 날 사라진다.
사용자는 "아직 하겠지" 하다가 놓친다. → **종영 시점을 데이터로 예측**하지 못하면 이 앱의 목적 자체가 성립하지 않는다.

### 2.2 핵심 통점은 단관 개봉 독립·예술영화
와이드 릴리즈 블록버스터는 어차피 몇 주씩 걸려 있어 놓치기 어렵다. 진짜 가치가 큰 타겟은
**상영관이 몇 개뿐이고 1~2주 만에 내려가는 독립·예술·영화제 상영작**이다. 여기서 앱의 효용이 극대화된다.

### 2.3 여러 편을 한정된 시간·위치 안에 다 보기 어렵다
보고 싶은 영화가 5편인데 각각 마감기한·상영관·상영시각이 다르고, 사용자의 가용 시간과 동선은 한정적이다.
수동으로 짜기엔 조합이 폭발한다. → **일정 최적화**가 필요하다.

## 5. 기능 요구사항

> 우선순위: **[MVP]** 최초 출시 필수 / **[v1]** 정식판 / **[Later]** 이후 확장

### F1. 영화 카탈로그 수집 **[MVP]** — *(사용자 원안 ① 보완)*
- 상영중 + 개봉예정 목록을 수집·갱신. 권위 데이터는 **KOBIS**, 포스터/시놉시스/평점/감독·배우는 **TMDB·KMDb**로 보강.
- 정렬·필터: 개봉일, 종영 위험도, 장르, 단관/와이드, 영화제 상영 여부.
- *(보완 포인트)* 단순 목록이 아니라 **"종영 위험도" 뱃지**를 목록 단계부터 노출해 행동을 유도.

### F2. Wanted 마킹 + 우선순위·희망 포맷 **[MVP]** — *(사용자 원안 ② 입력부)*
- 영화를 `wanted`로 등록. 사용자 **우선순위(꼭 봐야 함 ~ 여유되면)** 와 **희망 포맷(일반/IMAX/4DX/자막/더빙)** 지정.
- wanted가 곧 일정 최적화 엔진(F4)의 입력 집합이 된다.

### F3. 종영 위험도(D-day) 예측 엔진 **[MVP, 간이] / [v1, 정식]**
- KOBIS **일별 상영횟수·스크린수·좌석판매율 추세**를 추적해 종영 임박도(잔여일)를 산출.
- MVP: 단순 추세(최근 N일 상영횟수 감소율 + 절대 스크린수 임계치) 기반 휴리스틱.
- v1+: 시계열 모델로 고도화. **신뢰구간·근거**("최근 5일 상영횟수 -60%, 잔여 스크린 3개")를 항상 함께 노출.
- 이 출력(예측 종영일 + 신뢰도)이 **F4의 마감기한 입력값**이 된다.

### F4. 관람 일정 최적화 엔진 ★**MVP 심장**★ **[MVP]**
6장에서 상세. 사용자 원안 ②의 "쓰러뜨릴 방법을 찾아준다"를 **정보 종합 → 실행 가능한 최적 일정**으로 격상.

### F5. 알림 & 예매 딥링크 **[MVP]**
- 시간 민감 푸시가 사실상 킬러 기능: *"OO이(가) 주말 지나면 종영 위험. 토 14:00 □□극장 잔여 12석, 지금 예매."*
- 알림에서 체인 예매 페이지로 **딥링크**. (앱 내 예매는 제휴 전까지 외부 연결로 처리)
- 알림 트리거: 위험도 급상승, 미션 보드 임박, 잔여좌석 소진 임박.

### F6. 관람 인증 & 현상금 / 게이미피케이션 **[v1]**
- **인증 수단**(난이도/신뢰도 순): 예매내역 연동 > 티켓/예매내역 사진 OCR > 극장 GPS 체크인(상영 시간대).
- **어뷰징 방지**: 상영 시간대·극장 위치·중복 인증 교차검증, 의심 건 보류/검토.
- **현상금 난이도 티어**: 와이드 릴리즈=하, 인기작=중, 단관/마지막 상영/심야=상. 난이도×우선순위로 포인트 차등.
- **컬렉션/배지**: 감독 전작 제패, 특정 영화제 수상작 컴플리트, 연속 관람 스트릭, 시즌 이벤트.
- **리더보드**: 지역/친구 단위.

### F7. 실패 · 대체 경로 (수배 해제) **[Later]**
- 종영으로 놓친 영화: **OTT 출시·재개봉·특별상영·영화제 재상영** 알림으로 "다른 곳에서 잡기" 제안.
- 메타포 유지: '수배 해제' / '현상금 이월'.

## 6. ★MVP의 심장: 관람 일정 최적화 엔진

### 6.1 문제 정의
> **마감기한 제약 스케줄링(deadline-constrained scheduling) 문제**
> "여러 wanted 영화를, 각자의 예측 종영일 이전에, 사용자의 위치·가용 시간·선호 제약 안에서,
> 가능한 한 많이(그리고 중요한 것 우선) 관람하도록 날짜·극장·회차를 배정한다."

### 6.2 입력 (Inputs)
- **wanted 목록**: 각 항목당 { 예측 종영일(F3), 신뢰도, 사용자 우선순위, 희망 포맷 }
- **상영 시간표 / 잔여좌석**: 인근 극장의 회차별 시각·포맷·잔여좌석 (체인 스크래핑, 7장)
- **사용자 컨텍스트**: 현재/주 활동 위치, 이동 가능 반경·최대 이동시간, 선호 극장
- **가용 시간**: 캘린더 연동으로 얻은 빈 시간 슬롯
- **관람 제약**: 일일 최대 관람 편수, 상영 간 최소 이동/휴식 버퍼

### 6.3 목적함수 (Objective)
- **1순위 — 최대 검거**: 종영 전에 보는 wanted 편수를 최대화하되, `우선순위 × 긴급도(1/잔여일)` 가중합 극대화.
- **2순위 — 비용 최소화**: 총 이동거리/시간, 불필요한 대기 최소화.
- **성향**: 고위험(임박)작 우선 배치(Earliest-Deadline-First), 신뢰도 낮은 예측은 더 보수적으로(빨리) 배치.

### 6.4 알고리즘 (단계적 고도화)
- **MVP — 휴리스틱**: EDF(마감 임박 우선) 정렬 → 각 영화에 대해 [가용 슬롯 ∩ 상영 회차 ∩ 이동 가능] 교집합에서
  실행 가능한 첫 슬롯 배정 → 충돌 시 우선순위로 조정. **더블헤더(하루 2편 연속)** 제안 포함.
- **v1+ — 최적화**: ILP / 제약충족(CP-SAT 등)으로 전역 최적해 탐색. 좌석 매진·일정 변경에 따른 **재계획(re-plan)** 지원.

### 6.5 출력 (Output) — "이번 주 관람 미션 보드"
- 날짜순 미션 카드: { 영화, 날짜·회차, 극장, 포맷, 잔여좌석, 예매 딥링크, "왜 지금"(종영 D-day 근거) }.
- **미달성 위험 경고**: "OO은 가용 일정 내 관람 슬롯이 없음 → 조건 완화(이동시간↑/포맷 변경) 제안" 또는 '수배 해제' 후보.
- 사용자가 슬롯을 수락/거절하면 즉시 재계획.

## 7. 데이터 소스 & 파이프라인

### 7.1 소스별 역할
| 소스 | 역할 | 성격 |
|---|---|---|
| **KOBIS 오픈API** | 박스오피스, 상영정보, 개봉예정작, 일별 상영횟수/스크린수/관객수 | 공식·합법·안정 / 종영예측 근거 |
| **TMDB / KMDb** | 포스터, 시놉시스, 평점, 감독·배우 메타데이터 | 보강용 |
| **극장 체인 스크래핑** (CGV·롯데시네마·메가박스) | 실시간 회차별 시간표·잔여좌석·예매 딥링크 | 일정 최적화 필수 입력 |

### 7.2 파이프라인 개요
```
[수집 워커] KOBIS(일배치) + 체인 스크래퍼(주기) + TMDB/KMDb(메타 캐시)
      ↓ 정규화·매칭(동일 영화 ID 매핑)
[예측 배치] 종영 위험도(D-day) 산출 → ClosurePrediction 갱신
      ↓
[최적화 서비스] 사용자 요청 시 wanted + 컨텍스트로 미션 보드 생성
      ↓
[알림 서비스] 위험도 급변/임박 시 푸시
```

### 7.3 ⚠ 법적 · ToS 리스크와 완화책 (필수 고지)
극장 체인 스크래핑은 **각 사 이용약관 위반 소지, IP 차단, 법적 분쟁(저작권/부정경쟁/전산망법) 리스크**가 있다.
출시 전 법률 검토 필요. 완화책:
- **요청 레이트 제한 + 캐싱**으로 부하 최소화, `robots.txt`·약관 존중.
- **공식 제휴/오픈API 협의를 최우선 경로로** 추진(스크래핑은 임시 폴백 위치).
- 스크래핑 차단·실패 시 **사용자 크라우드소싱**(관객 제보: "이 극장 이 회차 봤다/상영표 첨부") 폴백.
- 개인정보·예매 행위는 사용자 계정/딥링크로 위임, 우리 서버가 대리 예매하지 않음.

## 8. 데이터 모델 (개체 + 핵심 필드)

| 개체 | 핵심 필드 |
|---|---|
| `Movie` | id, 제목, KOBIS코드, TMDB id, 개봉일, 등급, 장르, 단관여부, 영화제태그 |
| `ScreeningSnapshot` | movieId, 날짜, 상영횟수, 스크린수, 관객수, 좌석판매율 *(일별 추세)* |
| `TheaterChain` / `Theater` | 체인, 극장명, 위치(좌표), 보유 포맷 |
| `Showtime` | theaterId, movieId, 시각, 포맷, 잔여좌석, 예매 딥링크 URL |
| `WantedItem` | userId, movieId, 우선순위, 희망포맷, 등록일 |
| `ClosurePrediction` | movieId, 예측종영일, 신뢰도, 근거요약 |
| `ViewingPlan` / `Mission` | userId, 항목들[{movieId, showtimeId, 상태}], 생성시각, 미달성위험 목록 |
| `ViewingProof` | userId, movieId, showtimeId, 인증수단, 검증상태 |
| `Bounty` / `PointLedger` | userId, movieId, 난이도티어, 획득포인트, 사유, 시각 |
| `User` | id, 위치, 이동가능반경, 선호극장/포맷, 캘린더연동, 알림설정 |

*(상세 ERD 다이어그램은 별도 산출 가능 — 필요 시 추가.)*

## 9. 시스템 아키텍처 개요 (문서 수준)

```
[모바일 클라이언트] ──REST/GraphQL──> [백엔드 API]
                                         ├─ 수집 워커 (KOBIS / 체인 스크래퍼 / 메타)
                                         ├─ 예측 배치 (종영 위험도)
                                         ├─ 일정 최적화 서비스 (미션 보드)
                                         ├─ 알림 서비스 (푸시)
                                         └─ DB (영화/상영/사용자/현상금)
[외부] KOBIS API · TMDB/KMDb · 극장 체인 · 푸시(FCM/APNs) · 캘린더(구글/애플)
```
- 수집/예측은 **스케줄러 기반 배치**, 최적화는 **사용자 트리거 온디맨드 + 캐시**.

## 10. 범위: MVP vs 이후

| 구분 | 포함 기능 |
|---|---|
| **MVP** | F1 카탈로그, F2 wanted, **F3 간이 종영예측**, **F4 일정 최적화(휴리스틱)**, F5 알림·딥링크 |
| **v1** | F3 정식 예측, F6 현상금/인증/게이미피케이션, 캘린더 연동 고도화 |
| **Later** | F7 대체 경로, 일정 최적화(ILP/CP), 소셜/그룹 관람, 영화제 연계 이벤트 |

**MVP 성공의 정의:** "일정 최적화로 만든 미션 보드를 따라 사용자가 종영 전에 실제로 관람했다"가 측정 가능할 것.

## 11. 비기능 요구사항
- **개인정보**: 위치·캘린더 접근은 명시적 동의/최소 수집/온디바이스 우선. 위치는 일정 계산에만 사용.
- **데이터 신선도**: 상영 시간표·잔여좌석은 갱신 주기와 "마지막 갱신 시각"을 UI에 노출(딥링크 시 재확인 유도).
- **신뢰도 투명성**: 종영 예측은 항상 신뢰구간/근거와 함께 표시(과신 방지).
- **확장성**: 신규 극장 체인/지역 추가가 수집 어댑터 교체로 가능하도록 설계.
- **성능**: 미션 보드 생성 응답 목표(예: p95 < 3초, 캐시 활용).

## 12. 리스크 & 오픈 이슈
- **스크래핑 합법성/차단** (7.3) — 최우선 법률 검토 + 제휴 추진.
- **종영 예측 정확도** — 초기엔 보수적으로(빨리 보라고) 편향, 데이터 축적 후 보정.
- **인증 어뷰징** — 포인트 가치가 커질수록 우회 시도↑, 교차검증 강화 필요.
- **예매 딥링크 한계** — 잔여좌석/딥링크가 체인별로 안정적이지 않을 수 있음.
- **기존 저장소 정리** — 현재 코드는 무관한 주담대 계산기. 본 제품 착수 시 저장소 분리/정리 방향 결정 필요(본 PRD 범위 밖).

## 13. 성공 지표 (KPI)
- **핵심**: 종영 전 관람 성공률 (wanted 중 종영 전 인증 비율).
- wanted → 관람 전환율, 알림 클릭 → 예매 딥링크 전환율.
- 놓침 방지 건수(예측 임박 알림 후 관람), 미션 보드 수락률.
- 리텐션(주간 활성), 단관/예술영화 관람 비중(차별화 검증).
