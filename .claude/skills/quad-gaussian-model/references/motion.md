# 모션: 걷기 · 회전판 · 보조 뼈 구동 · 다른 뼈대의 모션 가져오기 · 팔 마무리

단계 ⑨ ⑫ ⑬. `template/motion.py`를 고치거나 새 동작을 지을 때, 다른 캐릭터의 모션을 가져올 때(`import_pose.py`),
팔꿈치가 몸통에 박히거나 주먹을 쥐게 해야 할 때(`arms.py`) 읽는다. 영상에서 동작을 가져오는 것은 `mocap.md`.

## 함수의 모양

- `*_rots(skel, phase, …)` → `(rots, root)`: 뼈별 로컬 회전 dict + root 이동. 한계 검사·보조 뼈 구동은 이 단계에서 한다.
- `*_pose(skel, phase, …)` → `(mats, root)`: 뼈별 3×4 행렬 + root. 렌더러(`Renderer.frame(cam, mats, root)`)가 받는 형태.
- `phase`는 0…1의 한 주기. **`pose(1) = pose(0)`** 이어야 loop다(`verify --checks loop`: `seam_position < 1e-5`).

새 동작을 짓는 순서: 관절 각도를 `rig.local_rot(뼈, pitch, yaw, roll)`로 채운 dict → `rig.check_limits(rots)`가 빈 목록인지 확인 →
`motion.drive_helpers(rots)`로 보조 뼈 채움 → `SKEL.world_mats(rots, root_offset=root)`.

## 걷기 loop — `motion.walk_pose(skel, phase, advance)` (달리기 `run_gait_pose`도 같은 틀, `motion.Gait`)

`advance = STRIDE × phase`를 주면 실제로 전진하고, 0이면 제자리(러닝머신) 걷기다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `WALK_PERIOD` / `STRIDE` | 1.0 s / 1.4 m (1.4 m/s, 분당 120걸음) | 한 주기(두 걸음)의 시간 / 발 하나가 가는 거리 |
| `STANCE` | 0.62 | 한 주기 중 발이 땅에 있는 비율 |
| `WALK_NORM` / `RUN_NORM` | (퍼센트, 각도) 표 | 사람의 평균 고관절·무릎·발목 곡선(문헌의 대략값). 뜬 다리와 받친 무릎이 따른다 |
| `PITCH_STRIKE` / `PUSH_PITCH_MAX` | −16° / 70° | 뒤꿈치 착지 때 / 발볼로 밀 때 최대 발 기울기 |
| `WALK_PUSH` | 0.30 | 이 위상부터 뒤꿈치가 "무릎이 사람처럼 굽는" 만큼 들림 |
| `SWING_CLEAR` | 0.012 H | 뜬 발이 곡선보다 더 드는 높이(발끝이 바닥에 닿지 않게) |
| `ZMP_SHIFT`·`ZMP_FROM/TO/EASE` | 0.02 · 0.25/1.3/3 | 균형 풀이의 기준 ZMP 경로(발 위를 뒤꿈치 → 발가락으로) |

"자연스럽게"를 만든 네 가지 — **발을 먼저 정하고, 다리는 사람의 관절 곡선을, 몸은 균형을 따른다.**

1. **디딘 발은 월드에 고정**: ① 뒤꿈치 한 점을 축으로 내려앉고 ② 발바닥 전체로 섰다가 ③ 발볼을 축으로 뒤꿈치가 들린다. 축이 되는 점이 월드에서 고정이라 발이 미끄러질 수 없다. 발의 방향은 `rot_x(pitch)`만 쓰므로 돌 수 없다.
2. **뜬 다리는 사람의 곡선**: 고관절·무릎 곡선을 골반에서부터 이어 붙이고(전진 운동학), 발이 떠날 때의 각도·각속도와 내려앉을 곳에 맞게 **관절 각도로** 고친다(다리가 길이보다 늘어나지 않음). 발은 앞으로는 멈춘 채, 아래로는 조금 내려오며 닿는다.
3. **골반 높이 = 받친 다리의 무릎이 곡선보다 펴지지 않는 높이** 아래의 매끄러운 곡선(이차계획법 `smooth_below`: 답이 하나로 정해짐. 최대 평균만 찾는 선형계획법은 같은 평균의 모양이 여럿이라 실행마다 다른 답을 냈다). 달리기의 체공은 중력만큼 떨어지는 포물선.
   **앞뒤·옆 위치는 균형으로 정한다**(`_balance_loop`): 팔다리까지 넣은 점질량 ZMP가 디딘 발 위를 구르도록 x'' = (y''+g)/y·(x − p)를 한 주기에서 풀고(체공 중에는 앞뒤 속도 유지), 높이와 함께 0.4·0.25배씩 천천히 갱신해 수렴시킨다.
4. 무릎은 2-bone IK(`leg_ik`), 팔은 같은 쪽 다리와 반대로(걷기 어깨 18° 뒤…12° 앞, 달리기 40° 뒤…15° 앞), 가슴은 허리 회전판에서 골반과 반대로, 머리는 목 회전판에서 다시 정면.

주의: 이 틀은 매개변수에 민감하다(발 자리·골반 높이·균형이 서로 얽힘). 하나를 바꾸면 `qc.py walk`(ZMP·튐), `foot_report`, 관절 곡선 그림을 같이 다시 본다.

통과 기준(`verify --checks feet`, `soldier.foot_report`): `stance_slide < 1e-4`, `stance_heading_deg < 1e-4`, `max_reach < 1`, `limit_violations = 0`,
디딤 중 지면 오차 ±0.004 이내, 뜬 발 −0.007 이상(발끝이 발볼로 떠날 때 한두 프레임), 착지 속도 수평 < `body_speed`의 25 %·전체 < 60 %.

## 회전판 데모 — `motion.turn_pose(skel, phase, bend=0)`

제자리에서 허리 yaw = 40°·sin(2π·phase), 목 yaw = 70°·sin(2π·(phase + 0.30)). 위상이 엇갈려 허리와 목이 서로 다른 순간에 끝에 닿는다.
`bend`(도)를 주면 허리 앞뒤 굽힘이 더해져 원판 속 공이 드러난다. 회전판을 고쳤으면 이 클립을 반드시 본다.

## 보조 뼈 구동 — `motion.drive_helpers(rots, phase=0, walk=0, chest_spin=0, head_spin=0, prev=None, dt=1/24)`

걷기 위상을 몰라도 되는 **임의의 자세**용 함수다. `rots`의 pelvis·chest·head·thigh·shin·foot 회전만 읽고 보조 뼈 12개의 회전을 같은 dict에 채운다(약 0.4 ms).

| 보조 뼈 | 구동 | 잰 값 |
|---|---|---|
| 치마 8쪽 | 쪽마다 벨트 밑 경첩에서 **바깥쪽으로만**. 각도 = 그 쪽 아래의 넓적다리·무릎(다리를 따라 놓은 공 12개)이 천에 닿지 않는 최소 각도 | 넓적다리 40° → 앞왼쪽 18°, 80° → 53°, 100° → 85° (최대 125°). 다리 30° 벌림 → 옆쪽 17° |
| cape, capeTip | 가슴의 pitch·roll을 되돌려 수직으로 늘어뜨리고 yaw는 절반만 따라감. 엉덩이·치마 뒤쪽·다리 뒤를 지나도록 필요한 만큼 뒤로 기욺 | 가슴 25° 숙임 → 17°, 발꿈치를 엉덩이까지 차올림 → 33° |
| plume, plumeTip | 고개를 돌리면 반대로 휨 | 최대 ±25° |

- `walk`(0~1)·`phase`: 걸음에 맞춘 작은 흔들림(밑단 0.8°, 망토 6°, 깃털 끄덕임). **0이면 자세만으로 결정**되고, 쉬는 자세에서는 정확히 단위 회전이다.
- `chest_spin`·`head_spin`(도/주기, 주기 1초로 보면 도/초): 망토와 깃털이 도는 쪽에 뒤처진다.
- `prev`·`dt`(관성): 프레임마다 **같은 dict**를 넘기면(처음엔 `{}`) 들린 천이 곧바로 떨어지지 않고 초당 200°(치마)·120°(망토)로 내려온다. 넘기지 않으면 자세만의 함수라 loop가 그대로 loop다.

**부드러운 함수의 조건** — 구동 각도는 두 함수를 거친다.

- `soft_max`: 어느 공이 미는지 바뀌어도 각도가 꺾이지 않게 섞는다. 진짜 최댓값보다 아래로 내려가지 않는다(내려가면 천이 다리에 닿는다).
- `soft_pos(x, eps)`: 매끈한 `max(x, 0)`. **x ≤ 0에서 정확히 0, x ≥ eps에서 정확히 x**, 그 사이는 기울기가 0에서 1로 이어지는 곡선. 0 이하에서 0이 아닌 매끈한 함수를 썼을 때 천이 몸 쪽으로 들어간 적이 있다(테스트 `test_soft_pos_is_zero_below_zero_and_smooth`가 고정). 새 구동 함수도 이 두 조건(0 이하에서 정확히 0, 필요한 값에 못 미치지 않음)을 지킨다.

새 보조 뼈의 구동을 쓸 때의 틀: ① 그 천이 피해야 할 몸의 점들을 공으로 근사(`leg_points`) → ② 조각마다 "닿지 않으려면 필요한 각도" 계산(`gore_needs`, `cape_need`) →
③ 쉬는 자세의 필요량을 빼서 쉬는 자세가 0이 되게 → ④ `soft_pos`와 최대각으로 자름 → ⑤ `rig.rot_axis(경첩 축, 각도)`.

## 달리기 loop — `motion.run_gait_rots(skel, phase, advance=0)`, 가드 숨쉬기 — `motion.guard_idle_rots(base_rots, base_root, phase)`

- 달리기: 걷기와 같은 순서(월드 발 경로 → IK → 골반 높이 설계 → 균형 풀이)로 만든 **체공 있는 달리기**. 3.75 m/s, 한 주기 0.667 s, 보폭 2.5 m, 발마다 디딤 27 %.
  디딤은 거의 평평하게 내려앉아 발가락 경첩으로 굴러 42°에서 떠남, 뜬 발은 뒤꿈치를 차올리며 한 아치로. 골반은 체공에서 포물선(자유낙하의 0.6배), 디딤에서 눌림.
  관절 한계 안, 디딘 발 고정, loop 닫힘. `qc.py run`.
- 가드 숨쉬기: 붙잡은 한 자세 둘레의 loop(숨 한 번, 무릎 3 mm 두 번, 체중 이동). 두 발은 `pin_legs`로 그 자세의 자리·방향에 고정. phase 0이 그 자세 자체.
- `leg_state(rots, root)` / `pin_legs(rots, root, pins)`: 자세의 발목 위치·발 방향·무릎 방향·다리 비틀림을 읽고, 골반이 어떻게 움직였든 발을 그 자리에 다시 놓는다(비틀림 유지).

## 합성 달리기·도약 (옷 시험용)

`motion.run_pose`, `motion.jump_pose`, `motion.big_poses()`는 모션 캡처가 아니라 **관절 범위만 흉내 낸 합성 자세**다(발 접지 없음):
달리기는 넓적다리 앞 80°~뒤 20°·무릎 최대 123°, 도약은 웅크림 → 차오름 → 무릎을 가슴으로(넓적다리 100°, 무릎 125°) → 착지.
치마·망토·소매가 큰 동작에서 어떻게 되는지 재는 데 쓴다(`animate --clips big`, `verify --checks clash`의 run·jump·big 열).
발이 땅에 붙는 달리기·도약은 `synth.py`(합성 캡처)나 실제 모션 캡처 쪽에 있다.

## 다른 뼈대의 모션 가져오기 — `template/import_pose.py` (단계 ⑫)

영상이 아니라 **이미 관절 회전으로 되어 있는 모션**(다른 캐릭터의 뼈대에서 뽑은 자세 열)을 이 뼈대로 옮긴다. 맨몸 마네킹(`--outfit none`)에도 쓴다.

```bash
python template/import_pose.py retarget motion.json -o out/punch --outfit none --model out/fig   # clip.npz + import.json (보고서)
python template/import_pose.py render -o out/punch --model out/fig --views catalog,side --compare --strip 30,44,49,59
```

입력 JSON: `names`(관절 이름, 부모 먼저) · `parent` · `tpose`(모든 회전이 단위 행렬일 때의 관절 위치; 미터, y 위, 정면 +z, 그의 왼쪽 +x, 바닥 y = 0) · `dt` ·
`frames`(프레임마다 `rot` {관절: **로컬** 3×3, 행 순서 9개 수}, `root` [x, y, z], 선택 `stretch`, `place` {R, p}) · 선택 `events` [{t, type: punch | block | hit, name}].
파일의 형식과 순운동학은 `import_pose.py` 맨 위에 적혀 있다.

| 무엇을 | 어떻게 | 고치는 곳 |
|---|---|---|
| 관절 대응 | 우리 뼈 → 원본 관절, 쉬는 자세의 관계(same / axis / parent) | `SOMA` 표 하나. 다른 뼈대면 이 표를 새로 쓴다(`retarget(src, par, table=…)`) |
| 방향 | 뼈마다 대응 관절의 **월드 방향**을 받는다. 원본은 T-포즈, 우리는 팔을 내린 A-포즈라 팔 사슬만 쉬는 자세 차이를 보정 | `corrections` |
| 골반 | 원본 엉덩이 경로 × (고관절 높이의 비) | `hip_scale` |
| 다리 | 베끼지 않는다. **발볼을 원본의 자리(배율 적용)에 놓고** 2-bone IK로 푼다 → 비례가 달라도 발이 미끄러지거나 가라앉지 않는다 | `Params.foot_ik` |
| 관절 한계 | `rig.clamp_rot`으로 자르고 관절·프레임별로 전부 적는다. 위팔은 방향을 지키고 제 축 둘레로만 돌려 넣고, 그 비틀림은 아래팔이 받는다 | `keep_axis` |
| 팔꿈치 · 손 | 아래 "팔 마무리"가 기본으로 걸린다 | `--no-clear-elbows`, `--hand-turn-max`, `--wrist-give`, `--wrist-range default\|human`, `--no-grip` |

- **완료 기준**: `import.json`을 읽는다 — `clamps`(잘린 관절: 못 따라 한 부분의 기록), `measured.feet`(디딤발 미끄러짐), `measured.steps.wrap`(반복했을 때의 튐: 이 도구는 loop로 만들지 않는다),
  `elbows`(아래), `grip`(아래), `--model`을 줬으면 `measured.mesh`(표면끼리 파고든 깊이). 그리고 `compare_<view>.mp4` / `strip_<view>.png`를 **원본 막대 뼈대와 나란히** 본다.
- `render`의 `--views`: `catalog`(원본 카드의 카메라) · `side` · `right` · `front` · `three` · `back` 또는 각도. `--camera fixed`는 카메라를 경로 한가운데 고정(이동과 디딤발이 그대로 보임).
  `--budget`초가 지나면 멈추고 같은 명령으로 이어 그린다. 192px 한 장에 5~13초(60000개 모델, 다른 작업과 CPU를 나눠 쓰면 느린 쪽).
- `--clear-trunk`는 예전 방식(팔 전체를 손까지 통째로 돌림)이다. 장갑이 평균 50° 따라 돌아 기본에서 뺐고 비교용으로만 남겼다.

## 팔 마무리 — `template/arms.py` (단계 ⑬)

어떤 출처의 모션이든 뼈대에 올라온 **뒤에** 거는 두 단계. 자세 열(프레임별 로컬 회전 dict)과 root 를 받아 제자리에서 고친다. `import_pose.py retarget`은 둘 다 기본으로 건다.

```bash
python template/arms.py fix out/mocap/run/clip.npz -o out/mocap/run/clip_arms.npz    # 저장된 클립에(새 파일): --no-clear --no-grip --loop --events ev.json
                                                                                     #   --hand-turn-max 도 --wrist-give 도 --wrist-range default|human
```
```python
report = arms.clear_elbows(frames, roots, fps, loop=False)        # 팔꿈치 빼기 (wrist_range="human": 손목 굴곡·신전 70°)
grip, report = arms.grip_track(frames, roots, fps, events=None)   # (T, 2) 왼손·오른손 grip
arms.apply_grip(frames, grip)
```

### 팔꿈치 빼기 — `arms.clear_elbows`

선으로만 된 뼈대에는 갈비뼈가 없다. 그런 뼈대에서 지은 가드 자세는 뒷손 팔꿈치를 척추 3~5 cm 앞에 두는데, 가슴 두께가 있는 몸에서는 그 자리가 가슴 속이다(`pitfalls.md`).

- 팔을 **어깨–손목을 잇는 선 둘레로** 돌린다(팔의 swivel 각, "pole" 각이라고도 함). 어깨와 손목은 그 선 위라 움직이지 않고 팔꿈치만 원을 그리며 나온다.
- 팔 = 공 12개(`ARM_BALLS`: 위팔 5, 아래팔 7 — **손목까지**), 장애물 = 맨몸의 가슴·골반(아래팔은 머리·목도; `OBSTACLES`). `arm_depth` = 가장 깊이 든 공의 깊이(음수 = 떨어져 있음).
  아래팔 끝 두 공(0.90, 1.00 = 손목)은 재고 보고만 한다(`wrist_end_*`): 어깨–손목 선 위라 swivel 로 움직이지 않으므로 각을 정하는 데 쓰지 않는다(`STEER_UP_TO = 0.80`).
  위팔의 공은 실제보다 가늘다: 늘어뜨린 팔은 원래 옆구리에 닿아 있다(이 기준으로 쉬는 자세 −0.019, 걷기 −0.011 → 건드리지 않음).
- 프레임마다 **여유 `CLEAR_MARGIN` = 0.004 H(7 mm)로 벗어나는 가장 작은 각**(3° 간격 + 이분법, 최대 150°) — 관절 한계 안에서, 장갑을 상한 넘게 돌리지 않고 만들 수 있는 각만. 없으면 만들 수 있는 각 중 가장 얕아지는 각(상한 끝까지).
  그 상한 끝이 이미 여유만큼 빠지면 빠지는 **가장 작은 각**을 다시 찾는다(3° 격자 사이에 있는 경우).
  팔꿈치가 든 프레임이 이어지는 구간은 **한쪽 방향만** 쓴다(팔꿈치가 반대편으로 튀지 않게).
- 시간으로 고르기 `_spread`: 방향마다 따로, 앞뒤 `SMOOTH_S` = 0.05초의 최댓값 → 같은 창의 평균. **필요한 각보다 작아지지 않는다.** 창이 짧은 것은 일부러다 — 필요한 각은 팔이 들어가는 만큼 0에서 자라 원래 연속이고, 창이 길면 스윙이 필요 없는 펀치 동안에도 팔꿈치가 벌어져 있다.
  반대 방향 두 구간 사이는 틈 한가운데에서 0을 지난다(양쪽을 서로 빼면 필요한 각의 절반도 못 받는 프레임이 생겼다 — `pitfalls.md`). 클립 바깥은 0으로 본다.
- **손**: 위팔·아래팔은 함께 돌고(팔꿈치 굽힘 그대로) 손에는 원래의 월드 방향을 다시 준다 → 손목이 반대로 꺾여 장갑이 돌지 않는다. 손목에는 한계가 있어 모자라는 만큼은 손이 돈다.
  걸리는 것은 **신전**(손등 쪽으로 젖히기, 기본 30°; 오른손 −roll)이다 — 옆 꺾기가 아니다. 원투는 젖힘 54.5°까지, `inout@5m`은 36~52.5°를 요구했다(옆 꺾기·뒤집기는 한계에 닿지 않음).
  그래서 장갑은 엄지 축(w) 둘레로 **손바닥 쪽으로** 기운다(손 좌표로 평균 +8.8°·+9.7°, 길이 축 +1°, 옆 꺾기 0°).
  **장갑은 기본 10°까지만 돈다**(`HAND_TURN_MOST = 10`, `--hand-turn-max`). 더 돌아야 빠지는 프레임은 10°가 허락하는 만큼만 돌리고 위팔·팔꿈치가 일부 든 채 둔다 → `hand_cap_limited`에 적힌다.
  "돈 각" = 손의 원래·새 월드 방향 사이의 실제 회전각(geodesic). 손목이 한계를 "넘은 정도"도 같은 각(가장 가까운 허용 회전까지)이다. `wrist_give=도`(`--wrist-give`)면 손목 구슬이 그만큼 한계를 넘어가며 손이 덜 돈다(기본 0 = 한계 우선).
  상한은 **받은 손** 기준이다: 한계 밖으로 들어온 손목은 당겨 넣지 않고 들어온 만큼까지 밖에 둔다(`wrist_in_past_*`; 더 나가지는 않음). 돌리지 않는 프레임은 받은 그대로다. "0°" = 0.001° 이내(`HAND_TURN_TOL`).
- **손목 범위**(`--wrist-range human`, `wrist_range="human"`, `rig.LIMIT_SETS`; 선택, 기본 아님): 손목의 굴곡·신전을 각 70°까지. 가져오기의 모든 자르기와 팔꿈치 빼기가 같이 쓴다.
  잰 값(다섯 클립, 상한 10° 그대로): **장갑 0°, 상한에 막힌 프레임 0, 여유 미달 0**, 위팔/가슴 표면 0.038~0.040, swivel 최대 46~72°;
  대가는 오른손목이 기본 한계(신전 30°) 밖으로 131~156프레임, 최대 57°(원투)~69.8°(`inout@1`) 젖혀지는 것. 프레임 사이 swivel 최대 원투 6.6° → 9.3°. `--hand-turn-max 0`도 같은 결과.
  손목 관절은 ±70°에서도 닫혀 있고(공유 구 < 0), 컬링이 남기는 면은 기본 묶음과 같아 다시 구울 필요가 없었다. 기본으로 할지는 사용자가 그림을 보고 정한다.
- 못 푸는 프레임(곧게 편 팔이 가슴을 가로지름, 상한에 막힘)은 가장 얕아지는 각만 준다. `not_cleared` = **적용한 뒤 잰 깊이로** 여유가 모자란 프레임(`under_margin_after`), `hand_cap_limited` = 그중 장갑 상한 때문인 것. 손목 끝은 이 방법으로 뺄 수 없다(손목을 움직이지 않으므로) → `wrist_end_inside`.

**완료 기준**(보고서 `elbows.L/R`): `wrist_moved_max` ≈ 0, `hand_turned_max` ≤ 상한, 그리고 `inside_after`·`hand_cap_limited`·`not_cleared`·`wrist_end_inside`를 읽고 받아들일지 정한다
(상한에 막힌 프레임은 위팔이 일부 든 채다 — 사용자에게 수치로 알린다. 더 빼야 하면 `--hand-turn-max`를 올릴지, `--wrist-range human`을 쓸지 묻는다).
`--wrist-range human`이면 `rig.check_limits(rots, limit_set="human")`으로 확인한다(기본 묶음으로 재면 손목이 걸린다).
잰 값(복싱 원투·스텝 5개 클립, 맨몸 마네킹, 60 fps, 기본 상한 10°): 뒷손 팔꿈치를 평균 36~42°(최대 46.7°) 돌림, 손목 이동 0, 손이 돈 각 평균 5.2~9.9°(최대 10.0°).
상한에 막힌 프레임 14~123개; 공 기준 몸통 속 프레임 0~75개(최대 +0.022); 표면 기준 위팔/가슴 최대 0.043~0.071(빼기 전 0.078~0.169, 상한 30°였던 이전 기본값 0.040; 쉬는 자세 0.028).
아래팔은 네 클립에서 0이다. `inout@1`은 원본이 손목 자체를 가슴 속에 둔다(138프레임, 손목 공 +0.031): 아래팔 손목 쪽 끝이 표면 기준 0.030,
**손까지 치면 0.0345**(`hand+forearm / chest+pelvis`, 프레임 96, 약 140프레임) 든 채 남는다 — 손목을 움직이지 않는 방법이라 뺄 수 없다.
상한 30°(이전 기본값): 손 평균 7~15°(최대 28.5°)로 모두 빠짐; `--wrist-give 30`이면 손 0°(손목이 한계를 최대 27° 넘음).

### 주먹 — `arms.grip_track`

| 단계 | 규칙 (손마다, 모션 전체를 보고) | 상수 |
|---|---|---|
| reach | 어깨→손목 거리 ÷ 팔 길이(1 = 곧게 폄). 가드 = 모션 전체에서 reach 의 20번째 백분위 | `GUARD_PERCENTILE = 20` |
| 발사 | reach 가 초당 2 팔 길이보다 빠르게 늘어남. 0.3/초보다 빠르게 늘어나는 동안 "나가는 중"(도중 0.10초까지의 멈춤 = 히트스톱은 같은 펀치). 출발점(당겼다 나가는 손은 가드)보다 0.15 넘게 나가야 펀치 | `LAUNCH_SPEED = 2.0` `OUT_SPEED = 0.3` `PAUSE_S = 0.10` `PUNCH_MIN = 0.15` |
| 쥐기 | 손이 **절반 나간 프레임**(원본에 block / hit 이벤트가 있으면 그 접촉 프레임, 둘 중 이른 쪽)에 주먹 완성. 그 5/60초 전(punch 이벤트 = 입력 시각이 더 이르면 그때)부터 쥠 | `FULL_AT = 0.5` `CLOSE_S = 5/60` |
| 유지 | 다 뻗은 시점을 지나, 돌아오는 손이 뻗은 거리의 75 % 지점에 올 때까지 | `HOLD = 0.75` |
| 펴기 | 돌아오는 만큼 펴서 25 % 지점에서 다 펴짐. 도중에 다시 쥐지 않고, 아무리 빨리 돌아와도 0.10초는 걸림 | `OPEN = 0.25` `OPEN_MIN_S = 0.10` |
| 이벤트만 있는 펀치 | 훅처럼 reach 가 거의 안 변하는 펀치: 접촉 프레임에 완성, 0.10초 유지, 0.20초에 걸쳐 폄 | `EVENT_HOLD_S = 0.10` `EVENT_OPEN_S = 0.20` |

- 이벤트에는 어느 손인지가 없다 → punch 와 같은 이름의 block / hit 을 한 쌍으로 묶고, 그 사이에 reach 가 더 늘어난 팔을 고른다.
- **완료 기준**(보고서 `grip.L/R.punches`): 펀치마다 `grip_at_full = 1`(접촉·완성 프레임), `grip_at_peak = 1`, `open_frame`이 있고, 가드 구간의 grip 이 0. 펀치 없는 모션은 `punches = []`.
- 잰 값(원투 `1-2@5m`, 60 fps): 잽 — 입력 0.667 s 에 쥐기 시작, 접촉 0.750 s 에 완성, reach 최대 0.833 s, 0.850 s 부터 펴서 1.117 s 에 다 펴짐.
  크로스 — 0.850 / 0.933 / 1.000 / 1.000 / 1.117 s. 이벤트 없이 모션만으로는 잽은 같고 크로스 완성이 2프레임 늦다(0.967 s).
- 걷기(팔이 거의 편 채 흔들림)·0.67초에 걸친 느린 뻗기는 주먹이 되지 않는다(테스트). `PUNCH_MIN`을 0.10으로 낮췄을 때는 원투에서 어깨가 돌 때 딸려 나가는 가드 손(0.10~0.15)이 펀치로 잡혔다.
- 한계: 가드를 모션 전체의 백분위로 잡으므로 내내 팔을 뻗고 있는 모션에서는 가드가 높다. 이벤트 없는 훅·어퍼컷은 못 잡는다.

## 알려진 한계

- 천은 휘지 않는다. 넓적다리를 100° 들면 그 위의 치마 쪽이 벨트에서 수평으로 뻗어 나온다.
- 뒤꿈치 착지 때 신발이 지면을 최대 1.7 mm(192px에서 0.15픽셀) 파고든다(둥근 뒤꿈치를 한 점 축으로 굴린 근사).
- 넓적다리를 뒤로 20° 뻗은 채 무릎을 125° 접으면 종아리가 뒤쪽 치마 밑단을 4.7 cm 파고든다(달리기에서는 그 조합이 나오지 않아 0).
