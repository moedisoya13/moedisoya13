# /video-article

영상마다 같은 폴더에 두 파일을 남긴다.

| 산출물 | 설명 |
|---|---|
| `<영상이름>.mp3` | 분리한 오디오 (모노 16kHz 64kbps, 1시간 ≈ 27MB) |
| `<영상이름>.html` | 한국어 전문 번역 아티클. 같은 이름의 다른 HTML이 이미 있으면 `<영상이름>.article.html` |

"처리 완료" 판정은 HTML `<head>`의 `<meta name="video-article-source" content="<영상 파일명>">`
표식으로 한다. 이 표식이 있는 HTML이 폴더에 있으면 그 영상은 건너뛴다. 그러니 **HTML은
아티클이 실제로 완성됐을 때(또는 번역할 내용이 없다고 판정했을 때)만 쓴다** — 전사 실패 같은
미완 상태에서 HTML을 쓰면 그 영상은 다음 실행에서 영영 빠진다.

전사와 프레임 추출은 `watch` 스킬의 `whisper.py`·`frames.py`를 재사용한다
(키: `~/.config/watch/.env`, Groq 우선).

## 경로 상수

- `VA` = 이 SKILL.md와 같은 디렉터리의 `scripts/va.py` 절대경로
- Windows에서는 `python3`가 아니라 `python`. `va.py`는 스스로 UTF-8 모드로 재실행하므로
  한글 경로용 환경변수를 따로 붙일 필요는 없다.

## Step 1 — 미처리 목록

사용자가 준 경로(드래그한 `@"..."` 형태면 따옴표 안쪽)를 그대로 넘긴다:

```bash
python "VA" pending "<폴더 또는 영상 경로>"
```

JSON의 `items[].status`:

| status | 뜻 | 할 일 |
|---|---|---|
| `pending` | 처리 대상. `html`·`audio` 출력 경로와 `duration` 포함 | Step 2 |
| `done` | 표식 있는 아티클 존재 | 건너뜀 |
| `no_audio` | 오디오 트랙 없음 | 건너뜀(보고만) |
| `unreadable` | 길이 불명·손상. 다운로드 중일 수 있음 | 건너뜀(보고만, 표식 쓰지 않음 → 다음 실행에 재확인) |

`pending`이 0개면 그렇게 알리고 끝낸다.

`pending` 총 길이가 **3시간을 넘으면** 목록(이름·길이)과 총합을 보여주고 `AskUserQuestion`으로
전체/일부를 한 번 묻는다. Whisper API 한도(Groq 무료 등급은 하루 약 8시간 분량)와 번역
분량이 크게 늘어나는 결정이라 사용자가 정할 일이다. 3시간 이하면 묻지 않고 진행한다.

## Step 2 — 영상별 처리

영상 하나의 흐름은 **전사 → 자막 확인 → 판정 → 번역 → 렌더 → 확인**이다.

- 전사(스크립트 실행, 컨텍스트를 거의 안 씀)는 메인에서 **순차로** 돌린다. 병렬 업로드는
  Whisper rate limit에 걸린다.
- 자막 확인부터 끝까지(프레임 이미지와 번역문으로 컨텍스트를 많이 씀)는 **영상이 2개 이상이거나
  영상 길이가 15분 이상이면** 전사가 끝나는 대로 영상당 서브에이전트 하나에 넘기고(백그라운드),
  메인은 다음 영상 전사로 넘어간다. 긴 강연의 전문 번역은 수만 자라서, 메인에서 하면 이후 영상
  처리와 최종 보고에 쓸 컨텍스트가 바닥난다. 서브에이전트에게는 이 SKILL.md 경로와 transcribe
  JSON을 주고 "Step 2b~2f와 번역 원칙을 따르라"고 지시한다.
- 15분 미만 영상 1개이거나 서브에이전트를 쓸 수 없는 환경이면 직접 한다.

### 2a. 전사

```bash
python "VA" transcribe "<video>"
```

영상 옆에 `<영상이름>.mp3`를 만들고(이미 있으면 재사용) 임시 작업 폴더에
`transcript.txt`(`[HH:MM:SS] 문장` 줄 단위)를 쓴 뒤 JSON을 출력한다:
`work`, `transcript`, `backend`, `duration`, `segments`, `chars_per_min`, `max_gap`,
`subtitle_files`(영상에 내장된 텍스트 자막 트랙을 뽑은 `.srt` 목록, 없으면 빈 목록).

- 실패(키 없음, 429, 네트워크) → 이 영상은 **HTML을 쓰지 않고** 실패로 기록, 다음 영상으로.
  429가 연달아 나면 남은 영상은 멈추고 보고한다(다음 실행 때 자연히 이어진다).
- `max_gap`이 길이의 20%를 넘거나 5분 이상이면 청크 누락·긴 무음일 수 있다. 아티클 meta에 적는다.

### 2b. 화면 자막 확인

자막은 두 번째 원문이다. Whisper가 잘못 들은 고유명사·수치를 바로잡고, 말이 없는 영상에서
내용을 건진다.

- **내장 자막 트랙**: `subtitle_files`가 있으면 그 `.srt`가 화면 자막이다. 소프트 자막은
  프레임에 찍히지 않으므로 프레임 대신 이 파일을 읽는다(텍스트라 싸다).
- **번인 자막**(영상에 박힌 글자·캡션): 먼저 네 장만 떠서 있는지 본다.

  ```bash
  python "VA" frames "<video>" --work "<WORK>" --at 10%,35%,60%,85%
  ```

  출력된 `path`들을 `Read`로 본다. 자막·캡션이 보이면 이 영상을 **번인 자막 있음**으로 기억한다.
  안 보이면 이후 프레임을 뜨지 않는다 — 이미지는 장당 토큰이 크고, 자막 없는 화면은 번역에
  보탤 것이 없다. 자막 위치가 네 장 모두 비어 있어도 짧게 스쳐 가는 자막일 수 있으니, 전사에서
  말과 화면이 어긋나 보이는 구간이 나오면 그때 한두 장 더 떠서 확인한다.

### 2c. 판정 — 번역할 내용이 있는가, 원어는 무엇인가

`transcript.txt` 앞부분(~80줄), JSON 수치, 2b 결과로 판단한다.

- **발화 없음/환각**: 음악·무음 구간에서 Whisper는 그럴듯한 문장을 지어낸다. 다음 중 하나면
  발화가 없는 것으로 본다.
  - 같은 짧은 문장의 반복("Thank you for watching", "시청해주셔서 감사합니다", "♪" 류)
  - `chars_per_min`이 대략 100 미만
  - 세그먼트가 한 자릿수이고 `max_gap`이 길이의 절반을 넘는데, 남은 문장들이 서로 이어지지 않는
    조각이다. 이 경우는 `chars_per_min`이 100을 넘어도 환각이다(짧은 영상에서 조각 몇 개가
    수치를 끌어올린다). 번인 자막이 있다면 그 시점 프레임과 대조해 보면 확실해진다.
- **발화는 없지만 자막이 내용을 전달함**(텍스트 캡션으로 설명하는 데모·홍보 영상, 무성영화 자막 등,
  노래 가사 제외): 자막을 원문으로 삼아 번역한다.
  - 10분 이하 영상: `python "VA" frames "<video>" --work "<WORK>" --every 5`(최대 60장, 넘으면
    균등하게 솎인다)로 떠서 순서대로 읽고, 캡션 흐름을 따라 2d 원칙대로 옮긴다.
    meta의 원어 자리에 `원문: 화면 자막(<언어>)`.
  - 10분 초과: 60장으로는 자막을 대부분 놓치므로 번역하지 않고 스텁으로 처리하되, note에
    "화면 자막이 있는 무발화 영상(길이 N분) — 자막 번역은 별도 지시 필요"라고 적고 최종 보고에도 올린다.
- **발화도 전달할 자막도 없음** → **스텁 아티클**(아래). 표식이 있어야 다음 실행에서 이 영상에
  Whisper를 또 쓰지 않는다.
- **노래/뮤직비디오**: 발화 대부분이 가사면 가사를 옮겨 적거나 번역하지 않는다(저작권 문제이고
  기사로서 가치도 없다). 가사 자막도 마찬가지다. 가사가 아닌 말(인트로 멘트, 인터뷰)이 있으면
  그 부분만 번역하고, 없으면 스텁으로 처리한다.
- **원어**: 전사 텍스트(음성)의 언어로 정한다. 자막 언어, 등장 인물, 파일명으로 정하지 않는다 —
  한국어 자막이 박힌 영상이나 영어권 인물이 나오는 영상도 음성은 다른 언어 더빙일 수 있다.
  원어가 한국어면 번역은 생략하고 아래 원칙 중 구어 정리만 적용한다.
- 그 외: 2d로.

스텁 본문은 한 조각이면 된다:

```html
<div class="note">이 영상에서는 번역할 발화를 찾지 못했습니다(음악/효과음 위주로 판단). 전사 결과: 세그먼트 N개.</div>
```

### 2d. 번역 → 본문 조각

`transcript.txt`를 한 번에 올리지 말고 `Read`의 `offset`/`limit`으로 **약 250줄씩** 읽는다.
구간 하나를 번역할 때마다 `WORK/parts/001.html`, `002.html` … (0 채운 3자리)로 바로 `Write`한다.
이렇게 하면 한 번의 출력이 짧게 유지되고, 중간에 끊겨도 쓴 조각이 남는다. 구간 경계에서 문장이
잘렸으면 다음 조각의 첫 문단에서 이어 쓴다(조각은 그대로 이어붙여진다).

자막 대조는 구간마다 이렇게 한다.

- 내장 자막(`.srt`)이 있으면 같은 시간대 줄을 함께 읽는다.
- 번인 자막이 있으면, 그 구간에서 **확신이 없는 고유명사·수치·용어가 나온 시점만** 골라
  `python "VA" frames "<video>" --work "<WORK>" --at 12:34,15:02` 식으로 떠서 대조한다.
  구간당 0~5장이면 충분하다. 전 구간을 촘촘히 뜨지 않는다.

조각은 `<h2>`/`<h3>`/`<p>`/`<ul>`/`<blockquote>`/`<code>`/`<div class="note">`만 쓰는
HTML 조각이다(`<html>`·`<body>` 없이).

### 2e. 렌더

모든 조각을 쓴 뒤 제목을 정하고 렌더한다.

```bash
python "VA" render "<video>" --work "<WORK>" --out "<pending의 html 경로>" \
  --title "<한국어 제목>" --meta "<메타 한 줄>"
```

- **제목**: 내용에서 뽑은 한국어 명사구. 파일명은 내용과 무관한 경우가 흔하다
  (예: `역사 - X_3.mp4`가 실제로는 영어 AI 강연). 스텁이면 파일명 그대로.
- **meta**: `원본: <파일명> · 길이 <HH:MM:SS> · 원어: <언어> · 전사: Whisper(<backend>)`.
  자막을 대조했으면 `· 자막 대조: 번인/내장`, 자막이 원문이면 원어 자리에 `원문: 화면 자막(<언어>)`,
  전사 누락이 있으면 `· 약 N분 구간 전사 누락`을 붙인다. 제목·meta는 스크립트가 escape하므로
  평문으로 넘긴다.

### 2f. 확인과 정리

1. `python "VA" pending "<video>"` → 그 영상이 `done`으로 나와야 한다.
2. `<영상이름>.mp3`가 폴더에 있는지 확인.
3. 작업 폴더 `WORK`(전사·자막·프레임)를 `rm -rf`로 지운다(전사 텍스트는 남기지 않는 것이 기본).

## 번역 원칙 (핵심)

목표는 **원문 내용을 빠짐없이 옮긴, 읽히는 글**이다. 요약 에세이가 아니다. 논지의 순서,
예시, 수치, 일화, 농담까지 남긴다. 걷어내는 것은 내용이 아니라 구어 전사의 소음이다.

- **소음 제거**: 필러(um, uh, you know, like, so, 그, 이제, 약간), 말더듬, 같은 말 되풀이,
  시작했다 버린 문장, 반복 환각문. 이건 생략이 아니다.
- **문장 재조립**: Whisper 세그먼트 경계는 문장 경계가 아니다. 여러 줄을 이어 온전한 문장으로
  만들고, 생각 단위로 문단을 나눈다(한 문단 3~6문장 감각).
- **문체**: 화자의 말은 1인칭 **합니다체**로 일관되게. 청중에게 말하는 강연 톤을 살리되
  문어로 다듬는다. 소제목은 명사구.
- **소제목**: 주제가 바뀌는 곳마다 `<h2>주제<span class="ts">MM:SS</span></h2>`
  (1시간 이상이면 `H:MM:SS`). 대략 5~10분에 하나. 3분 미만 영상은 소제목 없이 문단만.
- **용어**: 업계에서 굳은 음차는 한국어로(에이전트, 프롬프트, 컨텍스트) 쓰고 첫 등장에만
  괄호로 원어. 제품명·코드·명령어·파일명·API 이름은 원어 그대로, 코드는 `<code>`.
- **화면 자막은 대조용 원문**: 음성 전사가 기준이고 자막은 확인 수단이다.
  - 고유명사 철자·수치·제품명·코드·슬라이드 제목은 **원어 자막**이 있으면 자막 표기를 따른다.
    Whisper보다 정확한 경우가 많다.
  - Whisper가 비었거나 알아듣기 어려운 구간은 같은 시점의 자막으로 메우고, 메웠다는 사실은
    필요할 때 `[자막 참조]`로 표시한다.
  - 영상에 **한국어 번역 자막**이 박혀 있으면 용어 선택만 참고하고 통째로 옮기지 않는다. 자막은
    화면 공간 때문에 줄이거나 의역한 경우가 많고, 이 아티클의 목표는 음성 전문 번역이다.
  - 자막과 음성이 내용상 다르면 음성을 옮기고, 차이가 의미 있으면 `(자막: …)`으로 짧게 병기한다.
- **전사 오류는 고치고, 화자의 말은 고치지 않는다**: 이 둘을 구분한다.
  - 전사 오류 = Whisper가 소리를 잘못 받아 적은 것. 문맥이나 자막으로 명백하면 바로잡는다
    (예: "cloud code" → Claude Code). 확신이 없는 고유명사·수치는 추측으로 확정하지 말고
    들린 대로 쓰되 괄호에 원문 표기를 남긴다.
  - 화자의 말 = 실제로 그렇게 말한 것. "네 가지"라고 해 놓고 다섯을 나열하거나, 앞뒤 수치가
    맞지 않아도 합치거나 정리하지 않는다. 들린 대로 옮기고 헷갈릴 만하면 `(원문대로)`를 붙인다.
    번역자는 논지를 다듬는 편집자가 아니라 옮기는 사람이다.
- **화면 의존 발화**("as you can see here"): 그대로 옮기되, 번인 자막 확인 때 뜬 프레임에
  해당 화면이 있으면 무엇을 가리키는지 괄호로 짧게 보충하고, 없으면 `[화면 참조]`를 붙인다.
- **여러 화자**: Whisper는 화자를 구분하지 않는다. Q&A처럼 교대가 분명할 때만
  `<p><strong>질문</strong> …</p>` / `<p><strong>답변</strong> …</p>`로 나눈다.
- **혼합 언어**: 전부 한국어로 옮기되, 한국어 구간은 정리만 한다.

## 마지막 보고

채팅에는 영상별 결과 표만 남긴다. 열은 파일명, 결과(생성/스텁/건너뜀/실패), 아티클 경로 또는
사유. 아티클 본문을 붙여넣지 않는다. 생성된 HTML이 1~3개면 `SendUserFile(display="render")`로
전달하고, 더 많으면 경로 목록으로 대신한다.

## 실패 모드

| 증상 | 대응 |
|---|---|
| `watch 스킬의 whisper.py/frames.py를 찾을 수 없음` | watch 스킬 설치 필요를 알리고 중단 |
| `Whisper API 키 없음` | `~/.config/watch/.env`에 `GROQ_API_KEY` 설정 안내, 중단 |
| 429 / rate limit 반복 | 남은 영상 중단, HTML 쓰지 않음 → 다음 실행에서 이어짐 |
| `unreadable` | 다운로드 미완료·손상 가능. 보고만 |
| `frames` 출력이 빈 목록 | 영상 스트림 손상·코덱 문제. 자막 대조 없이 진행하고 meta에 적지 않음 |
| 영상 이름을 바꿈 | 표식이 파일명 기준이라 새 영상으로 보고 다시 처리함(의도된 동작) |

## Security & Permissions

- 로컬에서 `ffmpeg`로 **오디오만** 뽑아 `watch` 설정의 Whisper API(Groq 또는 OpenAI)로 보낸다.
  영상 파일 자체와 프레임 이미지는 업로드하지 않는다(프레임은 로컬에서 `Read`로만 본다).
- 쓰기는 영상 폴더의 `<이름>.mp3`, `<이름>.html`(또는 `.article.html`)과 임시 작업 폴더뿐이다.
  같은 이름의 기존 HTML은 덮어쓰지 않는다.
