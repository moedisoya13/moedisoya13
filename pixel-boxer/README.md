# 한밤의 링 (pixel-boxer)

Gaussian splat 픽셀아트 복서 두 명의 시합입니다. 모션을 재생하지 않고 **매 스텝 풀어서** 만들고, 주먹은 **관절의 순차 회전**으로 던집니다.
다리에서 골반, 몸통, 어깨, 팔꿈치로 회전이 넘어가고, 맞았을 때의 결과는 그 순간 글러브의 속도와 그 뒤에 실린 질량으로 계산합니다.

`pixel-duel`(검객)과는 별개의 프로젝트이며 코드는 새로 썼습니다. 형태는 [ink-studio](https://github.com/siliconjungle/shapeshift-labs-ink-studio)로
조각하고, 스켈레톤은 [Kimodo](https://github.com/nv-tlabs/kimodo)의 SOMA 관절 이름을 그대로 씁니다.

## 실행

```sh
npm install        # ink-studio (커밋 고정). 조각·검수·베이크에만 필요
npm run serve      # http://127.0.0.1:8766
npm test           # 시합 규칙 + 모션 규칙
npm run feel       # 모션 측정표
# http://127.0.0.1:8766/catalog.html   풋워크 카탈로그
```

| 조작 | 터치 | 키보드 |
| --- | --- | --- |
| 이동 | 화면 왼쪽을 끌기 (카메라 기준 방향) | WASD, 방향키 |
| 잽 | 잽 버튼 | J |
| 강타 | 강타 버튼. 이어 누르면 스트레이트 → 훅 → 어퍼 | K |
| 가드 | 가드 버튼을 누르고 있기 | L, Shift |
| 대시 | 왼쪽을 빠르게 튕기기 | Space, 방향 두 번 |
| 카운터 | 주먹이 닿기 0.17초 안에 올린 가드 뒤의 주먹 (1.8배) | |

주먹이 맞으면 화면 위에 그 충격량(N·s)이 잠깐 뜹니다. 거리를 바꿔 가며 던져 보면 숫자가 달라집니다.

타이틀에서 **스파링**을 고르면 상대가 가만히 서 있습니다. 모션만 볼 때 씁니다.
주소 옵션: `?spar=1`, `?speed=0.25`(슬로모션), `?rows=160`(아트 격자 세로 픽셀, 기본 216), `?fps=1` 또는 `#fps`, `?seed=3`, `?auto=1`.

## 주먹의 물리: 순차적 관절 회전

주먹은 키프레임이 아닙니다. 버튼은 **운동 사슬**(`src/phys/chain.mjs`)을 시작할 뿐이고, 나머지는 역학이 정합니다.

- 관절 다섯 개가 아래에서 위로 이어집니다: 다리(지면 반력) → 골반 → 몸통 → 어깨 → 팔꿈치.
- 각 관절은 자기 근육이 끝 위치로 당기는 회전체입니다(감쇠비 0.62의 2차계). 언제 움직일지는 정해 주지 않습니다.
  **아래 관절이 최고 속도를 지나는 순간** 다음 관절이 켜집니다. 순서와 타이밍은 그 결과입니다.
- 어깨와 팔꿈치가 사슬의 마지막 두 관절입니다. 주먹의 위치는 "몸이 어깨를 어디까지 실어 왔는가" 위에
  "어깨가 팔을 얼마나 돌렸고 팔꿈치가 얼마나 폈는가"를 얹은 것입니다. 스트레이트는 어깨가 팔을 목표선에 올리고 팔꿈치가 그 선을 따라 폅니다.
  훅은 팔을 굽힌 채 가슴에 고정하고 몸통이 돌리며, 어퍼는 다리와 몸통이 밀어 올립니다.
- 회수는 반대로 손이 먼저, 다리가 나중입니다.

| | 다리 | 골반 | 몸통 | 어깨 | 팔꿈치 | 글러브 뒤의 질량 |
| --- | --- | --- | --- | --- | --- | --- |
| 잽 | 4 / 21 | 21 / 38 | 42 / 58 | 62 / 83 | 88 / 108 | 4.2 kg |
| 스트레이트 | 58 / 75 | 79 / 100 | 104 / 125 | 129 / 146 | 150 / 167 | 5.8 kg |
| 훅 | 92 / 108 | 112 / 133 | 138 / 158 | 163 / 175 | 고정 | 5.6 kg |
| 어퍼 | 96 / 117 | 121 / 142 | 146 / 167 | 171 / 188 | 고정 | 5.3 kg |

(각 칸은 버튼을 누른 뒤 관절이 켜지는 시각 / 최고 속도에 이르는 시각, ms. 스트레이트·훅·어퍼는 앞에 감는 동작이 있습니다.)

### 맞는다는 것

판정 시각도 사거리 표도 없습니다. 규칙이 매 스텝 두 선수의 몸을 풀고, **글러브가 지나간 궤적이 머리에 닿으면** 맞은 것입니다.

- **충격량** `J = 유효질량 × 접근속도 × (1 + 반발 0.3)`. 데미지, 경직, 밀려남, 히트스톱, 피격 반응이 전부 이 값에서 나옵니다.
- **유효질량**은 그 순간의 사슬 상태입니다. 주먹만이면 0.75 kg이고, 팔꿈치가 펴질수록 팔이, 골반·몸통의 회전이 막 도착한 순간에는 몸이 실립니다.
  몸의 회전은 정점을 지나면 0.11초에 걸쳐 빠집니다. 그래서 사슬이 한꺼번에 도착하는 순간에만 온전한 주먹이 됩니다.
- 그 결과로 나오는 것들: 멀면 닿지 않습니다. 너무 가까우면 팔꿈치가 펴지기 전에 닿아 약합니다(스트레이트 1.0 m에서 85 N·s, 0.68 m에서 11 N·s).
  머리를 빼면 피한 것이고, 가드를 올리면 글러브가 실제로 길을 막습니다. 닿기 직전에 올린 가드는 주먹을 튕겨 카운터를 엽니다.

| | 닿기까지 | 글러브 속도 | 질량 | 충격량 |
| --- | --- | --- | --- | --- |
| 잽 | 0.12 s | 7.7 m/s | 4.3 kg | 43 N·s |
| 스트레이트 | 0.15 s | 11.1 m/s | 5.9 kg | 85 N·s |
| 훅 | 0.18 s | 13.1 m/s | 5.8 kg | 98 N·s |
| 어퍼 | 0.18 s | 8.5 m/s | 5.3 kg | 59 N·s |

질량·관절 속도·반발 계수는 문헌의 범위에 들도록 제가 고른 값이고, 실제 선수를 측정해 맞춘 것은 아닙니다.

## 풋워크와 박자

발은 박자를 탑니다. 한 박자는 한 발이 닿는 순간이고, 바운스와 스텝이 하나의 박자 시계(`animator.mjs`)를 씁니다.

- **제자리**: 앞발과 뒷발을 번갈아 2cm쯤 띄웠다 내리며 체중이 앞뒤로 오갑니다(펜듈럼 바운스). 분당 약 187보.
- **이동**: 같은 박자가 그대로 스텝이 되고, 속도가 붙을수록 빨라집니다(서클링에서 분당 약 280보). 출발과 정지에서 박자가 끊기지 않습니다.
- 빠르게 이동할 때는 상하 바운스가 줄어듭니다.

`catalog.html`은 풋워크 카탈로그입니다. 항목마다 실제 시합을 스크립트로 반복 재생하고(`src/footwork.mjs`), 발이 닿을 때마다 등불과 발자국을 남깁니다.
캔버스 하나를 페이지 뒤에 깔고 화면에 보이는 카드만 계산하고 그립니다.

| 항목 | 내용 |
| --- | --- |
| 리듬 바운스 | 제자리 박자 |
| 스텝 인 · 아웃, 가드 전진, 대시 | 직선 |
| 사이드 스텝, 서클링, 따라 돌기 | 좌우와 회전 |
| 스텝 잽, 스텝 원투 | 스텝과 주먹 |

## 나머지 모션

| 파일 | 내용 |
| --- | --- |
| `src/phys/chain.mjs` | 운동 사슬과 유효질량 |
| `src/anim/moves.mjs` | 주먹별 사슬 설정과 각 관절이 자세에 더하는 양. 주먹이 아닌 동작(가드, 대시, KO)은 이징 곡선 |
| `src/anim/animator.mjs` | 층을 더하고 IK로 푸는 곳 |
| `src/rig/solve.mjs` | 스탠스(골반·발·손 위치)를 관절 회전으로 푸는 2-bone IK |
| `src/game/bout.mjs` | 시합. 몸을 풀고, 글러브 궤적과 머리의 충돌을 보고, 충격량을 계산합니다 |

- **가드와 바운스** — 초당 1.75회 바운스, 호흡, 손의 잔움직임. 가만히 서 있는 프레임이 없습니다.
- **스텝** — 발마다 자기 밑의 지면 속도(이동 + 회전)를 따라 딛습니다. 디딘 발은 제자리에 남고, 밀리거나 로프에 막히면 실제로 간 만큼만 걷습니다.
- **동작 사이** — 블렌딩하지 않고, 바뀌는 순간의 차이와 속도를 이어받아 임계감쇠로 풀어 놓습니다.
- **피격** — 충격량이 향한 방향대로 머리와 몸통의 스프링에 나눠 줍니다. 뒤로 가는 충격은 고개를 젖히고, 옆은 돌리고, 위는 턱을 듭니다.
- **팔꿈치** — 방향을 명령하지 않고 직전 방향에서 원하는 방향으로 기울입니다. 한 프레임에 뒤집히지 않습니다.

## 측정

`tools/feel.mjs`는 실제 시합을 스크립트 입력으로 돌리고 캔버스 위 관절 위치를 초당 60번 잽니다. 어기면 실패합니다.

| 규칙 | 기준 | 현재 값 |
| --- | --- | --- |
| 모든 장면의 모든 프레임에서 몸이 움직임 | 100% | 12개 장면 모두 100% |
| 한 프레임 갔다가 다음 프레임에 되돌아오는 튐 | ≤ 3 cm | 최대 2.9 cm |
| 걷는 동안 머리·몸통의 프레임 간 속도 변화 | ≤ 1 cm | 0.7 cm |
| 걸을 때 디딘 발의 미끄러짐 | < 5 mm | 0.8 mm |
| 모든 주먹에서 관절이 아래에서 위로 순서대로 켜지고 정점에 이름 | 순서대로 | 4개 모두 |
| 모든 주먹이 제 거리에서 글러브–머리 접촉으로 맞음 | 맞음 | 4개 모두 |
| 접촉 순간 글러브 속도 | 5 – 16 m/s | 7.7 – 13.1 m/s |
| 잽 < 스트레이트, 너무 가까운 스트레이트 < 절반 | | 43 < 85, 11 < 42.5 |
| 닿지 않는 거리의 잽은 아무것도 못 맞힘 | | 그렇습니다 |

## 검수와 베이크

```sh
npx ink-studio sheet scenes/boxer.js --from 2.4 --to 2.9 --n 10 --zoom 2.2    # 스트레이트를 관절 순서대로
npx ink-studio render scenes/ring.js --w 960 --h 540                          # 링과 구도
npm run bake                                                                   # assets/ (복서 8,657 + 링 23,997 splat)
```

`scenes/boxer.js`는 실제 시합을 돌리며 1.2초마다 동작 하나씩 보여 줍니다: 가드, 잽, 스트레이트, 훅, 어퍼, 전진, 후진, 좌우 이동, 대시, 가드 올리기, 피격 3종, KO.

## 알려진 한계

- 모션캡처가 아닙니다. 사슬 역학과 IK로 만든 움직임이라, 체중 이동의 미묘함은 Kimodo 클립에 못 미칩니다.
- 사슬은 관절마다 자유도 하나인 회전체입니다. 관절 토크 한계, 근육의 힘-속도 관계, 분절 간 상호작용 토크는 넣지 않았습니다. 유효질량은 사슬 상태에서 계산한 근사식입니다. 스켈레톤이 SOMA라서 Kimodo 클립을 넣을 자리는 있습니다(`pixel-duel/tools/kimodo_import.py`와 같은 방식).
- 실제 폰에서의 프레임 시간은 재지 않았습니다. 헤드리스 소프트웨어 GL에서만 돌렸습니다.
- 명암은 가드 자세에서 한 번 구운 것입니다. 위에서 내려오는 조명으로 맞춰 돌아서도 티가 덜 나게 했지만, 다시 계산하지는 않습니다.
- 맞는 곳은 머리뿐입니다(가드 글러브는 막습니다). 바디 공격, 클린치, 라운드와 판정은 없습니다.
