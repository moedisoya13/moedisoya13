# 한밤의 링 (pixel-boxer)

Gaussian splat 픽셀아트 복서 두 명의 시합입니다. 모션을 재생하지 않고 **매 프레임 풀어서** 만듭니다.
가드, 그 위의 바운스, 발밑의 스텝, 주먹, 맞았을 때의 흔들림이 각각 숫자 채널의 층이고, 프레임마다 더해 IK로 풉니다.
멈춰 있는 그림이 없으므로 그 사이를 메울 것도 없고, 화면 주사율만큼 부드럽습니다.

`pixel-duel`(검객)과는 별개의 프로젝트이며 코드는 새로 썼습니다. 형태는 [ink-studio](https://github.com/siliconjungle/shapeshift-labs-ink-studio)로
조각하고, 스켈레톤은 [Kimodo](https://github.com/nv-tlabs/kimodo)의 SOMA 관절 이름을 그대로 씁니다.

## 실행

```sh
npm install        # ink-studio (커밋 고정). 조각·검수·베이크에만 필요
npm run serve      # http://127.0.0.1:8766
npm test           # 시합 규칙 + 모션 규칙
npm run feel       # 모션 측정표
```

| 조작 | 터치 | 키보드 |
| --- | --- | --- |
| 이동 | 화면 왼쪽을 끌기 (카메라 기준 방향) | WASD, 방향키 |
| 잽 | 잽 버튼 | J |
| 강타 | 강타 버튼. 이어 누르면 스트레이트 → 훅 → 어퍼 | K |
| 가드 | 가드 버튼을 누르고 있기 | L, Shift |
| 대시 | 왼쪽을 빠르게 튕기기 | Space, 방향 두 번 |
| 카운터 | 주먹이 닿기 0.17초 안에 올린 가드 뒤의 주먹 (1.8배) | |

타이틀에서 **스파링**을 고르면 상대가 가만히 서 있습니다. 모션만 볼 때 씁니다.
주소 옵션: `?spar=1`, `?speed=0.25`(슬로모션), `?rows=160`(아트 격자 세로 픽셀, 기본 216), `?fps=1` 또는 `#fps`, `?seed=3`, `?auto=1`.

## 모션이 만들어지는 방식

| 파일 | 내용 |
| --- | --- |
| `src/anim/moves.mjs` | 동작 = 채널별 키와 이징 곡선. 판정에 쓰는 수치(닿는 시각, 사거리)가 곡선 옆에 같이 있습니다 |
| `src/anim/animator.mjs` | 층을 더하고 IK로 푸는 곳. 아래 항목이 전부 여기 있습니다 |
| `src/rig/solve.mjs` | 스탠스(골반·발·손 위치)를 관절 회전으로 푸는 2-bone IK |
| `src/game/bout.mjs` | 시합 규칙(순수 로직). 가속·감속하는 이동, 펀치 중 접근, 로프 근처 감속 |

- **가드와 바운스** — 초당 1.75회 바운스, 호흡, 손의 잔움직임. 가만히 서 있는 프레임이 없습니다.
- **스텝** — 발마다 자기 밑의 지면 속도(이동 + 회전)를 따라 딛습니다. 디딘 발은 몸이 가는 속도만큼 정확히 뒤로 밀리고,
  뜬 발은 지면 속도로 떠나 지면 속도로 닿습니다. 밀리거나 로프에 막혀 실제로 간 거리만큼만 걷습니다.
- **주먹** — 손의 경로와 골반·어깨 회전, 뒷발 피벗이 한 곡선 묶음입니다. 맞힐 머리가 있으면 경로 전체가 그 지점에 닿도록 옮겨집니다.
  훅은 팔을 가슴에 고정하고 몸통 회전으로 돌립니다.
- **동작 사이** — 블렌딩하지 않습니다. 바뀌는 순간의 차이와 속도를 그대로 이어받아 임계감쇠로 풀어 놓습니다. 잽 도중에 스트레이트가 나가도 손이 튀지 않습니다.
- **피격** — 머리와 몸통에 스프링 충격을 줍니다. 스트레이트는 고개가 젖혀지고, 훅은 돌아가고, 어퍼는 들립니다.
- **팔꿈치** — 방향을 "명령"하지 않고 직전 방향에서 원하는 방향으로 기울입니다. 손목이 어깨를 지나는 자세에서도 한 프레임에 뒤집히지 않습니다.

## 모션 측정

`tools/feel.mjs`는 실제 규칙을 스크립트 입력으로 돌리고, 페이지와 똑같이 애니메이션해서, 캔버스 위 관절 위치를 초당 60번 잽니다.
이 도구가 먼저 문제를 찾았고(대시·피격 때 발이 튐, 로프 앞 제자리걸음, 콤보 전환 때 손이 튐, 주먹이 한 프레임 늦게 닿음, 팔꿈치 뒤집힘), 그걸 고친 결과가 지금 값입니다.

| 규칙 | 기준 | 현재 값 |
| --- | --- | --- |
| 모든 장면의 모든 프레임에서 몸이 움직임 | 100% | 12개 장면 모두 100% |
| 한 프레임 갔다가 다음 프레임에 되돌아오는 튐 | ≤ 3 cm | 최대 2.6 cm (스트레이트를 당겼다 던지는 팔꿈치) |
| 걷는 동안 머리·몸통의 프레임 간 속도 변화 | ≤ 1 cm | 0.7 cm |
| 판정 시각에 글러브와 목표의 거리 | ≤ 4 cm | 1.7 – 2.7 cm |
| 주먹 최고 속도 | 6 – 16 m/s | 잽 6.8, 스트레이트 10.6, 훅 13.9, 어퍼 11.5 |
| 걸을 때 디딘 발의 미끄러짐 | < 5 mm | 0.8 mm |

## 검수와 베이크

```sh
npx ink-studio sheet scenes/boxer.js --from 2.4 --to 2.9 --n 10 --zoom 2.2    # 스트레이트를 프레임 단위로
npx ink-studio render scenes/ring.js --w 960 --h 540                          # 링과 구도
npm run bake                                                                   # assets/ (복서 8,657 + 링 23,997 splat)
```

`scenes/boxer.js`는 1.2초마다 동작 하나씩: 가드, 잽, 스트레이트, 훅, 어퍼, 전진, 후진, 좌회, 제자리 회전, 대시, 가드 올리기, 피격 3종, 튕겨남, KO, 승리.

## 알려진 한계

- 모션캡처가 아닙니다. 곡선과 IK로 만든 움직임이라, 체중 이동의 미묘함은 Kimodo 클립에 못 미칩니다. 스켈레톤이 SOMA라서 Kimodo 클립을 넣을 자리는 있습니다(`pixel-duel/tools/kimodo_import.py`와 같은 방식).
- 실제 폰에서의 프레임 시간은 재지 않았습니다. 헤드리스 소프트웨어 GL에서만 돌렸습니다.
- 명암은 가드 자세에서 한 번 구운 것입니다. 위에서 내려오는 조명으로 맞춰 돌아서도 티가 덜 나게 했지만, 다시 계산하지는 않습니다.
- 바디 공격, 클린치, 라운드와 판정은 없습니다. 머리를 향한 네 가지 주먹과 KO뿐입니다.
