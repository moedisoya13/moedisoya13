# 미결 카탈로그 기획 (`pending.html`)

작성 2026-11-22. `docs/handoff.md` §6과 `docs/pending.md`의 미결 내역만 모아, 사용자가 **그 화면에서 바로 정할 수 있게** 하는 새 페이지의 기획이다. 모션 카탈로그(`catalog.html`)와는 따로 둔다. 구현하는 쪽은 이 문서만 보고 만든다.

이 문서의 "잰 값"은 기획하면서 저장소 밖(스크래치)에서 값을 바꿔 돌려 본 것이다. 저장소의 코드는 건드리지 않았다. 구현하면서 같은 값을 `tools/pending.mjs`(§3.4)로 다시 재고, 다르면 잰 값을 쓴다.

지켜야 하는 것은 그대로다: 게임의 기본값은 바뀌지 않는다(`npm test` 328, `node tools/feel.mjs` 10, `node tools/audit.mjs` 그대로). audit 한도는 넓히지 않는다. 등급은 코드·문서에서 명/암, **화면에서는 L/D**다.

### 1.1 녹화 비교 카드 (2026-11-23, 5부)

5부의 항목은 비교할 동작이 아직 합쳐지지 않은 작업 폴더에만 있는 것이 많다. 그래서 **녹화한 클립**을 나란히 재생한다.

- 목록 `src/clips.data.mjs`: `ROOTS`(체크아웃마다 화면에 적는 출처: "지금 (게시된 동작)", "N 1차 구현 (합치기 전, 고치는 중)" 등)와 `CLIPS`(id, 체크아웃, 대본 id 또는 만든 장면, 바꾼 것(`change`: 상대 거리, 누름, 고리), 몇 초부터 몇 초, 무엇을 재는지).
- 녹화 `tools/clips.mjs`: 그 체크아웃의 `src`로 대본을 페이지와 같은 방식으로 싸우게 해 프레임마다 두 선수의 관절 22개의 회전·뿌리·늘림·선 자리(int16, base64)와 타격 사건, 같은 실행에서 잰 값, 출처(커밋 또는 폴더, 엔진 파일의 요약값)를 `src/clips/<id>.mjs`와 `src/clips/index.mjs`에 쓴다. 한 명령으로 모두 다시 녹화: `node tools/clips.mjs --write --root m=<M> --root n1=<N> --root u1=<U> --root u2=<U 고침> --root v1=<V> --root vchin=<V, 턱 32°>`(`now`는 이 체크아웃; 폴더를 주지 않은 체크아웃의 클립은 그대로 둔다). `--write` 없이 돌리면 무엇이 녹화될지만 찍고, `--events <id>`는 한 대본의 사건과 잰 값을 찍는다.
- 재생 `src/pending.mjs`: 같은 렌더러와 타격 이펙트로 그린다. 한 묶음의 카드는 시계 하나를 같이 써서 함께 시작하고, 마지막 프레임에서 0.6초 멈췄다가 다시 돈다. ¼ 속도 카드는 녹화된 프레임 사이를 `src/replay.mjs`의 `blend`로 잇고, 그 옆의 제 속도 카드는 네 번 돈다. 카드마다 출처, "녹화"(또는 "녹화 · ¼") 표시, 타격 표지, 잰 값 한 줄, 필요하면 제 카메라(각, 거리, 누구의 몸·머리를 볼지). 클립 파일은 그 줄이 화면 한 장 안으로 들어올 때 불러온다(`import()`; `tools/artifact.mjs`가 그것도 따라가 파일 목록에 넣는다).
- 크기: 클립 29개 1.0 MB(가장 큰 것 72 KB), 페이지 전체 3.7 → 4.7 MB. 첫 그림까지의 시간은 그대로(클립은 뒤에 온다).
- **단계가 합쳐지거나 고침 라운드가 끝나면 다시 녹화한다.** "지금"이 바뀌고, 합쳐진 단계의 비교는 뜻을 잃으므로 그 줄을 빼거나 출처를 고친다.

## 2. 변형 카드와 덮어쓰기 (`src/tune.mjs`)

변형 카드(조정안, 기획 모양)는 게임의 표에서 값 하나둘을 바꿔 돌린 **같은 엔진**이다. 기본값은 건드리지 않는다.

### 2.1 장치

```js
// src/tune.mjs
export function withTune(patches, fn) {          // patches: [[object, key, value], ...]
  const kept = patches.map(([o, k]) => [o, k, Object.prototype.hasOwnProperty.call(o, k), o[k]]);
  for (const [o, k, v] of patches) o[k] = v;
  try { return fn(); }
  finally { for (const [o, k, had, v] of kept.reverse()) had ? (o[k] = v) : delete o[k]; }
}
```

- 이것이 전부다. 게임 코드에 조정 값을 읽는 자리를 새로 만들지 않는다. 바꾸는 것은 이미 있는 표의 칸이다: `MOVES.hookBody.land`(`src/anim/moves.mjs`), `CROSS['4a'].R` 등(`src/anim/skill.mjs`), `TECHNIQUES.parryDown.answer.control`(`src/game/techniques.mjs`, 도구에서만). 셋 다 얼려 있지 않다(확인함).
- **값을 통째로 갈아 끼운다.** 배열·객체의 안을 고치지 않는다. `CROSS`의 `pole`은 다섯 등급이 한 객체를 같이 들고 있어서(`Object.assign`의 얕은 복사), 안을 고치면 다른 등급이 따라 바뀐다. `CROSS['4a'].pole = { L: …, R: … }`처럼 새 객체를 넣는다.
- 카드 정의의 `tune`은 경로로 적는다: `[['MOVES', 'hookBody', 'land', 0.76]]`. `src/pending.mjs`가 `{ MOVES, CROSS, LEVEL, RULES, TECHNIQUES }`에서 풀어 `[object, key, value]`로 만든다(마지막 둘이 key, value이고 그 앞이 길이다).

### 2.2 어디를 감싸는가

변형 카드 한 장에 대해 다음 세 곳을 `withTune(cell.tune, …)`으로 감싼다. 그 밖에서는 표가 기본값이다.

1. `freshBout(entry)` (루프를 새로 시작할 때: 만들면서 표를 읽어 두는 것이 있을 수 있다).
2. 한 스텝: `drive(entry, bout, t, DT)`와 `step(bout, controls, DT)`.
3. 그 카드의 숫자를 재는 코드(충격량, 각도).

한 줄의 카드는 지금처럼 차례로 스텝하므로(자바스크립트는 한 가닥이다) 옆 카드의 스텝은 늘 기본값으로 돈다. 그리기(`draw`)는 자세만 읽으므로 감싸지 않는다.

### 2.3 시험 (`tests/pending.test.mjs`)

1. `withTune`이 던져도 값이 돌아온다. 없던 키는 지워진다.
2. **끼워 돌려도 같다.** 기본 카드(`hookBody@4m`, `crossArm@4a`)를 혼자 한 루프 돌린 사건 목록과, 변형 카드와 한 스텝씩 번갈아 돌린 사건 목록이 같다(`deepEqual`).
3. `src/pending.data.mjs`의 모든 `tune` 경로가 실제로 있는 칸이고, 모든 카드의 `entry`가 카탈로그의 대본 id다. 모든 항목 id가 `^[a-z0-9]+(-[a-z0-9]+)*$`이고 겹치지 않는다. 선택지 id도 항목 안에서 겹치지 않는다. 권장안이 선택지 가운데 하나다.
4. `MOVES.hookBody.land`, `CROSS`가 시험 뒤에도 기본값이다.

## 3. 페이지

### 3.1 배치

- 폭 390 px에서 가로 스크롤이 없다. `.page`의 좌우 여백 16 px, `.grid { grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 8px }`, 모든 칸에 `min-width: 0`, 긴 글은 `overflow-wrap: anywhere`.
- **한 행에 카드 두 장, 폭이 같다.** 비교 쌍은 한 행에 나란히(왼쪽이 기준, 오른쪽이 조정안·기획). 카드가 한 장인 항목은 (가) 참고 이미지가 있으면 [참고 이미지(기획) | 엔진 카드(현재)], (나) 없으면 다음 한 장짜리 항목과 한 행에 둔다(§6의 "짝" 열). 짝이 된 두 항목은 머리와 결정 UI를 각자 갖고, 카드 행만 같이 쓴다: 데스크톱·모바일 모두 [항목 A 머리][항목 B 머리] 다음에 카드 행, 그 아래 [A 결정][B 결정]. 390 px에서는 머리와 결정이 한 열로 쌓이고 카드 행만 두 칸이다.
- 수치 표(기획 / 현재)는 세 열(무엇, 기획, 현재)이고 390 px에서 넘치지 않게 `table-layout: fixed`, 숫자는 `var(--data)` 글꼴.
- 무대(`.stage`)의 비율은 5 / 4. 참고 이미지 칸도 같은 비율의 틀에 `object-fit: cover; object-position: top`으로 넣고, 누르면 원본 크기로 열린다(`<a href>`로 새 탭).
- 등급은 L/D로 보인다: 페이지를 다 쓴 뒤 `shownAsLD(document.body)`. 데이터는 명/암으로 적는다. 저장하는 값(선택지 id)은 ASCII라 바뀌지 않는다.
- 속도 버튼(1×, ½×, ¼×)은 카탈로그 그대로. 발자국 버튼은 없다.

### 3.2 차례 (`<nav id="toc">`)

- 네 부의 제목과 그 아래 **모든 항목의 링크**(`<a href="#item-<id>">`). 항목의 닻은 `id="item-<id>"`, 부의 닻은 `id="part-<n>"`. `scroll-margin-top: 12px`.
- 링크마다 상태 표시 하나: 정하지 않음(빈 테두리), 정함(채운 점 + 고른 선택지의 짧은 이름). 저장이 끝날 때마다 갱신한다.
- 차례 위에 한 줄: "28개 가운데 n개를 정했습니다". 오른쪽 아래에 "차례 ↑"(`.to-toc`).
- 주소에 `#item-…`이 있으면 다 쓴 뒤 그리로 간다(카탈로그와 같다).

### 3.3 항목과 결정 UI

항목 하나의 구조(위에서 아래로):

1. 제목(`<h3>`), 부 안의 번호, id(작게, `var(--data)`).
2. **현재 상태** 한두 줄.
3. **기획 대비 수치** 표.
4. 카드 행(있으면). 카드 아래에는 그 카드가 무엇인지 한 줄과 숫자 줄.
5. **결정** (`<fieldset>`, `<legend>결정</legend>`):
   - 선택지마다 라디오 하나(`name="choice-<id>"`, `value="<option id>"`). 글은 선택지 이름 + 한 줄 결과. 권장안에는 "권장" 표시. 누를 곳의 높이 44 px 이상.
   - "고르지 않음"으로 되돌리는 버튼 하나(선택을 지운다 → `choice: null`).
   - 메모 `<textarea>`(자유 글, 2000자까지, `aria-label="메모"`).
   - **저장 표시**: "저장됨 · 11월 22일 14:03"(저장된 `at`을 그 사람의 현지 시각으로) / "저장 중…" / "저장하지 못했습니다. 다시 시도"(누르면 다시 보냄) / "아직 정하지 않음".
- 저장하는 때: 라디오를 바꾼 즉시, 메모는 입력이 멈추고 0.8초 뒤와 포커스를 잃을 때. 저장 버튼은 따로 두지 않는다.
- 권장안을 미리 골라 두지 않는다. 저장된 것이 없으면 아무것도 고르지 않은 상태로 그린다.
- 키보드: 라디오 묶음은 화살표로 움직이고, 포커스 테두리는 `outline: 2px solid var(--accent)`.

### 3.4 숫자를 재는 도구 (`tools/pending.mjs`)

```sh
node tools/pending.mjs               # 표로 찍는다
node tools/pending.mjs --write       # src/pending.numbers.mjs 를 쓴다
node tools/pending.mjs --matches     # 다운패링의 시합 비율까지(느리다: 시합 36 × 4, 몇 분)
```

- 변형 카드마다: 그 대본을 `withTune`으로 한 루프 돌려 카드 글에 들어가는 숫자를 낸다(리버 훅: 충격량·닿기까지·접촉 속도는 `src/measure.mjs`의 `rung('hookBody@4m')`을 그대로 쓴다; 크로스암: §6.6의 재는 법).
- `--matches`: §5.7의 다운패링 비율.
- 페이지는 `src/pending.numbers.mjs`의 값을 카드의 **기대값**으로 적고, 도는 카드의 실제 값(사건의 `e.J`)을 그 옆에 살아 있는 숫자로 적는다. 둘이 다르면 구현이 틀린 것이다.

| 변형 나 (카드에 쓰는 것) | `[-0.049, -0.056, -0.037, 0.08]` | `{ L: [1, -0.7, 0.4], R: [-0.089, -1, 0.041] }` | **−10** |

  `tune`으로는 `[['CROSS', '4a', 'R', […]], ['CROSS', '4a', 'pole', {…}], ['CROSS', '4a', 'lean', -10]]`. 값은 500번의 무작위 탐색(뒷 글러브가 머리에서 17.5~23 cm, 5~13 cm 아래, 어깨 표 위반 0을 지키며 기울기를 가장 작게)에서 나온 것이다. **기획의 15°에는 이 손잡이들로 닿지 못했다**(`lean`을 −10 아래로, `close`·`knee`까지 푸는 탐색은 하지 않았다).
- **확인하지 못한 것.** 변형 나로 선 가드가 (1) 같은 스트레이트를 여전히 막는지, (2) audit를 지나는지, (3) §4A.10의 다른 시험(가슴이 9° 이상 닫힘, 앞어깨 3 cm, 4암의 앞팔이 5암보다 4 cm 높음)을 지키는지. `lean`이 바뀌면 머리 높이와 앞팔 높이가 같이 바뀐다(표의 앞 글러브 0.94 → 1.01 m). 구현할 때 `tools/pending.mjs`가 변형 카드의 결과(막음 / 명중, 막은 곳)와 audit 위반 수를 같이 찍고, 카드의 글에 그대로 적는다(맞으면 "명중"이라고 보인다. 감추지 않는다).
- 카드: 참고 이미지 `docs/ref/cross-arm-guard.jpg`를 항목 머리 아래 한 폭으로(이미지 검색 화면이라 세로로 길다: 높이 240 px로 자르고 누르면 원본), 그 아래 한 행 [`crossArm@4a` 현재 | `crossArm@4a` 변형 나]. `view`는 둘 다 `{ yaw: 0.4, pitch: 0.26 }`, 한 시계. 카드의 숫자: 뒷팔 아래팔의 기울기 °(가드가 올라와 있는 동안의 평균. 재는 법: `fk(a.pose)`의 `RightForeArm`에서 글러브 가운데(손에서 아래팔 방향으로 7.5 cm)까지의 벡터와 수직의 각; `tests/show.test.mjs`의 `shape()`와 같은 틀), 블록 충격량, 막은 곳.
- 선택지:
  - `accept` 지금 모양을 둔다(45~50°).
  - `upright` 변형 나를 4암에 넣고 같은 방식으로 다섯 등급의 값을 찾는다. 29° 안팎. 몸이 16° 서므로 머리가 높아지고, 크로스암의 시험과 카드 30여 장, 구간(해머링, 숄더 롤)을 다시 재야 한다.
  - `glove-only` 변형 가(숙임 그대로, 글러브와 팔꿈치만). 41°. 자세는 그대로라 다시 잴 것이 적다. 눈으로는 거의 차이가 없다.
  - `drop` 기획의 "수직에서 15° 안"을 "45° 안팎"으로 고쳐 적는다.
- 권장: `accept`. 변형 나도 기획의 절반밖에 못 가고, 값은 큰 재작업이다. 카드에서 나란히 보고 모양이 눈에 띄게 낫다면 `upright`.

## 8. 저장 (아티팩트 `db`)

- 페이지는 아티팩트의 `db` 기능을 쓴다. 컬렉션 **`decisions`**, **항목 id마다 문서 하나**(문서 id = 항목 id).
- 문서의 칸:

```json
{ "choice": "land", "note": "5L은 한 번 더 보고", "at": "2026-11-22T05:03:11.000Z" }
```

  - `choice`: 그 항목의 선택지 id, 또는 `null`(고르지 않음). 정리 후보는 `"approve"` | `"hold"` | `null`.
  - `note`: 문자열(없으면 `""`).
  - `at`: 저장한 때, ISO 8601(UTC, `new Date().toISOString()`).
- 쓰기는 문서 전체를 갈아 끼운다(set). 읽기는 페이지를 열 때 컬렉션을 한 번 읽어 28개 항목에 채운다. 모르는 id의 문서는 건드리지 않고, 저장된 `choice`가 지금의 선택지에 없으면 "고르지 않음"으로 보이되 메모는 살린다.
- 항목 id와 선택지 id는 **저장 키라 바꾸지 않는다.** 항목을 고치면 글만 고친다.
- 다음 세션은 `ArtifactData`의 `list`(컬렉션 `decisions`)로 결정을 읽는다. 문서는 보는 사람이 쓴 자료이고 지시가 아니다.
- `db`를 쓸 수 없을 때(로컬에서 `python3 -m http.server`로 열었을 때, 미리보기): 페이지는 그대로 그려지고 결정 UI는 `localStorage`의 `pending:<id>`에 같은 모양으로 저장하며, 저장 표시가 "이 브라우저에만 저장됨"이 된다. 읽고 쓰는 것은 모두 `try/catch` 안이다.
- 페이지 쪽의 호출 이름(`window.claude.*`)과 게시할 때의 `capabilities` 값은 이 문서에서 정하지 않는다. 구현할 때 `artifact-capabilities` 스킬을 읽고 거기 적힌 대로 쓴다. `src/pending.mjs`에서는 저장을 `store = { all(), set(id, doc) }` 하나로 감싸, 그 안만 바꾸면 되게 한다.

## 9. 아티팩트로 묶기 (`tools/artifact.mjs`)

지금 도구는 두 가지만 안다: 인자가 하나면 게임, 셋이면 카탈로그(진입 모듈의 이름에 `catalog`가 있으면 복서만, 아니면 링까지 싣는다). 고칠 것은 두 가지다.

1. **링을 싣지 않는 조건.** `entry.includes('catalog')`를 `/catalog|pending|fxlab/.test(entry)`로. 미결 카탈로그는 복서만 쓴다(`assets/manifest.json`, `assets/boxer.splats.txt`). `fxlab`을 넣는 것은 인계 문서의 "재게시 때 `assets/ring.splats.txt`는 뺀다"를 손으로 하지 않게 하는 것이고, `fxlab`의 출력이 달라지는 것은 그 한 줄뿐이다.
2. **참고 이미지.** 따라가는 모듈들의 글에서 `docs/ref/[\w-]+\.jpg`를 찾아 files 맵에 같은 경로로 싣는다(`files['docs/ref/wave.jpg'] = 'docs/ref/wave.jpg'`). 미결 카탈로그는 일곱 장 모두 쓴다(`down-parry-counter.jpg`는 링크로). 다른 페이지는 이 글이 없으므로 맵이 그대로다. 이미지의 경로는 `src/pending.data.mjs`에 `'docs/ref/…'` 문자열로 적고, 페이지의 `<img src>`도 그 값이다(페이지가 저장소 뿌리에서 열리므로 로컬과 아티팩트에서 같은 경로다).

게시:

```sh
node tools/artifact.mjs pending.html src/pending.mjs <out.html> > <files.json>
```

그 다음 `root`를 `pixel-boxer`로, files 맵 그대로, `db` 기능을 선언해 publish한다. 처음 게시이므로 새 주소가 생긴다: `docs/handoff.md` §3의 표에 한 줄 더한다. 모션 카탈로그와 이펙트 시안의 아티팩트는 건드리지 않는다.

도구가 따라가는 것은 `from '…'`뿐이다. `src/pending.mjs`가 부르는 모듈(`pending.data.mjs`, `pending.numbers.mjs`, `tune.mjs`, 게임과 렌더러)은 모두 정적 `import`로 둔다.
