## 1. 허리 (D2)

### 1.1 어디에 두는가

- 뼈대(`src/rig/skeleton.mjs`)의 척추는 `Hips`(0.95 m) → `Spine1`(1.05) → `Spine2`(1.17) → `Chest`(1.29)다. 지금 몸통을 만드는 `animator.mjs`의 `trunk(c, gaze)`는 `Hips`에 `yaw`(몸 전체), `Spine2`에 `twist × 0.4`, `Chest`에 `twist × 0.6`을 주고 **`Spine1`에는 아무것도 주지 않는다.** 그 빈 관절이 허리 원판이다.
- 새 채널 **`waist`**(°, 왼쪽으로 도는 쪽이 +). `moves.mjs`의 `CHANNELS`에 `twist` 다음에 넣고, `trunk()`가 `Spine1: [0, waist, 0]`을 낸다. `headOf`·`chestOf`는 이미 `Spine1`을 지나므로 머리, 가슴에 잠긴 손(`lc`/`rc`), 어깨가 허리를 따라 돈다.
- 세 축의 뜻: `yaw` = 골반(다리와 엉덩이가 돌린다), `waist` = 허리(골반 위의 벨트·배가 돈다. `boxer.mjs`의 `Spine1` 튜브가 그 부분이라 눈에 보인다), `twist` = 가슴(허리 위의 흉곽과 어깨). 캔버스 기준 가슴의 방향 = `GUARD.yaw + yaw + waist + GUARD.twist + twist`.
- **한계(풀이 쪽, `animator.mjs`).** `WAIST = { knee: 16, most: 22 }`(16° 넘으면 덜 가고 22°를 넘지 않는다. `soft()` 그대로). 척추 전체의 비틀림은 지금의 `TWIST = { knee: 34, most: 42 }`가 **허리 + 가슴의 합**에 걸린다: `w = soft(c.waist, WAIST)`, `twist = soft(GUARD.twist + c.twist + w, TWIST) − w`(합이 넘치면 가슴이 먼저 양보한다). 시선의 `look`은 `c.yaw + w + twist − GUARD.twist`로 읽는다.
- 숙임·옆굽힘·젖힘은 지금처럼 `lean`/`side`가 `Hips` 0.4, `Spine2` 0.3, `Chest` 0.3으로 나눈다. 허리에 따로 굽힘 채널은 두지 않는다("허리로 스웨이"는 §3.2 N09: 있는 채널 `tip`으로 골반을 세운다).
- 손댈 곳: `moves.mjs`(`CHANNELS`, 주석), `animator.mjs`(`trunk`, `ZERO`/`REST`/`CHEST`는 자동), `evade.mjs`(`GROUP.waist = 'trunk'`, `SIDED`에 `waist`), `rig/solve.mjs`(바꿀 것 없음: `SPINE`에 `Spine1`이 있다), `phys/fall.mjs`(다운이 시작할 때의 자세에 `Spine1` 회전이 실려 가는지 확인: 227~230행이 `Spine1`을 `Spine2`에서 읽는다. 허리가 15° 돈 프레임에서 다운을 시작해 첫 프레임에 어떤 관절도 3 cm 넘게 튀지 않아야 한다), `game/trunk.mjs`(부위의 각 `a`는 지금처럼 가슴의 정면 기준. 바꾸지 않는다).

### 1.2 사슬에 넣는 법 (`src/phys/chain.mjs`)

- `LINKS = ['drive', 'hips', 'trunk', 'shoulder', 'elbow', 'waist']`. **번호 5로 끝에 붙인다**(0~4의 번호를 쓰는 곳이 `animator.mjs`·`bout.mjs`·`measure.mjs`·시험에 많다: `chain.q[3]`, `q[4]`, `on[2]` 등). 보여 줄 때의 순서는 따로 `ORDER = ['drive', 'hips', 'waist', 'trunk', 'shoulder', 'elbow']`를 내보낸다.
- **발사 순서: 가지.** `NATURAL = [[0], { 0: [1], 1: [5, 2], 2: [3], 3: [4], 4: [], 5: [] }]`. 골반이 넘겨줄 때 허리와 가슴이 **같이** 켜지고, 허리는 아무에게도 넘기지 않는다. 허리의 근육이 가슴보다 빠르므로(아래 `rate`) 최고 속도의 순서는 골반 → 허리 → 가슴 → 어깨 → 팔꿈치가 된다.
  한 줄로 잇지 않는(골반 → 허리 → 가슴) 이유: 넘겨주기가 하나 늘면 모든 주먹이 약 16 ms(감쇠 0.62, 70 rad/s의 회전체가 최고 속도에 이르는 시간) 늦어져 닿는 시각, 회피 구간, 카운터 시각이 전부 한 프레임씩 밀린다. 가지로 두면 기존 다섯 관절의 발사 시각은 한 스텝도 달라지지 않는다.
- 주먹마다 `move.chain.waist = { rate (rad/s), turn (°), from: 'hips' | 'drive', damp? }`와 `move.links.waist = { waist: … }`, 감기에 `move.coil.waist`. **`chain.waist`가 없는 주먹은 허리 관절이 `skip`에 든 것과 같다**(켜지지 않고 `q[5]`는 0). `from: 'drive'`는 다리가 넘겨줄 때 골반과 같이 켜진다(숏 훅과 플리커: §3.3).
- 배열: `rate[5]`는 `chain.waist.rate`, `RECOVER`에 `24`, `RECOVER_LAG`에 `0.04`(가슴 0.03 다음, 골반 0.045 앞에 돌아온다), `damp`·`early`·`lag`는 `each()`가 채우고, `amp[5]`는 적지 않으면 **그 등급의 `amp[2]`(가슴)** 다. 등급표의 순서 그래프(`ARM_FIRST` 등)에는 "2를 켜는 목록에 5도 넣는다"는 규칙을 `createChain`에서 한 번 적용한다. "마지막 관절"(`last`)을 고를 때 허리는 빼놓는다.
- **유효질량(`effectiveMass`).** 몸통의 몫을 새로 더하지 않고 **나눈다.** `T = |chain.turn[1]|`(허리 + 가슴의 합, 지금 값 그대로 둔다), `W = |links.waist.waist|`, `share = W / T`일 때 지금의 `trunk = behind(2) × …` 자리에 `(behind(2) × (1 − share) + behind(5) × share) × min(1, T × amp / 30)`. 두 회전이 같이 신선하면 지금과 같은 질량이고, 허리가 먼저 도착해 먼저 빠지는 만큼만 다르다. `share = 0`이면 식이 지금과 같다.
- **X-팩터(`form.sep`).** 지금 `c.twist −= sg × sep × … × 4 × hipsQ × (1 − hipsQ)`(골반이 도는 동안 어깨가 뒤에 남는다)를, 허리가 있는 주먹에서는 `c.waist`에서 뺀다. 양은 같다. 남는 것이 가슴이 아니라 허리라 벨트가 골반 뒤에 처졌다가 따라붙는 것이 보인다. `sep`은 1·2단계 0, 3단계 3, 4단계 7, 5단계 11이라 이것이 등급별 허리의 "분리"다: 1·2단계는 골반과 한 덩어리로 돌고, 올라갈수록 따로 논다.
- **훅의 쓸어 치는 길(`animator.mjs`의 `sweep`, 1927행 언저리의 `still`).** 아직 남은 회전에 `links.waist.waist × amp[5] × (1 − q[5])`를 더한다.
- `preload`(회피 끝에서 던지는 주먹)와 `tools/audit.mjs --turning`, `src/measure.mjs`에 허리 열을 더한다("허리(골반 위)" °/s).

- `chain.turn`(유효질량이 읽는 `[골반, 몸통]`)은 그대로 둔다. 감기의 `coil.twist`는 그대로 두고(팔을 세우는 것), §3.3의 세 주먹만 `coil.waist`를 갖는다.

## 2. 타격 이펙트 (D3, D4)

지금: `main.mjs` `react()`, `catalog.mjs` 626행, `pending.mjs` 545행, `fxlab.mjs`의 "지금" 카드가 같은 두 줄을 따로 갖고 있다: `fx.sparks(e.at, round(5 + 12k), [38, 39, 40, 41], 2.5 + 3k, e.dir)`와 `fx.sparks(e.at, round(3 + 8k), [41, 41, 25], 2.5 + 2k, e.dir)`(`k = min(1.6, J / 85)`), 그리고 맞은 선수의 흰 번쩍임(`bout.mjs` 1667행 `other.flash = 0.07`, 렌더러의 `u_flash`).

### 2.1 한 곳에 모은다: `src/render/blow.mjs` (새 파일)

- `exitOf(part, at, vec)` → 입자의 시작점(월드). `part`는 머리면 `{ at: 머리 가운데, r }`, 몸통이면 사건의 `e.trunk`(`{ at: 허리, to: 가슴, r: 0.13 }`).
- `blow(fxOfStruck, e, struck)` → 색 입자를 뿌리고 뿌린 수를 돌려준다. 네 곳이 이것을 부른다.
- `rippleOf(e, struck)` → 파문 하나 `{ joint, off, age: 0, strength, last, sway }`, `rippleRow(ripple, struck, set)` → 렌더러 층의 `wave: [x, y, z, front, width, strength, sway]`.
- 상수 `FX = { head: 0.115, out: 0.01, body: 0.6, ripple: { speed: 3, last: 0.4, width: 0.14, sway: 0.034, ref: 60, down: { last: 0.55, sway: 1.3 } } }`.

### 2.2 시작점: 타격선이 몸을 빠져나가는 곳

`o = e.at`(글러브가 닿은 점), `d = e.vec`(닿는 순간 글러브가 가던 방향, 단위 벡터. `bout.mjs`가 이미 준다).

- **머리(공, 가운데 `c = struck.points.head`, `r = FX.head`).** `m = o + d × ((c − o)·d)`(타격선이 가운데에 가장 가까운 점), `h = min(|m − c|, r)`, 시작점 `= c + (m − c) × (h / |m − c|) + d × √(r² − h²) + d × FX.out`. 선이 공을 지나면 반대쪽으로 나오는 점이고, 스치는 선(`|m − c| ≥ r`)이면 선이 스치는 쪽의 가장자리다. `|m − c|`가 0이면 `c + d × r`.
- **몸통(캡슐, `e.trunk`).** 같은 식을 쓰되 `c`를 "척추 선분 위에서 타격선에 가장 가까운 점"으로 잡는다. 리버 훅이면 왼쪽 등·옆구리 쪽으로 나온다.
- 팔꿈치(`e.part === 'elbow'`)가 머리에 닿은 것도 머리의 식 그대로다.
- 시험이 보는 것: 시작점이 부위 표면에서 1 cm ± 1 mm 밖이고, `(시작점 − c)·d ≥ 0`(늘 나가는 쪽 반구)다.

### 2.3 입자: 지금 것 그대로, 방향만 타격선

- 수, 색, 속도, 중력(−13), 끌림(3), 수명, 굵기: **지금 두 줄 그대로.** 몸통에 맞은 것은 수에 `FX.body`(0.6)를 곱한다(지금 렌더러 쪽에 준비된 값).
- 방향: 지금은 접촉면의 수평 방향 `e.dir`을 속도에 0.7배로 더한다. 이것을 `e.vec`의 수평 성분으로 바꾸고, 위아래 성분도 같은 0.7배로 더한다(`sparks(at, n, colours, speed, dir)`의 `dir`이 `[x, z, y]` 세 번째 값을 받게 한다). 어퍼컷이면 정수리 쪽에서 위로, 훅이면 반대쪽 뺨에서 훅이 가던 쪽으로 나간다. 퍼짐(지금의 무작위 부채)은 그대로다.
- **맞은 사람 위에는 그리지 않는다.** 입자를 선수마다 따로 둔 `fx`(`fxlab.mjs`의 `sprays`와 같은 틀: 선수마다 `createFx` 하나, 메시 하나)에 넣고, 층을 `outside: 맞은 선수의 실루엣 번호`로 그린다(선수 층에는 `silhouette: 1 | 2`). 반대쪽 면에서 시작한 입자가 몸을 뚫고 보이지 않고, 윤곽에서 처음 나타난다. 렌더러(`renderer.mjs`)의 `silhouette`/`outside`는 이미 있다.
- 막음(`block`)과 패리(`parry`)의 불꽃은 **닿은 점 그대로** 둔다(글러브와 글러브가 만나는 것이라 "맞은 몸"이 없다).
- 관성 땀(`fx.sweat`), 그늘면 분사(`fx.spray`)는 쓰지 않는다. 코드는 정리 승인 전까지 둔다.

### 2.4 파문: 흰 번쩍임 대신

값은 시안 A(`fxlab.mjs`의 `base`)에서 출발한다: 앞머리의 속도 **3 m/s**, 길이 **0.40 s**, 폭 **14 cm**, 흔들림 **3.4 cm**. 세기 `= min(1, J / 60) × (1 − age / last)^1.2`. 빛은 없다(몸의 그림이 좌우로 일렁일 뿐이다).

- **시작점은 닿은 점**이고, 맞은 부위에 붙어 따라간다: 머리에 맞았으면 `off = e.at − 머리 가운데`를 기억해 매 프레임 `머리 가운데 + off`, 몸통이면 `Spine2`의 자리 기준으로 같은 방식. 맞은 뒤 몸이 밀려나거나 접혀도 파문의 중심이 그 자리에 있다.
- **머리 포함.** 지금 셰이더(`renderer.mjs` 47~52행)는 닿은 점 둘레 6~30 cm를 죽여 둔다(`smoothstep(0.06, 0.3, length(from))`: "머리는 제 반동이 있다"). 이것을 `smoothstep(0.02, 0.10, …)`으로 줄여 머리도 일렁이게 한다. 나머지 식(화면 평면에서 세로로 주로 퍼지는 타원 `from.x × 0.35`, 가로로만 옮기는 변위, 파장 3.2 × 폭)은 그대로다.
- 3 m/s × 0.40 s = 1.2 m: 턱(1.5 m)에서 시작하면 0.17 s에 허리, 0.4 s에 발목 언저리까지 간다. 몸통(1.1 m)에서 시작하면 0.16 s에 머리, 0.37 s에 발.
- **다운(`e.down`)과 실신.** 같은 파문을 길이 0.55 s, 흔들림 1.3배로. 넘어지는 몸을 따라가며 끝까지 간다. 리버 다운(0.4 s 늦게 꿇는 것)은 맞은 순간의 파문 하나뿐이다.
- 스침(`graze`), 막음, 패리에는 파문이 없다. 한 선수에 파문은 하나다(셰이더의 값이 층마다 하나): 파문 중에 또 맞으면 새것으로 바뀐다.
- 화면 흔들림(`shake`)은 그대로 둔다.

### 2.4A 양과 굵기는 데미지에 비례 (사용자 지시, 2026-11-22, J 뒤에 더함)

입자의 **수와 굵기**, 파문의 **흔들림과 폭**이 그 주먹이 깎은 체력(사건의 `e.damage`)에 비례한다. `q = e.damage / FX.ref`, `FX.ref = 3`(프로의 스트레이트 85 N·s가 보통 턱에서 깎는 체력), `q`는 `FX.most = 2.2`까지. 입자 `17q + 11q`개(종류마다 적어도 1개), 굵기 `0.024 m × q`(가장 얇게 0.010), 파문의 세기 `q`, 폭 `0.14 m × q`(가장 좁게 0.06). 속도·색·수명은 그대로(속도의 `k`는 `min(1.6, max(q, J/85))`). 카운터의 배율과 몸통의 몫은 데미지에 들어 있으므로 `blow()`의 `gain`과 `FX.body`는 없앴다. 위 §2.3·§2.4의 "수는 그대로", "세기 `min(1, J/60)`"는 이것으로 바뀌었다.

**더한 지시(2026-11-23):** 입자의 **수명**도 데미지에 비례하되 전체적으로 10% 짧게: 수명 = 전의 `0.16 + 0.22·rnd` 초 × `0.95 × max(0.4, q)`(`FX.motes.life` 0.95, `short` 0.4; 처음 10%에서 사용자 지시로 5%로). 입자의 **속도**는 모두 5% 빠르게(`FX.motes.pace` 1.05, 퍼짐의 띄움 1.4 m/s까지 속도 벡터 전체에). 막음·패리의 불꽃(`met`)은 그대로.

### 2.4B 다운의 타격 효과 (사용자 지시, 2026-11-23: 제안 ①②③ + 바닥 파문 + 카탈로그 리플레이)

다운(`e.down`)과 실신(`e.out`)의 타격만 보통 타격과 다르게 보인다. 흰빛은 쓰지 않는다. **동작과 시합은 바뀌지 않는다**(사건 비교 빈 목록): 모두 그리기와 보여 주는 시간의 일이다.

1. **다운 순간의 슬로(①).** 다운 타격이 닿은 순간부터 시합 시간 0.25 s를 ¼ 속도로 보여 준다(실제 1 s). 앞의 0.05 s는 ½에서 ¼로, 끝의 0.1 s는 ¼에서 1로 부드럽게 바뀐다. 시합은 그 사이 같은 DT로 돈다(보여 주는 속도만 느림). 게임 본편(`main.mjs`)과 이펙트 시안(`fxlab.mjs`의 "확정" 다운 장면)에서. 실신은 0.35 s.
2. **착지의 두 번째 파문(②, 몸).** 쓰러진 몸이 캔버스에 처음 닿는 순간(그리기 쪽에서 몸의 점들로 안다: 골반·가슴·머리·무릎 가운데 하나가 캔버스 6 cm 안으로 처음 내려온 프레임; 시합의 사건은 더하지 않는다), 닿은 부위에서 몸으로 파문이 한 번 더 퍼진다. 첫 파문(맞은 점)이 아직 남아 있으면 바꿔 끼운다(한 선수에 파문 하나). 세기는 다운 타격의 `q`의 0.8배, 길이 0.45 s.
3. **바닥의 큰 파문(②, 먼지 대신).** 같은 착지 순간, 캔버스에 닿은 점에서 바닥(타일 층)으로 **큰 고리 파문**이 퍼진다. 월드의 수평면(XZ) 거리로 재는 고리: 앞머리 초속 4 m, 0.6 s(반지름 2.4 m까지), 파도 묶음의 폭 0.35 m, 타일이 위아래로 최대 3 cm 들썩인다(세기는 `q`에 비례, 가장 작게 1 cm). 빛은 없다: 들썩임만, 마루에서 타일 명암이 한 단계 밝아지는 정도까지(흰빛 아님). 바닥 층에 렌더러의 새 파문 종류(`ground`: 수평 거리, 세로 변위)를 더한다. 실신은 0.75 s, 세기 1.3배.
4. **떠 있는 입자(③).** 다운·실신 타격의 입자만 수명 1.6배, 떨어지는 힘(중력) 절반, 끌림 0.8배: 공중에 더 오래 머물며 천천히 가라앉는다. 수·굵기·색은 §2.4A 규칙 그대로.
5. **카탈로그의 리플레이(살짝 줌).** 모션 카탈로그에서 다운이 나는 카드(맞기와 다운 부의 다운·실신 카드, 리버 다운, 그 밖에 다운이 나는 대본)는, 몸이 캔버스에 닿고 0.3 s 뒤 그 장면을 **다시 보여 준다**: 타격 0.2 s 전부터 착지 0.3 s 뒤까지, ¼ 속도, 카메라가 맞은 선수 쪽으로 **1.2배 당긴** 틀(맞은 선수의 머리와 골반 사이를 가운데로). 기존 "기막힌 수비" 리플레이 틀(`src/replay.mjs`)을 쓰고, 카드 왼쪽 위에 "리플레이 ¼" 표시. 리플레이 중에는 줄의 시계가 기다린다(지금 방식). 리플레이에서도 입자·파문(몸과 바닥)이 그때처럼 보인다. 카드가 라이브에서 보여 주는 것은 ②③④(슬로는 리플레이가 맡는다).

**N01 `inout` 스텝 인 · 아웃: 5명은 콩콩 튀어 들어갔다 나온다.**

## 4. 횡 축 이동을 시합에 (D5, 단계 R)

머리(`brain.mjs`)에는 "돌아갈 선"이 없다. 거리와 방향을 그때의 상대에게서 다시 읽으므로, N05의 "돌아오지 않는다"는 시합에서는 이미 그렇다. 모자란 것은 **옆으로 가겠다는 결정**이다: 지금은 `brain.circle`(−1, 0, 0, 1 가운데 하나) × `plan.circle`(0~0.6)의 느린 옆걸음뿐이고, 측면 대시와 옆걸음을 고르는 곳이 없다. `ai.mjs`의 상대도 같다. 아래 셋만 더한다.

1. **각 잡기 걸음.** 쉬는 동안(`brain.rest > 0.25`) 사거리 안팎(`far < range + 0.25`)에 있으면, 쉼 한 번에 `0.15 + 0.35 × iq`의 확률로 옆걸음 한 번(N02의 등급 거리, 0.18~0.34 s: 1단계 0.34, 3단계 0.26, 5단계 0.18). 방향은 60%가 상대 앞발의 바깥(자기 오른쪽: 상대의 뒷손에서 멀어지는 쪽), 40%가 반대다. 걸음이 끝난 뒤 0.3 s 안에는 `eager`를 1.3배로 본다(각을 잡았으면 친다). **[기본값 11]**
2. **선에서 벗어나는 걸음.** 읽은 주먹이 스트레이트(상대 뒷손)이고 반응할 시간이 남으면(§4A), 슬립의 몫 가운데 25%가 옆걸음이다(3단계부터). 머리가 등급 거리만큼 선 밖으로 간다. 판정은 접촉이다: 늦으면 맞는다.
3. **측면 대시.** 상대가 강타를 던지는 중(그의 `turnRate`가 0.35배로 느린 동안)이고 숨이 40% 넘고 로프가 1 m 밖이면, 풋워크 능력치에 비례한 확률(`0.05 + 0.25 × footwork`, 한 콤비네이션에 한 번)로 `dash: [0, ±1]`. 내려선 뒤에는 그 자리에서 마주 본다(N05). 36°를 도는 데 상대는 강타 중 0.24 s가 걸린다: 그동안 그의 가드는 다른 곳을 보고 있고, 가드의 판정은 글러브가 실제로 길에 있는가이므로 옆에서 친 주먹이 닿는다. 따로 주는 보너스는 없다.

- 조종 값: 옆걸음은 새 행동 `sideStep`(`bout.mjs`의 `GOING`에 더한다: `{ step: 1 | −1 }`). 거리와 시간은 등급(`stance.travel.side`, `dash.face`)에서 읽는다. 숨은 `COST.sideStep = 2`.
- 재는 것(`tools/balance.mjs`에 더한다. 시드 36개, 3라운드 × 60초, 능력치 50, 등급 3 / 4명 / 5명): 선수마다 분당 옆으로 간 거리, 옆걸음과 측면 대시의 수, 10초마다 두 사람을 잇는 선이 돈 각의 평균, **맞은 사람의 정면 오차가 20°를 넘을 때 들어간 명중**("측면 타격")의 수와 몫, 승률.
- 목표: 측면 타격이 전체 명중의 8~20%(지금 값을 먼저 잰다. 지금은 0에 가까울 것으로 본다), 풋워크 70 대 30의 대결에서 높은 쪽의 측면 타격이 2배 이상, 등급 3끼리의 승률이 넣기 전 ±5점 안.
- 시험(`tests/bout.test.mjs`, `tests/techniques.test.mjs`): 같은 시드는 같은 시합. `iq`와 `footwork`가 1인 선수는 옆걸음을 거의 내지 않고(분당 2번 이하), 100인 선수는 분당 6번 이상. 옆걸음 뒤 두 선수의 정면 오차가 0.5 s 안에 5° 아래로 돌아온다. 로프 0.6 m 안에서는 로프 쪽으로 가지 않는다.

## 4A. 반응 시간 수비, 능력치 범위, 블록 지구력 (W1, 단계 X)

사라진 스태시에서 남은 것은 제목뿐이다("system WIP: timed-reaction defence AI, attribute ranges, block stamina cost"). 내용은 아래처럼 새로 정했다. **자리**: 동작이 다 끝난 뒤(V 다음), 최종 통합(Z) 앞이다. 반응 시간은 회피 구간 표(`src/windows.data.mjs`)에 대어 보는 것이라 구간이 더 움직이지 않을 때 넣어야 하고, 머리를 고치는 §4(단계 R)와 롤의 연속(N13)이 먼저 있어야 한 번만 맞춘다.

### 4A.1 지금 있는 것

- **수비의 결정**(`brain.mjs` 96~131행, `ai.mjs`도 같은 틀): 주먹이 보이면(`incoming(him)`) 한 번 주사위를 굴려 패리 0.2 · 가드 0.32 · 슬립 0.12(× `k.read` × 작전)의 몫으로 답을 고른다. 가드는 바로, 패리와 슬립과 기술은 **상대 주먹의 몸통 관절이 발사된 스텝**(`soon = coming.chain.on[2]`)에 누른다. 프로의 잽이면 누른 뒤 +3프레임이다. 반응 시간이라는 것은 없다: 고르면 늘 같은 때에 한다. 맞느냐는 그 프레임이 구간 안이냐(실제 접촉)로 정해진다.
- **능력치**(`profile.mjs` `body(sheet)`): 일곱 능력치(1~100)가 저마다 물리·판단 값의 범위에 직선으로 놓인다(힘 0.76~1.24배, 속도 0.84~1.16배, 걷기 1.8~2.8 m/s, 대시 0.95~1.45 m, 패리 0.11~0.23 s, 가드 새는 몫 0.23~0.07, 맷집 1.3~0.7배, 지구력 70~130, 회복 5~14/s, 읽기 0.55~1.3, 카운터 0.35~1, 페이스 0.6~1.25, 기상 0.35~0.95). **등급(`skills`)과 능력치 사이에는 아무 관계가 없다**: 5명의 걸음에 풋워크 1을 줄 수 있다.
- **블록의 값**: 몸통을 팔꿈치·아래팔로 막으면 맞았을 때 숨의 25%(`RULES.body.blocked`)가 든다. 머리를 글러브로 막으면 체력에 15%(`smother`)가 새지만 **숨은 들지 않는다.** 가드를 들고 있으면 회복이 0.6배, 피커부 셸은 초당 1.5%를 쓴다.

### 4A.2 반응 시간 모델 (`src/game/react.mjs`, 새 파일)

- **보는 것.** 주먹이 눌린 스텝이 단서다(사슬의 다리가 켜지거나 감기가 시작된 때: `coming.chain.t`가 0에서 떠난 스텝). 머리는 그 주먹의 손과 종류(`situation()`의 `punch`), 머리로 오는지 몸으로 오는지, 거리(`far`), 닿기까지 남은 시간의 어림, 그리고 제 상태(가드가 올라가 있는가와 그 나이 `coverAge`, 주먹을 내는 중인가, 경직, 숨)를 본다.
- **반응 시간**(ms, 단서에서 수비를 누르기까지):
  `RT = BASE × 예측 × 상태 × (1 + 잡음) − 등급`
  - `BASE = lerp(110, 45, a)`, `a = 0.6 × 수비 + 0.4 × 감각`(0.01~1). 능력치 50이면 약 77 ms.
  - 예측: 쉬는 동안 머리는 올 주먹 하나를 **기다린다**(상대가 최근 다섯 번 콤비네이션을 무엇으로 시작했는지 `mem`에서 가장 잦은 것. 감각이 낮으면 늘 잽). 맞으면 × 0.6, 틀리면 × 1.1.
  - 상태: 지침 `1 + 0.3 × (1 − fresh)`, 휘청이는 중 +40 ms, 콤비네이션의 둘째 주먹부터는 × 0.85(이미 보고 있다).
  - 잡음: 시합의 주사위 하나, 표준편차가 등급의 것: 1단계 25%, 2단계 20%, 3단계 15%, 4단계 12%, 5단계 8%. 범위는 ±2 표준편차로 자른다.
  - 등급(그 수비 동작의 등급): 4단계 −8 ms, 5단계 −17 ms(전설은 발에서 읽는다).
  - 바닥 33 ms(2프레임). `react.mjs`의 `reactionOf(k, grade, state, u)`는 순수 함수다(`u`는 0~1의 주사위 값).
  - 이 ms는 **이 엔진의 주먹**(누른 뒤 100~170 ms에 닿는다)에 대한 것이고 사람의 반응 시간을 옮긴 것이 아니다. 사람이 잽을 막는 것은 대부분 예측이다: 여기서는 그것이 "예측 × 0.6"이다.
- **고르기.** 지금의 주사위 하나(답할 것인가: `k.read` × 작전의 몫)는 남는다. 답하기로 했으면 반응 시간이 지난 스텝에 **그때 아직 되는 것 가운데** 고른다.
  - 구간 표가 "되는 것"을 말한다. `tools/windows.mjs --write`가 카드마다 지금의 `from`·`to`·`at`에 더해 **닿는 프레임 `hit`** 을 쓰게 한다. 수비 × 주먹 × 수비하는 사람의 등급마다 "닿기 몇 초 전부터 몇 초 전까지 시작하면 되는가"(`early = (hit − from) / 60`, `late = (hit − to) / 60`)가 나온다. 표에 없는 짝(더킹 대 잽 등)은 후보가 아니다.
  - 닿기까지 남은 시간 `T` = 그 주먹의 `hit`(던지는 사람의 등급) ÷ 60 − 지난 시간 + (거리 − 카드의 거리) ÷ `RULES.stepIn`.
  - 후보: 패리·슬립·더킹·위빙·스웨이·옆걸음(§4)·그가 가진 기술 가운데 `T ≥ late`인 것. `T > early`면 기다렸다가 구간의 가운데(`at`)에 누른다. 여럿이면 지금의 몫(작전 × 기술의 `share`)을 후보끼리 다시 나눠 주사위 하나로 고른다.
  - 후보가 없으면: 가드가 제때 올라오면(`cover.arrive` × 2 ≤ `T`) 가드, 아니면 아무것도 못 한다(맞는다). 가드가 이미 올라가 있으면 그대로 막는다(반응이 필요 없다).
  - 패리는 "막 올린 가드"여야 한다. 가드를 들고 있는 중에 패리나 다운패링을 골랐고 시간이 되면(`T ≥ late + 0.05`), **두 프레임 내렸다가** 제때 다시 올린다. 지금은 이때 그냥 블록이 된다.
- **다운패링이 드문 것(`pending-catalog.md` §5.7)이 같이 풀린다.** 거기서 잰 세 원인 가운데 둘이 이 모델로 없어진다: (2) 고른 것의 4분의 1~3분의 1이 막 올린 가드가 못 되던 것은 위의 "내렸다 올리기"로, (3) 늘 구간의 끝(+3프레임)에 누르던 것은 구간의 가운데에 누르는 것으로(5명은 반응이 빨라 +1에 누를 수 있다: §5.7의 `legend-early`를 일반형으로 넣은 셈이다). (1) 고르는 몫(패리의 60%)은 그대로 둔다. 목표: 잽 100개당 눌러 내린 횟수 4명 **6 이상**(지금 4.4), 5명 **6 이상**(지금 3.4). 108개 시드로 재고, 못 미치면 수치로 보고한다. **[기본값 12]**(§5.7의 선택지는 사용자가 아직 고르지 않았다.)
- `ai.mjs`의 상대(`novice`/`contender`/`champion`)는 능력치가 없으므로 `LEVELS`에 `react`(ms: 105 / 75 / 55)와 잡음(25 / 15 / 10%)을 적고 같은 `react.mjs`를 쓴다.
- **맞춤(끝 조건).** 능력치 50 · 등급 3끼리의 시합에서 "상대 주먹 가운데 제때 답한 몫"과 승률이 넣기 전 ±5점 안이 되도록 `BASE`의 두 끝을 맞춘다(먼저 지금 값을 잰다). 수비 20과 80 사이에 그 몫이 25점 이상 벌어져야 한다. 등급 1은 잽을 거의 못 피하고(구간이 누르기 전이다: 슬립 −5~−1) 스트레이트와 훅에는 가드로 답한다는 것이 표로 나와야 한다.

### 4A.3 능력치 범위 (`profile.mjs`)

- `body(sheet)`의 범위는 그대로 둔다. 새로 생기는 값만 더한다: `react`(위 `BASE`), `guardCost`(4A.4).
- **등급이 허락하는 능력치의 범위**를 새로 둔다. 능력치마다 그것이 드러나는 동작의 등급에 묶는다:

| 능력치 | 묶이는 등급 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 힘, 속도 | 주먹 가운데 가장 높은 등급 | 10~45 | 25~60 | 40~75 | 55~90 | 70~100 |
| 풋워크 | `stance` | 10~45 | 25~60 | 40~75 | 55~90 | 70~100 |
| 수비 | `evade`·`cover` 가운데 높은 쪽 | 10~45 | 25~60 | 40~75 | 55~90 | 70~100 |
| 감각 | 가장 높은 등급 | 5~50 | 20~65 | 35~80 | 50~95 | 65~100 |
| 지구력, 맷집 | 가장 높은 등급(넓게) | 10~70 | 20~80 | 30~90 | 40~100 | 50~100 |

  `ATTR_RANGE`, `fits(sheet, skills)`(벗어난 능력치의 목록), `fit(sheet, skills)`(범위 안으로 당긴 시트)를 내보낸다. 선수를 **만드는 곳**(커리어, 상대 생성, §8의 대본 생성기)이 `fit`을 쓴다. `createBout`은 주는 대로 받는다: 카탈로그와 시험은 일곱 등급을 모두 능력치 50으로 돌려 동작만 견준다(3단계 범위의 가운데에 가깝다. 1단계와 5단계에는 범위 밖이지만 재는 조건이지 선수가 아니다). **[기본값 13]**
- 시험(`tests/techniques.test.mjs` 또는 새 `tests/profile.test.mjs`): `fit`의 결과는 `fits`가 빈 목록이다. 범위의 두 끝에서 `body()`의 값이 단조롭다. 등급 5에 풋워크 10을 주면 `fits`가 풋워크를 짚는다. `rate()`가 등급 범위의 가운데에서 등급 순서대로 커진다.

### 4A.4 블록 지구력 (`bout.mjs`)

- 규칙: **막은 사람은 막은 충격량만큼 숨을 쓴다.** `RULES.block = { ref: 85, glove: 2.5, forearm: 2.0, elbow: 1.5, shoulder: 2.5, rolled: 0.8 }`(85 N·s를 막을 때 드는 숨, 지구력 100 기준의 점수). 든 숨 = `값[막은 곳] × J / 85 × guardCost × 등급의 버팀`.
  - `guardCost = lerp(1.3, 0.7, 수비)`.
  - 등급의 버팀은 있는 값 `cover.block.brace`(1단계 1.5, 2단계 1.2, 3단계 1, 4명 0.8, 암 0.6, 5명 0.7).
  - 패리, 해머링, 다운패링은 0이다(쳐낸 것은 받은 것이 아니다). 구른 어깨(`roll: true`)는 0.8, 서서 받은 어깨는 2.5.
  - 몸통을 팔꿈치·아래팔로 막은 것은 **지금 식 그대로**(`breathOf × 0.25`)이고 위 값과 겹쳐 받지 않는다.
- 크기의 뜻: 스트레이트(88 N·s)를 글러브로 막으면 2.6, 던진 쪽은 7을 쓴다. 막는 쪽이 싸지만 공짜는 아니다. 다섯 주먹(약 350 N·s)을 가드로 받으면 10(지구력의 10%)이 들고, 가드 중 회복(초당 5.7)을 2초 가까이 지운다.
- 시합에 주는 것: 가드만 들고 버티는 작전(`defend`, 피커부 셸)이 오래 못 간다. 압박(`pressure`)이 막힌 주먹으로도 얻는 것이 생긴다. 지치면 반응이 느려지므로(4A.2) 블록 → 숨 → 반응의 고리가 생긴다.
- 사건: `block` 사건에 `breath`(든 숨의 몫)를 더한다. `tools/events.mjs --diff`는 이 칸을 비교에서 뺀다(카탈로그의 카드가 "바뀜"으로 뜨지 않게).
- 시험(`tests/bout.test.mjs`): 막은 뒤 숨이 식대로 줄어든다. 패리는 0. 몸통 블록의 수치는 지금과 같다. 수비 100은 수비 1의 0.54배를 쓴다.

- **K가 그다음**이다. 메모의 절반이 허리를 쓴다. 엔진만 먼저 넣고 "아무것도 달라지지 않았다"를 사건 비교로 증명한 뒤에 동작에 넣는다. 숫자가 움직이는 것은 N부터다.
- **M은 손의 길을 바꾸는 단계들(N, P, Q, U) 앞**이다. 새 손의 길이 처음부터 이 점검을 받는다.
- **N(주먹)이 P·Q(수비)보다 먼저**다. 수비의 구간은 주먹의 길에 대어 재는 것이라 주먹이 먼저 굳어야 한다. **P(크로스암)가 Q보다 먼저**인 것은 롤의 연속과 해머링을 새 모양 위에서 한 번만 재려는 것이다.
- **R이 S보다 먼저**다. 파도의 뜀이 R에서 만드는 "두 발이 같이 뜨는 걸음"을 쓴다.
- **X는 동작이 끝난 뒤, Z 앞**이다(§4A의 머리말).
- 5차의 남은 "I 최종 통합"은 따로 하지 않고 Z가 한다. 지금 하면 이 모든 단계 뒤에 다시 해야 한다.

## 8. 약속 대련 (D6): 방향만

선택지와 여러 변수로 그 라운드의 대본을 미리 만들고, 오토 배틀을 보다가 개입하는 형식이다. 이번에는 만들지 않는다. 대본 생성기가 동작 엔진에서 필요로 할 것과, 위 단계들이 지켜 둘 것만 적는다.

- **같은 입력은 같은 결과.** 지금도 대본(`footwork.mjs`의 `drive`: 시각마다의 자리와 누름)과 시드로 시합이 정해진다. 새로 넣는 것(옆걸음의 방향, 롤의 연속, 반응의 잡음, 휘청임의 받치는 걸음, 도발)은 모두 시합의 주사위(`random(bout)`)만 쓰고 `Math.random`과 벽시계를 쓰지 않는다. 단계마다 "같은 대본은 같은 결과" 시험을 둔다.
- **이름으로 부를 수 있다.** 모든 동작이 조종 값으로 불린다: 주먹(`jab`, `power`, `body`, 이름 지정), 수비(`cover`, `slip`, `duck`, `roll`, `pull`), 이동(`move`, `dash`, `sideStep`, `away`), 기술(`tech: 'rollCounter'` 등 `techniques.mjs`의 id). 새 동작에 새 이름이 생기면 `techniques.mjs`나 `bout.mjs`의 조종 값 주석에 적는다. 머리의 주사위를 거치지 않고 대본이 직접 부를 수 있어야 한다.
- **시간표.** 생성기는 "이 주먹은 누른 뒤 몇 프레임에 닿는가", "이 수비는 언제 시작해야 되는가", "이 동작은 얼마나 묶이는가"를 알아야 한다. 구간 표(`windows.data.mjs`: 이번에 `hit`를 더한다), 사다리(`tools/ladder.mjs`의 닿는 시각과 충격량), 등급표(`skill.mjs`의 시간들)가 그것이다. 단계 Z에서 이 셋을 한 파일(`src/timing.data.mjs`, 도구가 쓴다)로 모으는 것을 **후보**로 적어 둔다(만들지는 사용자가 정한다).
- **결과는 약속이 아니라 접촉.** 대본은 누름과 자리를 약속하고, 맞았는지는 엔진이 정한다. 그래서 개입(거리를 5 cm 바꾼다, 한 프레임 늦게 누른다)이 결과를 바꾼다. 생성기는 만든 대본을 한 번 돌려 사건 기록(`tools/events.mjs`의 형식)으로 확인하면 된다.
- **사건 기록의 형식을 지킨다.** `hit`, `block`, `parry`, `graze`, `punch`, `dash`와 그 칸(`who`, `on`, `name`, `J`, `at`, `vec`, `part`, `zone`, `roll`, `down`, `out`…)은 더하기만 하고 뜻을 바꾸지 않는다(이번에 더하는 것: `block.breath`, 패리의 `hammer`, 롤의 차례 `n`).
- **능력치와 등급.** 생성기가 선수를 만들 때 `fit(sheet, skills)`(§4A.3)을 쓴다. 반응은 `react.mjs`의 순수 함수로 미리 셀 수 있다(§4A.5).

## 9. 엔진이 못 하는 것과 가장 가까운 것

- **허리는 한 축이다.** 도는 것(`waist`)만 따로 있고, 허리만의 숙임·젖힘·옆굽힘은 없다. "허리로 스웨이"는 골반을 세우고(`tip`) 그 위의 척추 두 마디를 젖히는 것으로 만든다. 허리뼈 하나하나는 없다.
- **허리는 사슬의 가지다.** 골반이 허리와 가슴을 같이 켠다. 허리가 가슴에게 "넘겨주는" 것은 아니다(그러면 모든 주먹이 한 프레임 늦어진다). 최고 속도의 순서는 골반 → 허리 → 가슴으로 나온다.
- **허리의 범위는 22°다.** 실제 허리뼈의 회전은 그보다 작다. "원판처럼"을 보이게 하려고 넉넉히 잡았다(척추 전체 45°는 그대로).
- **크로스암의 뒷팔은 30° 안팎까지다.** 기획의 15°는 머리가 어깨 바로 위에 와야 하는데, 그러면 웅크린 가드가 아니다.
- **파도의 속도.** 뜀으로 바꿔도 5차 기획의 1.9~2.2 m/s는 약속하지 못한다(1.4~1.6을 목표로 했다). 디딘 발은 여전히 미끄러지지 않는다.
- **시프트의 각.** 한 걸음으로는 다리 길이 때문에 23~28°였다. 두 걸음으로 40° 안팎을 노리지만 0.30 s 안에 두 발이 다 닿아야 해서 4명은 바디 훅이 늦어질 수 있다. 시트는 초당 4장이라 영상의 정확한 거리는 모른다.
- **파문은 한 사람에 하나**이고 화면 평면에서 좌우로만 민다(깊이 방향의 파동은 없다). 두 파문이 겹치지 않는다.
- **입자는 맞은 사람의 윤곽 밖에서만 보인다.** 카메라가 정확히 타격선 위에 있으면(주먹이 화면 안쪽으로 들어가면) 입자가 몸에 가려 늦게 나타난다.
- **손바닥이 없다.** 손짓의 "손바닥 위", 턱 두드리기의 "톡톡", 어깨 으쓱의 "손바닥을 편다"는 글러브(공)의 자리와 팔꿈치 방향으로만 나온다.
- **두 발이 같이 뜨는 걸음**은 지금 멀어지기(`hopPivot`·`hopCircle`)에만 있다. 걸음 전체의 박자 시계(한 발씩 번갈아)에 넣는 것이 R의 가장 큰 일이고, 뜀과 걸음이 바뀌는 반박자에 발이 2 cm쯤 끌릴 수 있다(재서 적는다).
- **롤은 약속이 아니다.** "두세 개를 빗나가게"는 구른 몸이 실제로 만드는 것이라, 상대의 주먹이 빠르거나 높이가 다르면(어퍼, 바디) 맞는다. 어퍼와 바디에는 구르지 않는다.
- **반응 시간의 ms는 이 엔진의 것이다**(주먹이 100~170 ms에 닿는다). 사람의 수치와 견줄 수 없다.
- **다운의 다리**는 물리다. 엉덩관절의 저항을 올리면 다른 다운의 누운 모습도 조금씩 달라진다(재서 적는다).

## 11. 정하지 못한 것

- 사라진 스태시의 실제 내용. 제목 말고는 남은 것이 없어 §4A는 새 설계다.
- 타이슨 시프트의 정확한 거리와 각(시트가 초당 4장). 프레임 단위로 재려면 원본 영상이 다시 필요하다.
- 이 문서의 목표값 가운데 지금 값을 재지 못한 것: 파도에서 어깨선의 각(약 52°는 채널에서 셈한 값), 플리커와 뒷손 훅의 등급별 충격량, 스웨이에서 머리가 뒤로 가는 거리, 휘청임의 머리 이탈, 시합의 측면 타격 몫과 "제때 답한 몫". 해당 단계가 손대기 전에 먼저 잰다.
- 허리를 넣은 뒤 회피 구간이 얼마나 움직이는지(단계 N에서 잰다), 크로스암을 세운 뒤 명치의 틈이 열리는지(단계 P), 자기 팔 점검을 0으로 만들 때 가드의 막기가 얼마나 달라지는지(단계 M).
