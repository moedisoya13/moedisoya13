> 측정 대상: 커밋 `f04bc93`의 빌드(`node build.js` → `dist/before-dawn.html`) · 작성: 게임 디자이너 · 읽는 사람: 구현 담당(이 문서만 보고 만든다)

> 이 문서의 숫자는 전부 `tools/feel/`의 스크립트로 잰 값이다. 추정한 곳은 "추정", 코드만 읽고 재지 않은 곳은 "코드 확인"이라고 적었다.

## 0. 결론 먼저

- 키보드 조작의 뼈대는 좋다. 입력 후 1프레임에 움직이고, 가속·감속이 없고, 대각선 속도가 같고, 벽을 따라 잘 미끄러진다. **이건 건드리지 않는다.**
- 나쁜 곳은 다섯 군데다: ① 사람 반응 속도로는 2층에서 죽는 난이도, ② 휴대폰에서 3mm짜리 조이스틱, ③ 씹히는 돌진 입력과 의도하지 않은 돌진, ④ 처음 0.3초 동안 거의 보이지 않는 예고, ⑤ 적에게 갇히고 기둥 면에 걸리는 이동. 여기에 ⑥ 용사 몸이 초당 3번 뒤집히는 방향 규칙을 더한다.
- 변경은 7개다(§3). 한 세션에 끝낼 수 있는 크기다. 끝나면 `node tools/feel/check.js --bots`가 전부 PASS여야 한다(지금은 26줄 중 17줄 FAIL, `--bots`의 3줄도 FAIL).

### 1.1 이동

### 3.2 조이스틱 크기를 CSS px로 고정한다 (문제 2)

- `src/client/40_input.js`의 `DEAD / FULL / FOLLOW`를 논리 px이 아니라 **CSS px**로 정의한다: **데드존 8, 최고 속도 48, 원점이 따라오는 거리 64** (CSS px). 4.7인치 휴대폰에서 1.2mm / 7.5mm, 9.7인치 태블릿에서 1.5mm / 9.2mm다.
- 구현: 끈 거리를 CSS px로 구한다(`논리 거리 × view.scale`, 또는 `clientX/Y` 차이를 그대로). 속도 = `clamp((d − 8) / (48 − 8), 0, 1)`, 선형 그대로. 원점 추종은 `d > 64`일 때 원점을 손가락 쪽으로 당겨 `d = 64`로 맞춘다.
- 마우스 끌기도 같은 값이다.
- 그리기(`src/ui/40_hud.js`의 조이스틱): 바깥 고리 반지름 = `48 / view.scale` 논리 px, 손잡이는 그 안에서 움직이고 반지름 `20 / view.scale`. 즉 화면에 보이는 고리가 곧 최고 속도 선이다.
- 고칠 테스트: `tests/ui/touch.test.js`(끄는 거리가 30 논리 px으로 적힌 곳).
- 확인: `check.js` S1 (두 해상도 모두 7px → 0, 9px → 움직임, 30px → 0.45~0.65, 40px → 1 미만, 48px → 1).

### 3.3 돌진 입력: 0.2초 기억, 다시 잡기와 구별, 방향 규칙 하나로 (문제 3)

**(a) 입력 버퍼 — 코어.** `src/core/21_hero.js`
- `hero.dashBuf`(초)를 둔다. 그 틱의 입력에 `dash`가 있으면 `dashBuf = 0.20`. 매 틱 `dt`만큼 줄인다.
- `dashBuf > 0`이고 `dashCd ≤ 0`이고 `dashT ≤ 0`이면 돌진을 시작하고 `dashBuf = 0`.
- 결과: 대기가 끝나기 0.2초 전까지의 입력, 돌진 중 끝나기 직전의 입력이 살아난다. 0.2초보다 일찍 누른 입력은 버린다(연타로 돌진이 예약되지 않게).
- `BD.C.DASH.buffer = 0.2`로 둔다. 사망·층 이동(암전)·제단 열림 때 `dashBuf = 0`.

**(b) 입력 없을 때의 방향 — 코어.** `H.startDash`
- 그 틱에 이동 입력이 있으면 그 방향. 없으면 **마지막으로 움직인 방향**(`hero.moveX/moveY`, 이미 저장돼 있다). 판을 시작하고 한 번도 안 움직였으면 보는 방향.
- 클라이언트의 꼼수(`st.dashReq`일 때 `lastDir × 0.02`를 이동으로 끼워 넣는 줄)는 지운다. 그 0.02짜리 입력이 "움직이는 중"으로 읽혀 한 틱 걷는 부작용도 같이 없어진다.

### 3.4 예고는 첫 프레임부터 꽉 찬 모양으로 보인다 (문제 4)

### 3.5 몸에 갇히지 않고, 모서리에 걸리지 않는다 (문제 5)

`src/core/21_hero.js`의 `moveHero`(돌진이 아닐 때). **GDD §2.2의 "용사는 적을 밀고 지나갈 수 없고"를 "용사는 졸개를 헤치고 지나가되 느려진다"로 바꾼다.**

**(a) 헤치기.** 걷는 틱에 용사 원과 겹친 적마다:
- 대상: 살아 있고, 쓰러져 있지 않고, 수호자·마왕이 아니고, 달려드는 중(`lunging`)이 아닌 적.
- 적을 **용사의 이동 방향에 수직인 옆 방향**으로 민다. 옆 방향은 적의 중심이 이동선의 어느 쪽에 있는지로 정하고, 정확히 선 위면 `적 id`가 짝수일 때 왼쪽, 홀수일 때 오른쪽이다(결정적).
- 미는 양: 겹친 깊이의 60%, 한 틱에 최대 `4.2 × dt × 0.6`u(= 초당 2.5u). `BD.nav.move`로 옮겨 벽·장애물을 통과하지 않게 한다.
- 그 다음 용사는 지금처럼 남은 겹침만큼 밀려난다(원 충돌). 입력이 없는 틱에는 밀지 않는다.
- 결과: 한 마리는 약 0.3초 만에 비켜 지나가고, 무리는 속도가 절반쯤으로 떨어진 채 헤쳐 나간다. 포위는 "갇힘"이 아니라 "느려져서 한 대 맞을 위험"이 된다. 고블린 포위의 해법 셋(§6.5)은 그대로 더 빠른 답으로 남는다.
- 적의 거리 유지 규칙(0.8u, 스스로 다가오지 않음)과 일섬의 `too_close` 규칙은 그대로다. 용사가 걸어 들어간 것이므로 플레이어 책임이다.
- 수호자와 마왕은 지금처럼 벽이다.

**(b) 모서리 보정.** 걷는 틱에 격자 충돌 때문에 의도한 이동의 30%도 못 갔을 때만:
- 이동 방향에 수직인 양쪽으로 0.25u까지(0.05u 간격) 옮긴 자리에서 같은 이동을 시험한다. 의도한 이동의 90% 이상이 되는 가장 가까운 자리가 있으면, 이번 틱에 그쪽 옆으로 `4.2 × dt × 0.6`만큼 민다.
- 결과: 모서리까지 0.25u 안이면 돌아 나가고, 면 한가운데로 박으면 지금처럼 멈춘다. 벽 미끄러짐(4.2 × cos)은 변하지 않는다(이미 30% 넘게 움직이는 경우다. 정면 90°는 양옆에도 길이 없어 그대로 멈춘다).
- 돌진에는 적용하지 않는다.

- 고칠 테스트: `tests/core/mechanics.test.js`의 충돌, 적 테스트 중 용사와의 접촉을 가정한 것.
- 확인: `check.js` M2~M7.

## 6. 남는 위험

- 사람 같은 봇은 모델이다. 실제 사람의 승률은 재지 못했다. H1의 폭(8~28%)을 넓게 잡은 이유다. 첫 사람 플레이 뒤 `--firewarn`과 `--guardhp`로 다시 맞춘다.
- 사람의 승리 판 길이 9~13분은 가동률 가정(40~55%)에서 나온 추정이다. 10분보다 짧게 나오면 마왕 HP를 3300으로 올린다(완벽한 봇 승리 길이로 +20초).
- 헤치기(§3.5)는 일섬 카드의 "품을 내줬다" 판정을 더 자주 건드릴 수 있다. 기준 11과 18의 일섬 관련 수치를 다시 본다.
- 보는 방향(§3.6)을 바꾸면 발도·반격 카드의 그림 방향이 달라 보일 수 있다. 판정은 `aim`을 쓰므로 바뀌지 않는다(코드 확인).

### 명세대로 만든 것 (요약)

- §3.1: 수치 전부(`T1~T3`). GDD §2.2·§6.2·§6.3의 수치 줄을 이 값으로 고쳐, `numbers.test.js`는 이 값을 GDD 값으로 읽는다(남은 튜닝 표시는 고블린·슬라임 피해뿐).
- §3.2: `40_input.js`가 끈 거리를 `논리 거리 × view.scale`로 재고 데드존 8 / 최고 48 / 추종 64 CSS px. 강제 가로(`view.rot`)에서도 거리는 그대로라 같은 값이다(`tests/ui/rotate.test.js` 새 항목). 고리는 반지름 `48 / scale`, 손잡이 `20 / scale`.
- §3.3: 코어 `hero.dashBuf`(`BD.C.DASH.buffer` 0.2), 사망·층 진입·제단 열림 때 0. 입력 없는 돌진은 `moveX/moveY`, 한 번도 안 걸었으면 보는 방향. 클라이언트의 0.02 끼워 넣기는 지웠다. 두 번 두드리기는 250ms 안 + 뗀 자리(클라이언트 px)에서 60 CSS px 안. 오버레이가 열려 있는 동안 셸이 매 프레임 `input.clearDash()`, 창이 포커스를 잃을 때도. 메뉴 중 Space는 돌진 요청이 아니다(일시정지 중 Space 버그).
- §3.4: `hatch` 양식만 바꿈(바탕 40% / 흰색 30%, 전체 빗금 0.6, 안쪽부터 불투명 빗금 + 55% / 45%, 처음 0.12초 6px 테두리). `blink`와 콘텐츠 양식은 그대로.
- §3.6(a): 표적이 있으면 `autoAttack`이 표적을 고른 직후 매 틱 그쪽을 본다. 없어지면 `hero.faceHold` 0.25초 유지 뒤 이동 방향.
- §3.7: 돌진 그림 `max(46, 34 / scale)`, 터치 `max(104, 72 / scale)`, 중심은 가장자리에서 반지름 + 16 이상. 667×375: 그림 68 / 터치 72 CSS px, 일시정지 44 CSS px. 1280×720은 예전과 같다.
