# 여명 전야 (Before Dawn) — 확정 사항 (팀장)

이 문서는 사용자와 이미 합의했거나 팀장이 정한 **변경 불가** 조건이다. 기획서(GDD)와 구현은 이 문서를 따른다. 여기에 없는 것은 기획 에이전트가 정한다. 사용자에게 되묻지 않는다.

## 1. 목표

- **비행기 안에서 오프라인으로 하는 게임.** 반복해서 해도 재미있는 로그라이크 샘플 게임을, 이번 세션 안에 **끝까지 플레이할 수 있는 상태**로 만든다.
- 한 판 10~20분. 타이틀 → 한 판(여러 층) → 보스 → 승리/사망 화면 → 다시 하기까지 막힘 없이 돈다.

## 2. 플랫폼과 기술 (팀장 결정)

- 결과물은 **단일 HTML 파일 하나** (`dist/before-dawn.html`). 더블클릭으로 `file://`에서 열려야 하고, 네트워크 요청이 0건이어야 한다. 외부 폰트·CDN·fetch 금지. 이미지는 base64로 내장, 효과음은 WebAudio로 합성한다.
- 이유: 비행기 안 노트북·태블릿·휴대폰 어디서든 설치 없이 돈다. Godot 웹 내보내기는 `file://`에서 열리지 않고, 데스크톱 내보내기는 사용자 OS별 템플릿이 필요하다. Godot 이식은 이후 과제로 둔다.
- 렌더링은 Canvas 2D. 외부 라이브러리 없음. 소스는 여러 파일로 나누고 의존성 없는 node 빌드 스크립트로 한 파일로 합친다.
- 입력: **키보드(WASD/방향키)와 터치(화면 드래그 가상 조이스틱) 둘 다.** 가로 화면 기준, 세로로 들면 회전 안내.
- 성능: 중급 휴대폰에서 60fps 목표. 화면 내 적 80, 파티클 300 수준을 상한으로 설계한다.
- 저장: `localStorage`만 사용(기록, 설정, 가벼운 해금). 쓸 수 없는 환경에서도 게임은 돌아야 한다.
- 화면 글자는 한국어. 시스템 글꼴 사용.

## 3. 게임의 뼈대 (사용자 합의)

- 테마: 정통 용사 판타지 in 현대 도심. 마왕성이 강림한 마천루를 동트기 전에 오른다. 톤은 정통(농담 없음).
- 주인공: 돌아온 노용사(일흔 안팎), 성검 「첫빛」. `prior/hero-design.md` 참고.
- **조작은 이동 위주, 공격은 자동.** 플레이어는 움직여서 자리를 잡고, 용사는 사거리 안의 적을 스스로 벤다. 이동 외의 버튼은 많아야 하나(예: 어깨 돌진)까지 허용한다. 한 손 엄지로 할 수 있어야 한다.
- 실시간. 턴제·격자 이동이 아니다.
- **카드 3장 장착.** 시작할 때 덱에서 무작위로 3장을 받는다. 카드는 소모되지 않는 패시브이고, 전부 **자동 공격을 바꾼다**. 성검 코등이의 홈 3개가 카드 슬롯이다.
- 카드 종류: 형태 / 속성 / 발동 / **표적**(특정 적 유형에 효과) / **퀘스트**(조건을 채우면 판 도중에 각성, 진행도가 보임) / **콤보**(연속 달성마다 강화, 실수하면 초기화).
- 판 안에서 카드를 바꿀 기회가 있다(이전 기획의 제단).
- 시계: 실제 약 15분이 게임 속 18:00→06:00. 06:00을 넘기면 즉사가 아니라 압박(서서히 HP 감소 등).
- 영구 강화(판 사이 진행)는 **허용**. 다만 범위는 가볍게.

## 4. 그래픽 기준 (사용자 채택)

- 로우폴리 극화: `prior/art-direction.md`와 `prior/style-reference-A.jpg`.
- 고정 아이소메트릭 3/4 시점. 밤 도시 위에 뜬 마천루 한 층의 단면. 방 하나가 화면에 다 들어오고 용사는 화면 높이의 1/8 안팎.
- 층 바닥은 그 층의 우세 적 유형을 나타내는 단색: 마물 `#f2c230`, 언데드 `#4fa94d`, 마법 `#5c4d8e`, 중갑 `#e0392f`.
- 주황 `#ff9a3c`은 용사의 칼과 궤적 전용. 적의 공격 예고는 빨강 빗금(빨강 바닥에서는 흰 빗금).
- 먹 외곽선, 명암 2단, 잉크 튐, 손글씨 의성어.
- 배경과 소품(책상, 벽, 가시, 크리스털)은 코드로 그린 로우폴리 도형. 인물은 2D 스프라이트를 세운다.

## 5. 준비된 그림 (팀장이 제공, `assets/`)

- 용사 스프라이트 6포즈: 앞 대기, 뒤 대기, 옆 대기, 베기(주황 궤적이 그림에 포함됨), 어깨 돌진, 피격. 왼쪽은 좌우 반전.
- 적 스프라이트 **7종 고정**: 슬라임, 고블린(마물) / 해골 궁수, 구울(언데드) / 마도사(마법) / 암흑기사(중갑) / 마왕(보스). 각 1포즈, 좌우 반전. 변종은 크기·색조·테두리 효과로만 만든다. **새 그림이 필요한 적은 기획하지 않는다.**
- 그 밖의 모든 것(칼 궤적, 탄환, 예고 표시, 지형, HUD, 아이콘)은 코드로 그린다.

## 6. 범위 원칙

- 끝까지 도는 한 판이 먼저다. 그다음이 카드 다양성, 그다음이 연출.
- 기획한 카드는 전부 화면에서 효과가 눈에 보여야 한다. 보이지 않는 패시브는 넣지 않는다.
- 자동 검증이 가능해야 한다: 시드 지정, 상태 덤프, 자동 조종(봇) 훅.

## 7. 기획서(GDD) 확정 뒤 보충 (GDD와 다르면 이 절이 우선)

- **적의 몸 색은 준비된 그림 그대로 쓴다.** 실제 그림: 슬라임 자홍, 고블린 청록 피부, 해골 궁수 뼈색에 보라 두건, 구울 잿빛, 마도사 진홍 로브에 청록 구슬, 암흑기사 검은 강철, 마왕 검정과 진홍. GDD §6.2의 "기준 몸 색" 열과 색조 회전은 적용하지 않는다. 네 가지 바닥색 위에서 확인했고, 우세 층의 바닥색과 겹치는 적은 없다. "색상 차 40° 안이면 흰 테두리" 규칙만 남긴다(예: 초록 바닥의 고블린, 빨강 바닥의 마도사).
- **그림 파일 이름**: GDD의 `skel_archer`는 `assets/enemies/skeleton_archer.webp`다. 게임 안의 id는 GDD대로 `skel_archer`를 쓰고, 그림만 이 파일에 연결한다.
- **`hero_slash` 그림에는 주황 궤적이 들어 있다.** 전투 중 궤적은 카드에 따라 달라지므로 코드로 그린다. 전투 중 공격 순간에는 옆/앞/뒤 대기 그림을 짧게 내밀고 기울이는 식으로 표현하고, `hero_slash`는 타이틀과 결과 화면 연출에만 쓴다.
- 그림 목록과 크기는 `assets/README.md`와 `assets/sprites.json`에 있다.
- **용사는 졸개를 옆으로 헤치고 지나가고, 장애물 모서리에서는 모서리 보정을 받는다.** GDD §2.2의 "용사는 적을 밀고 지나갈 수 없고"를 이것으로 바꾼다(`docs/CONTROLS-REVIEW.md` §3.5). 수호자와 마왕은 지금처럼 막는다. 같은 검토의 튜닝(졸개 HP 약 2/3, 수호자·마왕 HP, 피격 후 무적 1.0초, 불 원 예고 1.1초)과 기준 17의 새 목표(사람 같은 봇 8~28승 / 100판, 1~2F 사망 22판 이하, 완벽한 봇 60승 이상)도 채택한다.
