# 여명 전야 v2 — 방향 (팀장)

사용자 평가: **"너무 재미가 없다."** 요구: ① 직접 플레이하며 스스로 개선 ② 맵 크기 확대 ③ 로우폴리 개선 ④ 모든 캐릭터에 로토스코핑 수준의 부드러운 움직임(세부 스프라이트).

이 문서는 v2의 고정 방향이다. `LEAD-DECISIONS.md`의 플랫폼·조작 조건(오프라인 단일 HTML, 이동 + 돌진 하나, 자동 공격, 카드 3장, 한 판 10~20분, 정통 톤, 로우폴리 극화)은 그대로다. 그 밖의 v1 기획(GDD)은 재미를 위해 바꿀 수 있다.

## 1. 직접 돌려 본 v1 (시드 21, 봇, `docs/screens/play-v1/bot-run-seed21.jpg`)

- 5분 30초 동안 처치 102. **분당 약 18마리.** 화면에 적이 1~9마리뿐인 시간이 길고, 마지막 한두 마리를 쫓아다니는 시간이 많다.
- 고르는 순간이 층당 한 번(제단)뿐이다. 약 60~100초에 한 번. 그 사이에는 주울 것도, 자랄 것도 없다.
- 방 하나가 화면에 다 들어와서 갈 곳이 없다. 화면의 절반은 건물 외벽과 밤하늘이다.
- 인물이 한 장짜리 그림이라 서 있는 것과 뛰는 것이 같다.
- 층이 바뀌어도 바닥색과 적 종류만 다르고 하는 일은 같다.

## 2. v2의 기둥

1. **몰려오고, 쓸어 담고, 자란다.** 약한 적이 많이 온다(잡졸은 한두 번 베면 죽는다). 죽은 적은 빛 조각을 떨구고, 걸어가서 주우면 게이지가 찬다. 게이지가 차면 **셋 중 하나를 고른다**(장착한 카드의 단계 올리기가 중심). 30~45초에 한 번은 고르게 한다. 카드 3장이라는 틀은 유지하되, 카드가 판 안에서 여러 단계로 자란다.
2. **넓은 층.** 한 층은 화면 여러 개 크기이고 카메라가 용사를 따라간다. 층 안에 갈 곳(제단, 상자, 성소, 정예 둥지 등)이 흩어져 있어 "어디부터 갈까"가 생긴다. 화면 밖 목표와 위협은 화면 가장자리 표시와 미니맵으로 알린다.
3. **움직이는 인물.** 모든 캐릭터에 대기·이동·공격 프레임 애니메이션(팀장이 영상 생성 모델로 프레임을 만든다. 계약은 `assets/anim/README.md`).
4. **로우폴리 무대.** 높낮이가 있는 소품, 벽과 기둥, 층마다 다른 구역 소품, 밤 도시 원경. 명암 2단과 먹 외곽선은 유지.
5. **손맛.** 처치가 잦아지는 만큼 타격·처치·줍기·성장의 피드백을 싸고 선명하게.

## 3. 지켜야 할 것

- 모든 피해 공격은 예고가 있고 움직임으로 피할 수 있다. 넓은 맵에서는 "화면 밖에서 맞지 않는다"를 규칙으로 보장한다.
- 성능: 중급 휴대폰 60fps. 적이 많아지므로 상한과 컬링을 다시 정한다.
- 결정성, node에서 도는 시뮬레이션, `__BD` 훅, 봇, 사람 같은 봇(`tools/feel/human_bot.js`)은 유지한다. v2의 수용 기준은 사람 같은 봇으로 잰다.

## 4. 스스로 개선하는 고리

플레이 측정 → 진단 → 수정 → 다시 측정. 측정 항목: 분당 처치, 선택 간격, 빈 시간(화면에 적이 3 미만인 시간의 비율), 이동 거리당 사건 수, 피격 원인, 사람 같은 봇의 승률과 판 길이. 수치 목표는 GDD-V2가 정한다.
